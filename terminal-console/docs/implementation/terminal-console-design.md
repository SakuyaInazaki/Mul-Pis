# Mul-Pis 终端工作流控制台

状态：本地终端入口已实现，2026-10-15 完成展示同步与布局整理。控制台读取研究工作区里的持久运行记录，并连接同一工作区的 Pi RPC 宿主发送消息和有限的结构化工作流动作。它展示实际记录和回执；阶段完成、模型回答、评审返回都不自动等于科学结论成立。

## 启动与观察

已有工作区可直接打开交互界面：

```sh
npm run console -- --workspace /path/to/workspace
```

界面会显示工作区历史记录；有运行中的宿主时自动尝试连接。未指定工作区时从当前目录及其 `workspaces/` 子目录发现带 `research.config.json` 的工作区。交互界面需要 TTY。`--once` 输出一次只读文本快照后退出，可与 `--workspace` 一起使用；`status --json --workspace /path/to/workspace` 输出只读 JSON 快照。这些查看命令不启动 Pi，也不变更研究状态。

要启动由控制台持有的 Pi 主会话并交给它初始任务，可运行：

```sh
npm run console -- start --workspace /path/to/workspace --prompt-file /path/to/task.txt
```

主会话模型取工作区 `research.config.json` 的 research 角色；harness 不替用户选模型，命令行上没有模型参数。`--prompt-file` 中的文本作为初始主会话任务。交互界面里也可用 `:start`，随后输入初始任务。每个工作区同时只允许一个已核验的控制台宿主；离开界面不会停止运行宿主。控制台不会自动创建 M07 目标，主 Pi 仍通过 `research_goal begin` 建立目标。

`start --detach` 在宿主就绪后返回；随后用 `attach --workspace /path/to/workspace` 重连。普通 Pi 或旧 stdio 启动器的运行记录仍可观察，但不能中途接管其输入管道。已有目标的恢复须使用 `recover --workspace DIR --goal ID --old-descriptor FILE`，并由原有控制器核验旧进程、冻结状态和未决操作。

## 画面和按键

顶栏常驻 M01–M09 与知识库导航，可直接鼠标点选或使用快捷键。左栏只列节点身份、层级和状态；右栏固定为所选节点的概况，完整标题、检查状态和登记成果数量按字段排列。多段任务说明与报告正文通过 `v` 独立阅读。运行记录标成 `running` 但缺少新鲜活动证据时显示未知状态，不推断任务仍在推进。

调度树以连接线表达父子关系，选中行使用整行底色和 `›` 标记；状态同时保留文字和颜色，关闭颜色后仍能辨认。顶栏汇总当前阶段实际登记的任务或会话，不推算完成百分比。右侧内容和独立阅读页有行号范围与可点击的滚动条，全文阅读区限制行宽，避免宽终端上出现横贯屏幕的长段落。短终端自动压缩导航，长工作区名和运行编号移入可滚动概况及 `l` 信息页，不挤占正文或遮挡点击区域。

| 按键 / 鼠标 | 行为 |
| --- | --- |
| 点击阶段 / `1`–`9` / `←`、`→` | 切换 M01–M09，空阶段也能独立查看 |
| `a` | 回到当前运行 |
| `b` / `[`、`]` | 选择或切换所选阶段的历史运行 |
| 点击知识库 / `k` | 打开真实知识记录 |
| 点击分类 / `t` | 切换全部、C/K/E/J/Q/D/X 或限制 |
| `s` | 选择历史知识快照，或返回 CURRENT |
| `/` / `Esc` | 搜索节点或知识正文 / 清除筛选 |
| 点击节点 / `↑`、`↓` | 选择节点或知识记录 |
| 点击三角 / `Enter` | 展开、折叠调度节点；知识页 Enter 转入内容栏 |
| `Tab` | 切换目录与概况的键盘焦点；窄屏切换显示栏 |
| 滚轮 / `PgUp`、`PgDn` / `Home`、`End` | 滚动完整内容、翻页、到当前内容开头或末尾 |
| `v` | 选择节点完整记录（任务说明、检查明细、文件清单）或登记的正文成果，打开独立阅读页 |
| `o` | 打开主会话当前可见回复；`f` 切换跟随输出 |
| 阅读页 `Esc` / `q` | 返回原页面 |
| `l` | 查看完整提示、控制回执、工作区路径及宿主信息 |
| `w` / `h` | 选择工作区 / 已登记宿主 |
| `i` / `:` | 发消息给主 Pi（忙时进入后续回合）/ 输入控制命令 |
| 输入中 `Ctrl+V` | 预览尚未发送的完整输入；`Esc` 返回原草稿继续编辑 |
| `p` / `x` | 暂停或继续已核验 Pi 进程 / 选择中断当前轮或停止进程 |
| `r` / `?` | 刷新当前状态或知识快照 / 打开帮助 |
| 主页面 `q` | 离开界面，宿主继续运行 |

长任务说明、知识正文和文件按终端宽度换行，使用滚动阅读，不用省略号代替尾部。全文阅读保留原始换行；大文件逐段载入，滚到当前段尾后再按 PgDn 进入下一段，PgUp 可返回上一段。输入栏保持光标末端可见，长输入可用 `Ctrl+V` 在发送前完整回看。底部仅展示提示摘要，完整提示始终可按 `l` 阅读。

知识页显示所选快照引用的精确记录版本、历史使用决定、依据状况、正文与完整元数据；现行限制独立显示，浏览历史快照不撤销现行限制。知识页每 5 秒重新读取所选快照，选择 CURRENT 时随已发布快照更新；`r` 可立即刷新。缺失或格式错误的知识记录逐条提示，不创建知识库、不修改 CURRENT、不进行合入。

## 工作流节点

| 阶段 | 当前实现和控制台显示的对象 |
| --- | --- |
| M01 初识 | 单个独立执行会话读取原问题和必要原始信息，保存初始认识。 |
| M02 判据 | 同执行模型的新会话读取 M01 输出，提出候选判据；候选入库不代表验收。 |
| M03 质询 | 评审成员出题、续接 M01 会话作答、再由原评审会话评价，按实现顺序记录成员和会话。 |
| M04 判断 | 研究会话处理一批明确来源的反馈，生成判断与知识提案，并经单一合入入口记录。知识快照变化不等于科学验证。 |
| M05 获取 | 一个资料获取会话使用已配置工具，登记实际取得的来源和调用记录。 |
| M06 阅读 | 每个资料组按 reader → checker → applicability 顺序执行；资料组间有界并发，整批结果可转交 M04。 |
| M07 执行 | 持久目标、尝试、任务、子会话、检查、决策及 checkpoint。委派返回后仍需独立 review。 |
| M08 审查 | 固定显式选定材料；自查完成后启动调用方列出的外审成员。完成表示报告已返回，不表示通过。 |
| M09 交付 | 在命名 M08/M04 配对和允许范围内整理说明、复核交付副本，生成回执；不发布或外发。 |

M07 目标与 M04 回流可能跨越多次运行。控制台以持久 runId、taskId、sessionId、attemptId 和实际证据路径连接节点；没有记录支持的关系不由时间先后推断。概况来自持久控制记录；只有显式打开正文时才读取登记文件。阶段选择不会顺带混入活动 M07 子树。

M07 目标概况包含已保存的 M04 基线、知识快照、反馈形式、checkpoint 数和待决定事项；最新 checkpoint 的纳入/省略任务数来自对应冻结记录。`v` 的节点完整记录保留基线历史、checkpoint 范围和反馈路径。完整反馈、索引反馈、仅控制事实和待修复反馈分别显示；缺少冻结范围时显示未知，不推断全部任务已经反馈、M04 已经完整读取或知识已经合入。

## 审计投影

执行树一次只展示一个节点。要回答「这个候选为什么被拒」和「预算花在哪」，控制台另外给一份跨节点的审计投影：根节点概况里有摘要，根节点的 `v` 完整记录里有全部字段，命令行上是

```sh
npm run console -- audit --workspace /path/to/workspace        # 文本
npm run console -- audit --workspace /path/to/workspace --json # 结构化
```

审计覆盖工作区里**每一个可读的 M07 目标**，不只是当前选中的那一个；全部数字由 `goal.json`、冻结候选观测和会话用量 sidecar 确定性派生，不读取报告正文、回执内容或模型文本。字段：

| 字段 | 含义 |
| --- | --- |
| 任务判决 | 任务状态分布（执行中/已返回/已接受/未接受/失败/未知） |
| 候选判决 | 冻结候选观测的宿主核验结果：通过、失败、未判定，以及未判定占比 |
| 停在哪一级验证门 | 每个候选观测由 `summarizeCandidateDiagnostics` 确定性归类后停在的那一级：源码未绑定、未终态、编译失败、数值失败、运行失败、混合失败、正确性失败、正确未测量、正确已测量 |
| 引擎与 agent 自述的差 | agent 声明了候选的任务数，以及其中宿主核验通过、判失败、未判定各多少，控制器另行驳回多少 |
| 失败分账 | 基础设施失败（源码未绑定、未终态外部操作、执行失败）与策略失败（编译/数值/运行/正确性失败、复核失败）分列，另有未分类一栏 |
| 运行层分类的失败 | 直接读回运行层自己的判定：工具调用的 `failureClass`/`failureReason` 来自任务工具日志，传输失败来自运行记录里的「Read-only assessor transport observation」。界面**不重新分类**；没有标记的旧记录单列为「未记录分类」。未判定占比是 harness 健康指标 |
| 候选 guard 判决 / 晋级状态 / 分支决策 / 车道与相位 / 评分 | 读回 `episode.candidates[].policy` 的 `guard`（reject/keep/accept/revert）、`status`（unverified/verified/admissible/promoted）、`branch`（continue/merge/archive/abandon）、`lane`、`phase`、`score` 与「是否更新最佳指针」。没有判定记录的候选单列，不并入任何分布 |
| 搜索状态 | 读回 `episode.search`：最大停滞、强制换向次数、禁用方向条数、路线与停滞信号分布 |
| 搜索预算 | 读回 `episode.budget`：已用评估数（含前置驳回）、最小剩余、停止原因分布 |
| 预算 | 会话数、输入/输出/缓存 token、计费合计，以及记录是否完整 |
| 反馈密度 | 每个宿主核验通过需要多少候选；每百万 token 产出多少候选观测 |
| 改动类别 / 候选意图 / 性能画像证据 | 候选 `changeKind`、`intent` 与画像可用性（unavailable / partial / derived）的分布 |

逐节点视图同样接上了这些字段：候选节点列出它的宿主判决（guard、状态、分支、车道、相位、排名分与档位、是否更新最佳、对位最佳比较、失败签名、必须修复与建议），候选实验节点列出搜索状态与搜索预算的完整文字。

没有分母时显示「无分母」，不显示 0 也不编造比值。用量记录不完整时，预算是已读记录的**下界**并明确标注。未判定候选既不算失败也不算通过，不进入最佳与搜索前沿；它的占比本身是 harness 健康指标。审计只做计数，不判断科研质量，也不声称某个已测量候选真的更快。

## 控制命令

交互界面按 `:` 后输入：

| 命令 | 用途 |
| --- | --- |
| `:stage M01` | 提交无额外参数的阶段；可用 M01/M02/M03/M05/M06，实际前置条件仍由阶段校验。M04/M08/M09 需要 JSON 参数。 |
| `:workflow /path/to/action.json` | 从 JSON 文件提交 `stage`、`status`、`checkpoint`、`plan` 或 `decision` 的结构化动作。 |
| `:checkpoint` | 对当前绑定的 M07 目标冻结一次反馈 checkpoint。 |
| `:steer 指令` | 在主 Pi 下一可接收边界引导。 |
| `:continue 指令` | 对同一目标提交语义等待后的继续输入。 |
| `:condition /path/to/receipt.json \| 指令` | 用条件证据回执尝试解除依赖或授权等待。 |
| `:wait /path/to/condition.json` | 向当前目标提交含恢复条件的等待请求。 |
| `:recover 目标ID 旧attempt` | 启动新 Pi 进程并让控制器核验旧尝试及恢复条件。 |
| `:pause` / `:resume` | 暂停 / 继续已核验进程。 |
| `:abort` / `:stop` | 通过界面二次选择取消当前轮或正在执行的结构化工作流动作 / 停止进程。 |
| `:hosts` / `:help` | 选择宿主 / 查看帮助。 |

例如，向 M04 交接已冻结的 M07 checkpoint 时，JSON 文件可写为：

```json
{
  "kind": "stage",
  "request": {
    "stage": "M04",
    "feedbackStage": "M07",
    "feedbackRunId": "<当前目标 runId>",
    "feedbackCheckpointId": "<已生成 checkpoint ID>"
  }
}
```

`:workflow` 文件只包含动作；工作区、宿主实例、尝试和目标绑定由控制台从当前受信运行描述中填入。`stage` 接受 `research_stage` 对应参数但不接受自行覆盖 `workspace` 或 M07 阶段。`checkpoint`、`plan` 和 `decision` 只作用于当前绑定目标；`decision` 仅用于 resolve，不能创建新的待用户决定事项。复杂阶段参数须写入 JSON 文件；`:stage M04/M08/M09` 会在提交前提示补齐参数。历史节点只决定查看内容，消息与控制始终送给界面标明的当前宿主及目标。

提交回执只表示宿主接受请求；真正的工作流结果以 `workflow-result` 事件或 `workflow_result` 查询返回。桥接写入有限元数据，例如 runId、状态、checkpoint ID 和证据路径；不会把提示词或材料正文复制进控制回执。主会话忙时结构化动作会拒绝，待当前轮结束后再提交。普通 `i` 消息遵循 Pi 的消息队列语义。

对控制台提交且仍在执行的阶段，`:abort` 会向同一 Pi 进程中已核验的工作流请求发送取消信号；取消回执只说明信号已交给该请求，最终是否中断仍看原工作流结果回执。没有对应活动请求时，Pi 的普通 abort 只作用于主会话回合。已经发生的外部副作用不会因信号而自动回滚，M07 未决操作仍须按控制器记录核对。

## 边界

终端界面、独立宿主和 Pi 进程分开运行：界面离开后宿主持有 RPC 管道，重连从持久状态和有限的事件缓冲恢复观测。宿主使用本机私有 Unix socket，控制前核验精确进程身份；工作流动作在同一 Pi 内进入 ResearchService。现有 CLI 与 ResearchService 共用工作区修改锁，避免两条入口同时改写；未知所有者和无法核验的旧活动目标会明确拒绝。它不能约束一份不遵守该锁的旧版本程序。

宽终端显示调度目录与概况两栏；小于 86 列时按 Tab 切换单栏。`NO_COLOR` 可关闭颜色。主会话仅显示可见文本，全文阅读限定于工作区内的已登记文本文件；二进制文件不作为正文打开。已登记会话 JSONL 仅提取可见 assistant/tool 文本，保留完整消息和换行，不显示用户提示、隐藏思考或原始 JSON 字段；超过读取上限或损坏的会话明确报错，不展示截尾替代品。文件分段读取保护内存用量，后续内容仍可继续翻页，不会扫描全部会话正文来刷新画面。

控制台只控制当前工作流。它不提供 RSI 改进、H/I/CPU 实验、任意 shell、自动接受 M07 任务、修改科学成功状态、自动发布或发送。M09 的复算请求只记录和执行其既有受控范围，不构成完整复现证明。恢复是经身份与持久状态核验的新尝试，不重放旧子会话。`--once` 和历史浏览只读；所有实际执行仍依赖用户配置的模型、现有 ResearchService 及其控制器检查。
