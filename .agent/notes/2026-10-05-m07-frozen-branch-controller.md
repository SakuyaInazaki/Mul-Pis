# M07 frozen branch controller batch (2026-10-05)

The M07 controller now records an explicit context boundary for new tasks, fresh reviewers, and true competitive branches. A settled execute task can freeze a bounded work copy, the original problem copy, a historical-path evidence map, and a durable runner session checkpoint before its handle is disposed. Unsupported runners and unfreezable task work leave the ordinary task result intact but cannot serve as a fork source.

An explicit fork request must name the same M07 run, a settled original task, and its exact checkpoint. The controller keeps the original objective, inputs, outputs, checks, independent-check requirement, knowledge context, and formal baseline; each child gets its own task, execution directory, and genuine runner lineage. Known auth/session-like files, symlinks, special files, oversized copies, unresolved operations, changed baseline or manifest, unsupported fork capability, and cross-process concurrent dispatch fail closed. Same-goal plan, checkpoint, delegation, review, selection, finish, interrupt, suspend, reconciliation, and successor control writes serialize. Recovery separately requires proof that the prior process is dead and uses an atomic attempt claim; it does not take over a residual dispatch lock. Such a lock remains for exact manual review before new work. The file modes and tool roots are capability and accidental-edit controls, not an OS security boundary against the same user account.

Branches remain candidates. Existing M07 review must check the original and each returned branch before an explicit selection. Selection may choose a reviewed branch, the reviewed original when it is better, or no winner. A fulfilled goal requires a reviewed, selected winner when branches were opened and cannot use an unselected candidate's evidence as original-goal proof. Unresolved external operations block selection and finish even in a losing branch. Scoped M04 checkpoints strip unselected task evidence and unreviewed tool logs; CLI/Pi status projections expose only bounded control facts. M04 remains the only knowledge-adoption path; the feedback identifies branch status and choice without claiming that evidence was read or adopted.

Verification: `npm run typecheck`; focused M07, execution-loop, and branch-controller offline tests. The branch tests use the fake offline runner; separate runner tests exercise Pi SDK forking offline. No paid model run, publication, or external experiment was performed in this batch.
