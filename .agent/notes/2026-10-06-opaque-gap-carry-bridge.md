# Opaque executed-run carry bridge

The ledger can now distinguish the newest terminal workflow execution with an encrypted result but no private carry from an ordinary missing artifact. Its admission requires an earlier authenticated carry, a uniquely identified live result archive, exact terminal run/job/provider-step metadata, and an independently reviewed immutable source. The current one-time review binds the exact historical control request, first-parent source tree, offline CI, result archive, and predecessor carry. This is effect quarantine for an independently fresh goal; it is not reconstruction of missing private usage, invoice settlement, scientific acceptance, or replay of the interrupted run.

An admitted gap is carried as an append-only, encrypted, source-ordered receipt with accounting explicitly unquantified. The ordinary restart proof remains bound to the last actual authenticated carry. A live WeakMap accessor lets the restart policy include the reviewed gap in its policy digest without turning the missing result into research evidence. Later authenticated carries compact the gap receipt, so expiration of the old result archive does not silently erase the historical execution. Digest and source-order checks reject a changed gap predecessor or skipped/duplicated workflow source.

Emergency carry sealing preserves the exact current request audit, observed fees, prior authenticated bundle, and gap receipts when ordinary effect review fails. It marks current effects pending and does not grant restart or science authority. A future pending carry needs a separate, authenticated effect review before independent continuation; fee rows alone are insufficient. Synthetic tests exercise missing/expired/duplicate artifacts, missing or forged source review, exact one-time source and terminal checks, live claim and normal carry compaction, emergency AEAD audit retention, in-flight refusal, pending restart refusal, and gap-prefix tampering. No paid model calls or network calls were made in these tests.
