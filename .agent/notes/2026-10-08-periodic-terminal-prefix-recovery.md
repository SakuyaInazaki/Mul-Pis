# Periodic encrypted control checkpoints for terminal interruption

A GitHub-hosted campaign can reach the platform's hard job limit before its `always()` result and carry steps run. A runner-local incremental checkpoint then vanishes even though earlier controller and request facts were durably written inside the job. The existing small live-status artifacts contain counts and a checkpoint digest, not the checkpoint bytes. They cannot recover request accounting or controller observations on their own.

For future runs, the trusted Node action reads a committed incremental checkpoint only after the driver's awaited atomic journal write and authenticated initial status frame. The first snapshot's digest and sequence must match that frame or be replaced by a strictly newer prefix independently verified with the same signed key and source. Thereafter an observer-only 15-minute parent timer opens the latest atomic inode and independently authenticates its source, sequence and AEAD. This also captures a newer same-semantic controller save when the small status frame was coalesced. Each successful read copies only encrypted bytes into a temporary private snapshot. The producer checks an independent local free-space floor before copying and deletes each observer copy after its upload attempt finishes, including ambiguous failures. Upload, pipe, or observation failure cannot stop research or alter its exit. A completed upload may lag the latest local save by a cadence interval plus transport time; an abrupt stop leaves the later suffix UNKNOWN.

Encrypted prefix and final-carry bytes that exceed one connector-safe artifact are split into ordered 16 MiB payload chunks. Each chunk is uploaded as a uniquely named immutable, one-day ciphertext artifact. Only after every part upload returns a verified identity does the trusted action publish an AEAD-sealed transport manifest under the existing canonical artifact name. The manifest binds exact source, file names, offsets, byte lengths, hashes, part artifact IDs, and GitHub archive digests; a partial upload has no root authority. The host reconstructs each file from a stable complete artifact census and verifies the inner prefix or carry AEAD after transport checks. Legacy single-ZIP artifacts remain readable. The physical encrypted-file stream bound is 255 MiB, with each individual outer ZIP below the connector's 32 MiB materialization ceiling. The shared 500-artifact job count reserves up to 18 terminal artifact slots, limiting optional status/prefix uploads to 482 attempted calls. The optional status share leaves 125 attempts for periodic multipart snapshots across the hosted job window. These are observer and transport capacities, never research request, fee, output, or time quotas.

Host admission enumerates the complete artifact census, verifies live Actions source and terminal run/job/step metadata, the archive digest and strict ZIP contents, the signed mission key, and the prefix AEAD/source/sequence. A successful full terminal carry always takes precedence. A timed-out or cancelled run with neither terminal result nor full carry can be represented only as a distinct prefix-backed opaque executed-run gap, based on an earlier authenticated full carry. That earlier carry's root and every sidecar remain the selected authority; the newer prefix is partial host evidence with an UNKNOWN suffix. Fees and effects remain unquantified/unreviewed, and no old task, scientific result, or operation may be replayed or adopted from it. Fresh-only dispatch requires a separate private review of the interrupted source's actual confinement capabilities.

The periodic prefix artifact is not a self-contained backup of the earlier full carry. Its earlier root and every sidecar must still be retrievable within their existing retention period, or admission stops with the missing evidence explicit. A successor carry retains authenticated old-prefix bytes in separate encrypted one-MiB sidecar segments, bound to a compact carry receipt, so an already carried gap does not depend on the expiring original prefix artifact. Several near-limit prefix-backed gaps can exceed the 255 MiB transport bound; that physical failure must stay explicit without silently dropping earlier bytes. A checkpoint never proves what happened after it was sealed. GitHub artifact storage capacity is a separate physical boundary that an artifact-count reserve cannot guarantee. A large RSA outcome cannot be materialized directly through a connector's 32 MiB download route. When its original ZIP has been reconstructed privately, the bridge can instead verify the complete ZIP digest against authenticated live artifact metadata, strictly extract its one encrypted member, and compare it byte-for-byte to the supplied private result file. An absent or mismatched original ZIP remains unrecovered. This batch cannot retroactively recover a job that did not publish one of these new prefix artifacts.

Synthetic tests cover atomic replacement, same-semantic saves with no later frame, a silent reserved request, absent and conflicting artifacts, changed source and digest, upload ambiguity, stable pagination above one API page, a hard-kill-shaped terminal with no poststep artifacts, and preservation of the earlier selected tuple and unresolved exposure. The no-model Node24 Actions smoke uses an ephemeral signed seed to upload and re-download both small and production-size multipart encrypted prefixes, including a prefix-only final carry transport, through the real artifact client. Offline tests exercise a full sealed successor carry with historical-prefix sidecars. The remote smoke must pass on the exact published source before describing this as live recovery. No model or paid run is launched by these local changes.
