# Runtime control recovery batch

- Added a shared process identity probe with host and boot identity plus a process birth token. Darwin obtains microsecond birth time through system libproc; Linux uses `/proc` start ticks. A missing observation, reused PID, remote host or insufficient permission remains unknown and cannot authorize control.
- Added a versioned run descriptor and explicit stored control state. The existing control command now separates stored declarations from live observations and only signals a verified independent process group. The old PID file alone has no control authority.
- Child prompt and top-level watchdogs no longer treat an ordinary timer delay as a trusted pause. Child prompt timeout and stall use elapsed time minus only the pause duration written by the bound control state. Host heartbeat is distinct from observed assistant or tool output; no durable scientific progress is inferred from a heartbeat.
- Adapted the existing private launcher to register the spawned Pi process identity and descriptor, expose a fresh-session recovery flag, and rotate its active main log into retained bounded segments. The global disk free floor remains independent. The bounded local tail reads from a fixed file descriptor and reports truncation.
- Added offline tests for default 30-second watchdog timing, event-loop delay, trusted pause, process identity mismatch, and the actual control script status/rejection path. The private launcher offline check covers its preflight, fresh recovery flag, log rotation with preserved bytes, and bounded tail. No real model, network request, current workflow control signal, or lock removal was used.
- Further local process tests exercise the real control script against a synthetic detached worker, detect a live unregistered child after its group leader exits, and confirm bounded observation or an observer timeout leaves an independent worker alive. Control mutations use an exclusive local lock and atomic state replacement. The private launcher offline test now starts a synthetic fake Pi child through its actual launch path; an import gate waits for the exact descriptor before any model/extension code can load, then the test checks the fresh recovery environment and process identity.
- Updated the existing implementation design and project rules with the explicit recovery boundary and a 22-item regression catalog mapping. The mapping distinguishes offline checks, partial mechanisms and unrun real-model cases.
- This batch does not assert that process group signalling is race-free after the final observation, nor that a host crash can always persist a checkpoint. The M07 recovery state and merge transaction are separate coordinated batches.
