# Host planning after a missing-carry interruption

The private host adapter now distinguishes a terminal carry from an executed run that ended without one. For the latter it requires a live authenticated interruption proof, a single encrypted result artifact identity, and the preceding AEAD carry. It projects the original contract, selected tuple, unresolved operation references, and checkpoint only from that preceding carry. The interrupted run's result files remain untrusted history and its fee and effects remain unknown.

The host creates a new interruption action for fresh isolated work. It does not reuse the earlier checkpoint's action or claim that the interrupted run completed a task. A private operator review of the exact interrupted source's confined capabilities is required before preparing a descriptor; source and test citations record what was reviewed, while the operator remains responsible for their meaning. The old interrupted source and the new tested launch source are separately bound. A separately verified explicit user stop is an operator stop boundary; the bridge cannot identify who caused GitHub's cancellation. Older accounting-integrity, workflow-repair, M04-transaction, and exclusive-input blockers remain active. The private journal binds the interruption source, result archive digest, and review digest into the idempotency key before any control-ref update; the public descriptor still contains only the fixed request message and source/tree/parent commits.

Offline tests cover full ledger-to-host preparation, read-only planning, durable reservation and repeat planning, tampered interruption identity, missing fresh isolation, explicit user stop, and retained older blockers. No provider request, external write, publication, or real workflow launch occurred in this change batch.
