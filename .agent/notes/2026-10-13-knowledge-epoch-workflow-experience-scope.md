# Workflow method experience checks at a knowledge epoch

The epoch handoff previously checked inherited improver experience against the CPU method-research tag even when the active bundle was a workflow-method bundle. A pinned, applicable workflow improver experience could therefore prevent an otherwise valid explicit knowledge-epoch advance.

The verification now derives the experience scope from the active bundle environment and its executor method. Workflow executor requirements use the M07 slot; workflow improver requirements use the corresponding method-research workflow tag. CPU method bundles retain their existing CPU scope. The check still verifies every inherited experience reference, its dependencies and live limits, and every necessary scientific knowledge reference before activating a new bundle. A workflow bundle without a workflow executor method fails closed.

A fake-session regression first reproduced the erroneous rejection. It now confirms an applicable workflow improver experience survives a completed M04 knowledge-epoch handoff while an independently withdrawn required premise blocks the next handoff and leaves the active pointer unchanged. The focused offline test and TypeScript typecheck pass. No running goal or model session was touched.

The same scope mismatch also affected a frozen M07 workflow method when it carried an inherited improver experience, and the method service's explicit bind and rollback checks. Those paths now use the destination bundle's environment and its actual executor strategy and slot. Unknown or mismatched method contexts fail closed; CPU method checks retain their CPU scope. Explicit binding checks the incoming method together with the retained counterpart's necessary experience and knowledge before activation. Fake-session regressions first reproduced the false rejection at M07 delegation and workflow method binding, then passed after the fix; rollback of the same pinned workflow method is covered as well.

Method-package binding also previously parsed an external package, checked its dependencies, then reread its path during activation. A changed file could therefore activate different method bytes than those checked. The service now passes its single validated package object to the internal binding function; the public CLI and service still accept a package path, and activation retains the active-pointer compare. An offline regression changes the source package file during dependency verification and confirms that the imported strategy uses the originally checked object. Knowledge-epoch verification also rejects an unknown environment or a mismatched executor method instead of silently applying CPU tags. Neither change adds a file-hash manifest or a new execution platform.
