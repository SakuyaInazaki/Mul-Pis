# Live continuation after a settled failed M04 judgment

The default local mission now treats a returned, evaluator-rejected read-only M07 task followed by a failed no-proposal M04 judgment as bounded negative feedback when the same owner can verify the exact M07 checkpoint, M04 handoff, terminal transaction, published knowledge state, and absence of an unresolved merge. It finishes that M07 goal as unselected partial work, records the failed M04 run ID in the bounded-run checkpoint, and freezes the exact M04 failure and limitation fields for the next original-objective assessment. The active `mission run` may then choose and dispatch a distinct bounded task without repeating the prior builder or M04 judgment.

An accepted M07 candidate remains held if its M04 judgment fails; the M07 acceptance is preserved and no selection is inferred. A pending merge, ambiguous M04 run, unknown external operation, or interrupted final checkpoint also remains held for reconciliation. This batch does not add automatic retry of an accepted candidate's M04 review.

Offline default-mission tests cover two distinct bounded tasks in one invocation, frozen failed-M04 feedback, accepted-candidate and pending-merge holds, and a final-checkpoint interruption that does not redispatch the builder. No model request, cloud run, or GitHub Actions job was started.

An explicit Pi host abort now carries a distinct runner error code. The live failed-M04 continuation excludes that code, a typed AbortError, and an aborted host signal, so cancellation leaves the prior checkpoint and failed M04 facts held without launching another builder. Other model stops still use their existing code; a non-abort length stop and ordinary error text containing “cancelled” both remain eligible for no-proposal settlement.
