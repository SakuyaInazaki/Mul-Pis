# Freeze workflow research inputs before search

This batch repairs workflow research input handling. The controller freezes protected cases and their named input bytes before the first improver call, while exposing them to evaluation arms only after candidate selection. Shared development/protected inputs are rejected. All arms use one retained source template. Unrelated live knowledge growth must not rewrite the experiment; live withdrawal/necessary-reference checks remain authoritative, and automatic publication still requires the frozen knowledge epoch.

Original experiment records are retained. No active research process or task is replaced. The three new regressions first reproduced moving protected inputs, shared development/protected inputs and unrelated knowledge growth aborting the experiment. The repaired workflow adapter includes regressions for mid-evaluation withdrawal blocking M04 and live knowledge growth preserving a supported result without promotion. The README and implementation documentation explain snapshot retention, persistent knowledge reuse and the exact quality-admission scope.

An interrupted real knowledge merge regression also reproduced a prepared transaction being copied into the research template. Preparation now detects a copied merge lock or uncommitted intent before any model call and retains the files for inspection. Derived template views are rebuilt from its published records. Production files remain untouched. Active evidence-projection files are read once for template preparation, and the same captured file selection drives protected-input exclusion and copying.

It now accepts an existing regular file only when its bytes equal the frozen input, and otherwise fails the arm before M07 execution.
