# M05 外部知识获取：工具接入 — 2026-09-20

## 授权、选择与一次纠正

用户说明自研抓取工具尚不成熟，要求按现成项目实现 M05。用户明确推荐的是 browser-use；SearXNG、Crawl4AI、Playwright、Docling 是上一轮 agent 列在 `docs/research/m05-tool-candidates.md` 里的可替换候选。主会话起初把整张候选表当成用户选择，把 Docling 也装了进来；Docling 首次运行开始下载本地版面模型时用户明确表示不想在本地运行任何模型、机器空间有限，要求改用多模态模型识别。随后撤销：卸载 Docling 及其拖入的 torch，删除已下载的 Docling 模型缓存，删除 `tools/py/pdf_extract.py`，重建 venv。

用户随后又明确不要 Docker，于是移除 SearXNG（脚本与配置全部删除）。最终 M05 工具栈：browser-use（交互式站点最后手段，需单独配置云端模型与密钥）、Crawl4AI（网页抓取为 markdown，规则式转换，不跑模型）、以及一组纯 HTTP 检索接口：OpenAlex 与 arXiv（论文与开放版本）、Hacker News、Stack Exchange、Reddit、GitHub（社区，官方无密钥接口）、DuckDuckGo 公开 HTML（无密钥通用网页，尽力而为）、Brave Search API（可选，需用户密钥）。没有本地服务，没有 Docker。PDF 不用任何本地 ML 模型：poppler 的 pdftotext 提取文本层，pdftoppm 按需把单页渲染成 PNG 直接返回给多模态模型阅读；这要求 reader/checker 角色配置多模态模型。Pi 0.85.1 的消息类型不支持 PDF 文档块，所以“让模型直接读 PDF”只能以页面图像实现。

## 验证

- 类型检查无错误；`node --test`：30 项全部通过，不调用模型。
- 真实公开接口实测：OpenAlex、arXiv、Hacker News、Stack Exchange、GitHub、DuckDuckGo 均返回结果并正确解析；DOI 与 arXiv 标识的开放版本查询正确；Reddit 的公开 JSON 接口对无密钥请求返回 403，见下文。
- Crawl4AI 经 TS 适配器实测：example.com 与 arXiv 摘要页均返回 engine=crawl4ai、HTTP 200、markdown 与链接。
- PDF：`extractPdf` 对本地 RSI 论文报告 75 页并按限制截断；`renderPdfPage` 生成 `pages/…-p001.png` 并可复用。
- CLI `m05 --runner fake` 在临时工作区跑通。
- 环境：`.venv` 只含 Crawl4AI 0.9.3、browser-use 0.13.10、Playwright 1.63.0（Python 3.12.13），无 torch、无 ML 模型。

## 未决与依赖

- 通用网页检索缺省只有 DuckDuckGo 公开 HTML 接口（非官方，可能限流）；稳定的通用检索需要用户提供 Brave Search API 密钥。Reddit 无密钥访问被 403 拒绝，适配器保留但不在默认来源中，只有 `tools.searchProviders` 显式列出时才启用。
- browser-use 需要 `tools.browserUseModel` 与对应 API 密钥，未经真实模型运行验证。
- 扫描件没有文本层，只能靠页面图像由多模态模型阅读；长材料分块未实现。
