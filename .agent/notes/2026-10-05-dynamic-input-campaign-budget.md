# Dynamic provider-input reservation for the private campaign (2026-10-05)

The latest private M07 attempt reached a real tool-using model session and produced a candidate, but stopped when later serialized request context exceeded an arbitrary 96 KB input-payload ceiling. The incomplete result is retained only in the private outcome channel; it was not adopted as a validated solution or placed in this repository.

The campaign now removes that fixed provider-input byte ceiling. Immediately before each provider request, the runner measures the actual serialized UTF-8 payload and reserves its conservative input cost plus the existing capped output and accounting margin. Every successful provider event is reconciled against its own request reservation. A request is still stopped before transport if the cumulative campaign money ceiling or call count would be exceeded; failed or unknown outcomes do not refund reservations. The fixed model, endpoint, output-token limit, no-retry/no-compaction settings, and deadline remain intact.
