# 工作流运行修复与接续修改说明

本次按用户要求发布当前工作流源码，供后续修改接续使用。变更以既有算子优化工作流为基础，没有加入具体实验的平台、题号、成绩或候选实现。终端控制台继续保存在已有的 `terminal-console/` 独立目录。

## 已有改动

- `src/runner/pi.ts`：执行会话的 bash 工具显式使用毫秒参数 `timeoutMs`，调用 Pi 时才转换为秒。旧的歧义参数 `timeout` 在创建子进程前报错并说明重试方式；不新增默认超时或任务时长上限。
- `src/runner/managed-bash.ts`：取消与超时先向受管进程组发送 SIGTERM，允许清理；清理宽限期结束仍观察到进程组或无法确认其已消失时再发送 SIGKILL。等待清理后记录退出与进程组观察结果，覆盖父 shell 先退出而子进程仍存活的情形。
- `src/m07/controller.ts`、`src/m07/types.ts`、`src/pi/service.ts`：加入宿主专用 `hostAddConstraints` 入口，记录追加用户约束的事件标识、内容和时间；后续任务及 reviewer 继承约束，历史任务快照与原成功条件保留。该入口未注册为模型工具，新约束不在运行任务或未决外部操作期间追加。
- `src/m07/controller.ts` 与 P07：说明编号输入副本不会保留多文件脚本的相对依赖关系，复用时从显式输入在任务目录内恢复关系；要求原始查询、评测和实验回执保留原件，后续查询与汇总另存。
- `src/pi/extension.ts` 与 P07：延续用户指定的任务顺序和操作权限；已受理外部操作复用原 ID 查询，重复相同状态不作为实验进展。诊断须明确能区分的原因与所需证据。
- 测试围绕毫秒超时实际生效、旧参数不执行、合作式退出与强制清理、后续任务和 reviewer 的约束继承；未增加网络或真实模型测试。

## 接续修改时需要注意

`hostAddConstraints` 当前先检查目标与操作状态，再识别已记录的事件。因此，同内容事件在可追加状态下重试是幂等的，但若首次成功后任务已启动、操作状态变为未决或目标已结束，同事件重试会被状态检查拒绝。已有测试未覆盖这个先后次序。后续可将既有事件的内容比对与返回置于新增约束的状态检查之前，并验证不发生再次写入。

追加约束解决的是持久化和向后续会话传递的问题。用户要求的多对象执行顺序目前仍由主会话与 reviewer 依据目标及约束执行；它不是逐对象“验收完成并知识回流”状态机，不能把本次变更描述成所有任务顺序已获得程序化保证。

原始回执保留与相对依赖恢复属于明确的任务约定，没有自动恢复已覆盖文件或自动发现脚本依赖的机制。重复观察提示也没有实现语义进展检测。源码变化在新实例加载时生效，提交与推送本身不会重新启动运行进程。
