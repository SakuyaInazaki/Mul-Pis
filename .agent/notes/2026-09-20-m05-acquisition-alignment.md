# M05 获取方式对齐记录（2026-09-20）

## 本轮确认

- 用户关注当前论文、社区、论坛与通用网页覆盖过窄。
- 获取模型应按任务、页面状态与所需材料灵活组合搜索接口、直接抓取、 browser-use 与下载；browser-use 不固定为最后手段。
- 现有站点适配器是实现入口，不是全网来源范围的白名单。主会话将继续对齐覆盖要求，暂不决定新接口。

## 只读核查事实

- `src/tools/search.ts` 的默认 provider 集合较窄；同时 `src/stages/m05.ts` 已允许对任意 HTTP(S) URL 直接抓取或下载。
- 当前搜索 provider 都是单次请求，M05 工具没有暴露分页参数。
- 论坛与社区搜索主要返回帖子或问题的元数据及短片段，没有形成完整帖子内容的专门取得流程。
- `src/stages/m05.ts` 与 `src/tools/fetch.ts` 把 browser-use 描述为“最后手段”，但代码没有设置必须先调用 `fetch_page` 的门槛。
- `tools/py/browser_task.py` 目前只保存浏览器 Agent 的最终报告，没有输出其访问的原始页面或附件。
- browser-use wrapper 当前只接受 OpenAI 与 Anthropic 两类 provider；这是现有实现限制，不是用户对模型的选择。

## 边界与状态

- 本轮没有把完整帖子抓取、分页、账号或登录处理等尚未讨论的细节记录为已决定需求。
- 本轮只更新对齐文档与变更记录，没有修改实现代码。
- 其他获取细节仍待后续对齐；本轮未提交、未推送。
