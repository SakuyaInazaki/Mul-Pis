# Private carry seal diagnostic

The manual private campaign now retains separate structured explanations for research continuation collection, normal authenticated carry sealing, and emergency sealing failures. The explanations record each stage, an invariant class, and the exact message when it matches a fixed host-owned rejection phrase. For future unknown errors, they record a SHA-256 message fingerprint, bounded native error class, safe harness code, repository-relative source location, short credential-redacted message when safe, and a bounded cause chain. Unknown request bodies are omitted. An ordered list of fixed finalizer failure codes preserves earlier salvage, status sync, host census, accounting status, quarantine, collection, and sealing failures when a later summary label changes. These fields are written only to the RSA-encrypted campaign status; public workflow observations remain static.

After collection fails, the driver now requests an emergency accounting and effect carry directly, even when the normal sealer could accept the older fallback research bundle. That prevents a normal continuation from claiming the latest research was retained. The driver records a collection-specific emergency status and omits the normal seal failure field because normal sealing was not attempted.

If both normal and emergency seals fail, the process-only sealer error retains both causes behind a static public message. The driver persists their independently redacted details in the encrypted status.

The collector retains a logical continuation above the old aggregate four-megabyte ceiling, while keeping the bound for every file except research history. Research history and the complete logical checkpoint use the segmented carry capacity bound. The driver validates canonical sidecar names and Base64, writes each encrypted sidecar with private permissions, and publishes the root envelope only after every sidecar write succeeds. Failed or partial sidecar writes are included in the private ordered diagnostic.

Offline tests cover static and future ledger errors, a collection failure that forces emergency sealing with zero current requests, ordered failure retention, an aggregate carry above 4.26 MiB, a single research history above 4 MiB with full range-readable reconstruction, and sidecar persistence ordering, without provider calls or private task reads. The focused private campaign tests passed (60 tests). TypeScript typecheck and `git diff --check` passed.
