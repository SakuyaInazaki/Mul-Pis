# Remove standalone mechanism campaign total-cost gate

The budget-policy mechanism improvement path previously required `maxTotalCost`, decremented an estimated-cost balance after proposer and admission calls, and stopped before or after calls when that balance was exhausted. New campaigns decode but discard the historical field. They neither impose a total spending ceiling nor partition costs by proposer, baseline, candidate, or readback. Legacy per-campaign execution quotas remain inert. Actual visible calls, input/output usage and SDK-estimated cost are still recorded; missing proposer usage is marked unknown rather than treated as free.

The local scientific admission criterion is unchanged: complete, priced baseline and candidate usage is required for paired cost comparison, each candidate pair must be no more expensive, and candidate total cost must be strictly lower. An unpriced or incomplete arm cannot authorize promotion. Material-size and registered-range boundaries remain unchanged. The improver may explicitly return a reasoned stop. A repeated identical candidate is rejected as feedback, but does not stop the campaign or imply that another candidate is impossible. No replacement call, time, token, or candidate-count ceiling was added.

Offline tests cover absent and inert historical total-cost fields, paired promotion when observed cost exceeds a legacy value, unknown proposer cost in the ledger, paired usage failure, explicit model stop after duplicate feedback, and promotion of a distinct feasible candidate after a duplicate. No paid model call, commit, push, or publication is part of this change.

The follow-on evidence-availability pass removes the 20-run and 20-attempt history slices from the standalone improver. Each proposal receives a frozen complete JSON snapshot of sanitized prior attempt summaries. Its prompt names only three recent attempts and gives the total, visible and omitted counts; a read-only `history_read` tool returns requested UTF-16 ranges of that snapshot, at most 4,000 code units per call. The tool exposes no general filesystem access, writes, shell, case answers or credential paths. The run record distinguishes directly presented attempt IDs from exact ranges actually returned by the tool. An offline regression makes a fact from the first of 21 prior runs recoverable through tool reads despite its omission from the prompt; it does not claim the model semantically used every available record.

The same path formerly rejected otherwise valid hypotheses and explicit stop reasons once any free-text field exceeded 2,000 characters. That arbitrary model-output quota has been removed. Type, nonempty, origin, proposal-shape and policy-schema checks remain. The obsolete `maxReadbackChars` plan field is discarded without validation. Offline regression preserves each long hypothesis field and a long stop reason verbatim.
