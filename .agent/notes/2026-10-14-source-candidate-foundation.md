# Source candidate foundation

This batch adds an isolated model-edited source candidate path and explicit H/I source method references. The controller supplies the configured improver model, frozen development evidence, a reviewed writable source list, and engineering checks. A single confined builder session edits a private Git checkout; the host records its hypothesis, session reference, tool calls, provider usage, complete source diff, check outcomes, parent commit, generated commit, and prepared read-only source receipt. Failed checks and rejected edits remain recorded. No candidate is activated by this path.

The initial writable modules are the M07 feedback implementation and the separately versioned improver program entry. Control, evaluation, runner, verifier, usage, and knowledge merge modules cannot be nominated. Source H and I have independent typed bindings in the generation store, without a prompt body. Existing prompt consumers reject source methods explicitly. The existing prompt activation path rejects source bundles; source adoption uses the separate independently checked source confirmation flow. Existing prompt methods retain their previous schema and behavior.

The source preparation implementation moved under `src/runtime/` so a prepared source snapshot can import its own candidate builder; the original script remains a command-line wrapper and re-export. The snapshot still exports the same reviewed source directories and reuses the installed dependency symlink.

Offline tests cover a fake model's real file edit and private commit, a control-file attempt and full Git status rejection, an empty candidate, failed engineering checks, independent source binding, snapshot self-import, and legacy prompt compatibility. A candidate with failed engineering checks can retain a private commit for analysis, but its receipt says `engineeringStatus: failed`; it receives no activation. These engineering tests do not establish research benefit or model-generated improvement in a live experiment.
