# Private cumulative ledger continuation

Added a host-only continuation path for the mission's single CNY ceiling. The existing RSA-PSS signed Actions secret remains the root of trust. Its private signature bytes derive an AES-256-GCM key by HKDF with a seed-specific salt. Signed seed authentication is now reusable without weakening the original immediate-previous-run verifier.

Every later billable workflow run must publish one encrypted carry. Each checkpoint authenticates the mission and repository, signed seed digest, previous checkpoint digest, exact source run number/ID/attempt/commit, cumulative conservative commitment, retained unknown holds, and per-request host accounting evidence. The reader independently checks GitHub workflow history, jobs, and immutable artifact metadata. A proved skipped provider step is nonbillable. Missing, duplicate, cancelled, unauthenticated, incomplete, or replayed carries fail closed before another provider request. Later queued runs do not obstruct the active run; Actions workflow concurrency remains part of the execution boundary.

The carry may include a bounded allowlist of private research continuation files under the same encryption. Files restored from it are untrusted research evidence and need a separate authorized, confined handoff. Key material and budget bookkeeping stay host-only. ZIP extraction is bounded to one expected entry, and no token is passed to a subprocess or model.

A version 2 signed seed can optionally include a deflate-compressed private bootstrap bundle and exact original contract/source hash binding. This lets the first automatic run recover an already accepted candidate, plan, verification, checkpoint and assessment context without placing laboratory bytes in the repository. The signed seed parser enforces the 48 KiB Actions Secret limit, compressed/expanded size limits and a fixed file allowlist. The host must compare the signed source and contract binding against the decoded input before any provider call. If the private bundle cannot fit or the binding does not match, the continuation stops rather than restarting the scientific task from zero.

The already finished prior run has no authenticated carry; a one-time refreshed signed seed anchored to its existing encrypted result is needed before this path can continue automatically. This change does not create that signature or make provider calls.

Offline synthetic tests cover seed verification, accounting, encrypted continuation, retained unknown holds, interrupted/failure cases, skipped and queued runs, replay/tampering, and ZIP guards. No private laboratory contents, actual costs, or live run identifiers were added to source or tests.

The recovery audit tightened full-page counts, descending run order, run identities, exact job/artifact counts, and ambiguous step handling. GitHub concurrency does not guarantee run-number order, so a newer completed potentially billable run now blocks an older run rather than being silently omitted. Queued first attempts and proved skipped steps remain nonbillable. The legacy seed-only verifier reuses this same proof.

Persistence now retains truthful conservative observations above the admission ceiling; an over-ceiling restored total still prevents the next provider reservation. Per-request audit reconciliation uses conservative integer-nano totals instead of a tolerance that could hide small omissions. Retained request facts remove floating-subtraction residue, and conflicting late price reports can only increase unknown holds. Audit snapshots contain no prompts, session IDs, credentials, or source bytes.

ZIP response bodies are bounded while streaming, directory and local headers are checked before reads, and only one expected fixed entry with supported compression/flags is accepted. The host writes that file as the exact object containing the returned envelopeB64; the workflow separately uploads its ciphertext artifact. Signed/carry research bundles also allow a bounded research-history file so old version-bound research evidence is retained without importing it into the active knowledge store. The original input source remains the bootstrap binding, never the evolving candidate.

A version 2 seed may now carry a root-reviewed anchor attestation naming the exact original run commit and SHA-256 of the encrypted result envelope. The signature and existing previous-run/artifact identity bind that review, so expiration of the old artifact does not revoke its accepted cumulative accounting. The runtime still verifies the exact anchor run/attempt/commit and all subsequent run dispositions. Historical seeds without the attestation retain their original unexpired-artifact requirement.

New version 2 carries include a flattened authenticated ancestry of every executed post-seed run: source identity, prior and ciphertext digests, settled/unknown deltas, cumulative amounts, prompt-free request audit, and original-source binding. Opening the latest unexpired carry verifies its complete ancestry against independently enumerated GitHub executions and recomputes all totals from the signed seed. Old ciphertexts can expire only after such a newer authenticated carry has retained their checked receipts. Version 1 carries still require full ciphertext availability until migrated. The latest required carry, workflow history, fixed page horizon, and bounded artifact size remain explicit availability limits; no indefinite recovery or accounting reset is claimed. A repeated consumed one-use push marker is rejected; explicitly authorized manual attempts retain their separate route.
