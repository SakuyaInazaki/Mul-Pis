# Accepted control request with no observed Actions run

An accepted control-ref update can exist without an observed Actions run. An empty run census is an observation at one time, never proof that the push will not be delivered later or that provider fees and effects are zero. The original private journal entry remains delivery-unknown. A distinct linked fresh intent binds the accepted old control commit, its exact prior journal record, a complete exact-SHA run census, a different tested feature source with successful CI and live source/ref fence, and a private operator review of the old source's capability confinement. The new public commit descriptor contains only the existing fixed control fields. The operator review has a mode-0600 exact-schema receipt, five code/test evidence roles including indirect host execution confinement, immutable source reads and a process-local brand. It does not decide whether the old request ran. Existing `reconcileNotDelivered` remains reserved for a ref update that demonstrably did not reach the control ref.

The running Actions admission independently walks the linked control-commit ancestry using read-only GitHub metadata. For each accepted request with no observed run, it verifies the old commit, tested source tree and CI, and exact-SHA run census. It creates an ordered unobserved-control-delivery record with UNKNOWN effects and unquantified charges. This is separate from an opaque gap for an actually executed run. The initial awaited encrypted incremental prefix records these controls before any model inference request or reservation, and later request/control prefixes retain them. Ordinary and emergency mission carries seal the same lineage; a later successor verifies the entire authenticated prefix. The private campaign starts from a freshly checked selected tuple, empty isolated workspace/store, confined grants and a V2 fresh-only quarantine; old work is not replayed or adopted. Research history can expose only the control identities and their uncertainty, not imagined old results.

An old run observed later must be examined, not inferred from elapsed time. A source-fenced verifier-step failure before decode/provider is recorded as a separate terminal disposition while the historical UNKNOWN observation remains. A run that reached a model-capable step enters a typed reconciliation-pending path; no old science is promoted by the new source. The host journal releases an old unknown dispatch hold only when a branded terminal carry for its linked successor proves the exact ordered unobserved-control rows. An acknowledgment or run ID without that carry does not settle the old delivery. A linked successor that ends without an authenticated carry still holds the old unknown delivery; that later branch needs separate no-carry lineage recovery before another dispatch. Multiple accepted no-run controls retain their full ordered chain without a retry-count limit. Storage and platform visibility remain real physical boundaries, and the design does not claim at-most-one paid execution when an old hidden job could already have passed its pre-provider source fence.

Offline tests cover exact host/journal binding and source review, repeated accepted controls, initial prefix before a synthetic request reservation, ordinary/emergency AEAD sealing, terminal carry handoff, late-run quarantine and source/ancestry tampering. They do not constitute a real Actions delivery or a paid research result.
