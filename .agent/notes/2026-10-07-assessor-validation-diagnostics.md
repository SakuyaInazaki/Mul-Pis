# Private assessor validation diagnostics

The original-objective assessor now uses one frozen response schema for its initial prompt and same-session correction. When prior grounding is indexed, both prompts require a grounded assessment delta and a decision-changing next-task hypothesis. A malformed response cannot dispatch work, grant read credit, or close the mission.

The continuation collector now carries the current run's repair-state receipt into an ordinary authenticated checkpoint and discards a stale predecessor's receipt when the current run has none. An earlier encrypted result can contain a repair receipt even when its already-sealed carry omitted it. The host may review that result as separate private workflow-repair evidence under exact result artifact/source/checkpoint binding; the old carry itself is never rewritten and the result does not grant scientific acceptance.

Every repair-triggering original-objective reply is recorded before another prompt, including malformed schema, missing returned evidence, a blocked verdict with available work, and a proposed task with no available adapter. M04 uses the same sink for incomplete selected-evidence reads, malformed proposal JSON, and structurally rejected drafts. Its rejected transaction remains a rejected draft with no merge authority. An ordered private diagnostic retains the raw model text, host validator code, fixed reason, field path, safe underlying grounding reason or exact private M04 issue data, session generation and attempt, and actual returned read ranges. The first rejected turn of a session copies its available transcript into a separately named private file; later diagnostics in that same session retain their own exact raw reply and refer back to that frozen first transcript. An unavailable transcript receives a typed reason. Both file types use the existing RSA-encrypted outcome transport with bounded regular-file checks. They do not enter the public Actions log, model prompt, or accounting carry.

The result transport has finite per-file and aggregate byte bounds. A physical diagnostic write failure stops the next assessor prompt or M04 repair and leaves a typed private status cause, including the initiating validator code/path, for recovery; it never creates a scientific completion or treats an unrecorded reply as valid. When M04 already wrote a transaction, the driver attempts to export its exact portable transaction into the RSA result before stopping, including a prefixed file when the working archive lives in temporary scratch. That emergency copy is unbound diagnostic evidence and cannot authorize import, merge, or adoption without the ordinary completed archive and host checks. A missing matching transaction or failed secondary export is recorded without replacing the initiating error. Earlier encrypted outcomes cannot retroactively reveal a validator subcondition or a raw response that they did not preserve.

The private status also retains a fixed allowlisted OS error code, such as EACCES or ENOSPC, when a diagnostic file or sequence reservation fails. Unknown or malformed codes are omitted; exception text and filesystem paths are never copied into this field. If the result directory is wholly unwritable, the encrypted status artifact itself may be unavailable.

The next authenticated private run exposed a repair contract mismatch: the grounded physical-gap validator required an exact unavailable scope ID, while the model-visible host facts described unavailable observations and numeric execution bounds in prose. The indexed-delta schema also omitted the allowed issue status values, and a same-session correction received only the broad validation category. The host now freezes a machine-enumerated unavailable capability registry in the line-addressable host evidence and supplies its exact IDs and row locators to both objective assessment stages. A physical gap must cite the row for its chosen exact ID. This registry does not make a scope dispatchable; the supported executor adapter list is unchanged. Both initial and correction prompts show the full issue shape and exact unavailable IDs. Corrections include only the fixed validator field path and safe host detail, and stagnation compares those distinct host issues. The scientific claim, original obligations, current evidence-read proof, unavailable-equipment limits, and open-ended closure gate stay under their prior checks. Old encrypted replies are diagnostic evidence, not accepted scientific assessments.

A later encrypted assessment showed repeated indexed resolution citations in `part:line` string shorthand. The host had required span objects while describing their field names without object types, then collapsed all malformed and out-of-range spans to a broad delta error. The indexed prompt now gives the exact `priorRef` and `evidenceRefs` object shapes and maps an authenticated prior locator to `{sourceId:partName,startLine:line,endLine:line}`. A typed structural error identifies the exact JSON pointer; its private diagnostic and same-session feedback contain only the host-frozen expected locator or registered source bound, and sanitized actual type/line fields. The model's raw citation shorthand is not copied into feedback. Correcting format does not create read credit, change a prior issue, or accept a scientific claim: the ordinary exact-locator, new-evidence and current-session read checks still apply. A synthetic three-turn indexed assessment first rejects a string `priorRef`, then string evidence references, and accepts only properly returned spans.
