# Same-method workflow A/A calibration

An explicit workflow calibration command now runs two fresh isolated M07-to-M04 arms with the same active evidence-handoff H version, or with the builtin method in both arms. The caller supplies a development case set, an isolated experiment root, and an even number of repetitions. Execution order alternates across repetitions. This is local handoff variability evidence: matching failures remain failures, discordant checks remain visible, and a complete calibration does not establish scientific benefit or promote a method.

Calibration reuses the workflow source template, formal M04 and knowledge-epoch check, frozen case inputs, policy copy, live limits, necessary H-reference checks when H is used, and complete handoff/usage receipts. It does not call the improver, open protected admission cases, create a candidate, or modify production active method and knowledge pointers. The parsed plan and development case set are retained with the calibration record. Each arm receipt is written before the next arm starts, and the current unpaired arm is discoverable in `run.json` as `partialPair`. An incomplete first arm stops the pair before another provider call; an incomplete second arm retains both receipts in `partialPair`. Frozen template model configuration is checked against the active bundle for roles actually used: research for calibration, and research plus improver for method search.

The CLI exposes `improve research workflow calibrate --plan`, returning a nonzero exit code for incomplete or failed calibration; the Pi extension also exposes `workflow-calibrate`. The extension's older instruction to impose a total estimated-cost ceiling was removed so estimated cost remains an observation under the current project policy. Offline regressions first reproduced the missing service entry, then verified same-method fresh arms, no improver/protected evaluation/promotion, builtin independence from unused H/I references, model drift rejection before provider use, honest disagreement and failure recording, retained per-arm receipts and partial pairs, and CLI routing. No real model, network, or production experiment was run for this change.
