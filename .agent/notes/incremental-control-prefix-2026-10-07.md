# Incremental private control prefix

This batch adds an isolated host-only checkpoint writer and reader. The writer projects an accounting-only request audit and a partial host-effect observation, binds them to the current run and prior carry digest, seals them with an AES-GCM key derived from an authenticated mission key, and atomically replaces one private `incremental-control-prefix.json` file. It retains the previous complete file if a new snapshot is invalid or the write stops before rename. The reader requires the authenticated key and exact source and rejects changed ciphertext or metadata. The effect observation is explicitly incomplete and has no selection authority. A confined session with an attested grant may be recorded before its controller task is persisted; later snapshots may add the task but cannot change the grant or drop earlier request and operation identities. The writer also rejects rollback of previously observed controller operation, task, and goal states while permitting the controller's forward transitions and external reconciliation.

The file has its own entry in the existing RSA outcome transport allowlist, with an offline encrypt/decrypt test. The prefix is always labelled incomplete, unreviewed, and non-replayable. Monetary observations remain observations and include in-flight and unpriced states without a new monetary gate. An optional sink is injectable, but no new upload service or permission is configured here.

The campaign driver now obtains the already authenticated mission-derived key through its ledger continuation and calls the writer before provider dispatch, after observed responses and at objective control checkpoint updates. The workflow transports the encrypted prefix through its existing carry artifact step; a prefix-only artifact remains a nonterminal missing-carry gap. Recovery checks exact Actions archive provenance and AES-GCM source/parent binding. It makes no claim about work after the last recorded prefix, completion of research or M04 judgment, or survival when the final wrapper upload does not run. A predecessor without this AEAD prefix remains on its previous opaque-gap recovery path.

Private diagnostics expose typed stages and reason codes for envelope decoding, source binding, AEAD authentication, decoded schema, monotonic regression, and file/I/O bounds; public error text remains generic. A recorded UNKNOWN billing request retains its observed hold and reported usage in later local prefixes. The prefix contains accounting/control observations only. It has no selected artifact bytes or closed transition proof and does not establish scientific progress adoption.

Verification: `npm run typecheck`, `node --test test/incremental-private-checkpoint.test.ts` (24 tests including nested cases), and `python -m unittest discover -s test -p 'private_actions_transport_test.py'` (9 tests) passed. No model call or network request was used.
