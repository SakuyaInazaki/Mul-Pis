# Generic historical restart migration

The live private restart path now treats authenticated earlier source policies and missing-carry effects as historical UNKNOWN observations. It preserves the original signed seed and encrypted ancestry, cumulative known accounting and unquantified gaps, selected tuple, and unresolved operation references. New research requires a fresh isolated store, current confined tools, and a new host-bound fresh-only reservation. No old session, proposal, or task is replayed or automatically adopted.

This batch removes exact historical run/source/artifact pins from live restart and ledger code. It also retires `test/one-time-legacy-v3-source.test.ts` and `test/one-time-legacy-v3-brand.test.ts`: both assert the removed one-time authority using literal historical identities. They are recoverable from Git history. Dynamic reusable control-request first-parent/tree/CI tests and generic signed-carry, missing-carry, and seal/reopen tests cover the retained behavior without giving one historical execution special authority. Historical envelopes and signatures are read as originally recorded; their raw bytes are not rewritten.

This migration does not reconcile earlier provider invoices, M07 operations, M04 transactions, or arbitrary historical host effects. Their UNKNOWN status remains explicit. The current source and tool boundary is independently checked before any new model work.

A new host-authored transition receipt inside the authenticated carry records each actual canonical selection change after an accepted M07 result, passed current verification, and completed portable M04 adjudication. The receipt retains the prior and selected tuple identities through later wrapper runs; a rejected draft cannot create selection authority. Newly selected registered work includes its plan in the selected tuple, while historical tuple names remain byte-exact. An incomplete M04 stage keeps its candidate as unselected history and retains the last authenticated selection.

One Actions execution may still end with an incomplete objective checkpoint after a real transport or unavailable-evidence boundary. That status leaves the mission open; the current controller does not yet contain a fully automatic cross-run scheduler. The authenticated run-request path can continue from the preserved state without replaying UNKNOWN external operations. A separate host-authored pending-action/supervisor increment is needed for unattended cross-run continuation.
