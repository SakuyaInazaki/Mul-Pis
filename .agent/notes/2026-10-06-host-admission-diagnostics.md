# Host admission diagnostics without another provider request

The host now records a structured, content-free diagnostic when it rejects a prepared provider request before transport. The encrypted mission carry includes the serialized candidate byte count, conservative input and output-margin estimates, remaining global CNY, one-token requirement, affordable output allowance, price assumptions, and whether the limiting condition was input cost, minimum output cost, a requested cap above the affordable allowance, or the provider-call limit. It explicitly says `requestNotSent: true`. No raw prompt, model response, credential, session identifier, or rejected request ID is included. The ordinary status exposes only the decision and unsent flag. Admitted request rows also distinguish full from reduced output caps.

The first request in a safe, host-attested confined-file or no-tools prompt may now receive a branded local not-issued disposition if host admission refuses it. An issued prompt with any admitted request cannot use that zero-request proof. M07 must still check its live confined-file grant before recording a not-issued operation. The research task remains incomplete; the global 30 CNY ceiling, conservative earlier commitments, and unknown holds remain unchanged. Older encrypted carries without the new fields remain valid.

The previous real run did not retain the rejected payload size. Its exact size is unknown, and this change cannot retroactively supply it. No paid request was made for this diagnostic repair.
