# Live execute continuation after failed M04

The same-owner failed-M04 continuation now includes a returned, evaluator-rejected local execute task when its single M07 operation has a complete response and every persisted Pi tool call has a paired terminal result. Managed Bash calls additionally need a terminal host receipt, a terminated shell identity, and no active process in the shell's attributed process group. The host checks this evidence again before finishing the unselected partial M07 result. The failed M04 still needs the exact no-proposal transaction and no unresolved knowledge merge. Accepted candidates and unknown operations remain held.

This is an observed local control boundary for an already returned M07 task. The Bash receipt records its group at shell exit; the live gate also checks that group again before completion. An empty process group does not prove that a shell did not start detached or remote work; the managed receipt retains that uncertainty. The continuation does not change historical unknown effects, authorize remote actions, or turn an evaluator report into scientific selection. Execution loops are held because their multiple rounds cannot be attributed by the current single-operation receipt reader. Forked Pi sessions are also held: their inherited tool-call prefix cannot yet be separated from the current operation by an authenticated fork boundary.

Offline default-mission regressions use a real managed Bash call to compile and run a small C++ program and a typed Pi read call. They verify that a failed no-proposal M04 becomes frozen negative feedback and that the same mission invocation chooses a distinct second execute task without replaying the first. An active background process group and a persisted unknown M07 operation each block new work. The background test terminates its exact test process group and checks that no active member remains. Direct local typecheck and 15 affected default-mission tests passed after the final fixture change; 115 broader focused tests passed earlier in this batch. All checks use existing dependencies; no model, network, cloud task, or GitHub Actions run was started.

Both live managed and V6 historical transcript readers now reject a tool result before its call, duplicate calls, orphan results, and an explicit ancestor session header. V6 binds a present header to the expected builder or reviewer session and its position before messages while continuing to accept older headerless transcripts; the live reader requires its exact current session header. Default execute-path corrupt-transcript cases remain held without a second builder call. These ordering checks do not grant lineage authority to inherited tool histories. One hundred and one affected execute/V6 history tests and direct typecheck passed after these checks.

The historical reader also rejects a present builder or reviewer session reference with a missing or malformed ID or file, including a reviewer with no tool calls. Only a truly absent optional reviewer reference is omitted. During live group observation, a process that disappears while its `/proc` stat is read is treated as gone for ENOENT or ESRCH; other read failures retain an unknown group status. Deterministic disappearance and unreadable-stat checks, the exact background cleanup, and the malformed-session cases passed in the final offline focused run: 169 tests, with direct typecheck passing.
