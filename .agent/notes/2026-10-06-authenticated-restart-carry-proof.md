# Authenticated carry evidence for independent restart

The ledger reader now exposes a narrow host-only proof after authenticating the latest carry, validating its complete accounting ancestry, and independently matching the completed GitHub run and job identities. The proof records the source run/attempt/commit, exact encrypted carry envelope digest, immutable carry artifact identity, terminal job/step observations, admitted current run, and unchanged cumulative committed and unknown-held amounts. It is deeply frozen and branded in a private runtime registry; copied, deserialized, or model-authored objects are not authority. A sorted-key file-map digest and predicate bind the exact restored private bundle without disclosing its contents.

When the same verified artifact listing contains one matching unexpired encrypted-result artifact with a valid GitHub SHA-256 digest, the proof also exposes its immutable identity and digest. The scope is explicitly the GitHub artifact archive, not the inner encrypted result-envelope file. Missing, ambiguous, expired, or mismatched result metadata cannot create this reference.

The optional restart claim callback is scoped to the reviewed Actions workflow with one host driver invocation and its fixed shared concurrency group. It checks the current durable run record and exact active job/campaign step again, binds the prior carry digest and current run/attempt/commit/job, and permits one claim per admission in the host process. The full-history ledger check requires later runs to account for that executed run with an authenticated carry, or stop if it is missing. This is not a filesystem lock or a general distributed compare-and-swap across arbitrary host processes. Claiming does not reconcile an operation, rewrite an old goal, release unknown billing, or grant provider/tool authority.

The fixed private continuation and encrypted outcome allowlists now retain the independent restart quarantine receipt and its fresh-goal binding. These receipts remain host control evidence and are not model inputs. Synthetic tests cover proof identity and immutability, exact bundle binding, terminal identity mismatches, archive digest scope, active-current-job checks, concurrent duplicate claims, retained unknown amounts, and both encrypted persistence routes. No provider call or live task publication was part of this change.

Inherited quarantine receipts can now be checked against an exact source run/attempt/commit and encrypted-envelope digest in the already validated carry ancestry. A new branded predicate uses a private runtime ancestry registry, including the latest prior carry, and rejects copied proofs, wrong versions, changed source identities, unrelated digests, and inferred fields. This exposes no key or private file content and makes no accounting or settlement change. Synthetic regressions cover exact and mismatched ancestry bindings while preserving unknown holds.
