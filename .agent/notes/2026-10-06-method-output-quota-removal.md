# Method-path output quota removal

The user asked to remove workflow-imposed model output limits. The research-method and mechanism-improvement paths formerly kept aggregate output-token quotas separate from their monetary and input accounting. This batch removes those output quotas from active budgets, phase preflight, admission, and prompt views. Actual output tokens remain recorded and priced. Older plans may still contain `maxOutputTokens` or `maxTotalOutputTokens`; validators accept and omit those historical fields from a newly executed plan. Existing historical files are not rewritten.

The manual public M01 smoke path no longer sends its former 8,192-token limit. Before a model call it verifies the exact DeepSeek Flash provider maximum through `/models`, sets the temporary model profile to that provider bound, and estimates the full-bound request cost. Its separate 2.1 CNY smoke ceiling was not enlarged, so current full-bound pricing is expected to reject the smoke request before a paid model call. This is a policy migration, not evidence of a new successful smoke run. Public documentation and offline tests were updated. No private case, authentication value, paid model call, commit, or push was part of this change.

The user's later instruction also removed workflow execution-time and repetition/count limits while retaining file-size limits. Method campaigns now treat former decision, candidate, inspection, schema-repair, provider-call, trial-call, aggregate token, CPU-time and wall-time fields as historical only. Current plans and I prompts omit them. A campaign still requires an explicit monetary budget, complete usage and an explicit or evidence-based terminal outcome; paired evaluation repetition counts and the CPU case's probe allowance define the experiment itself. Repeated unchanged candidate text is reported as a rejection with feedback; it is not a new terminal condition. The public M01 script's 90-second abort and service-level prompt/stall deadlines were removed. The final audit also removed the project-set Actions job timeout; any GitHub-hosted runner lifecycle limit is external to this workflow.

Retained data-size and persistence boundaries include case-material characters, frozen case file bytes, readback windows, method artifact fields, and serialized MetaEpisode/readback file bytes. The former bare 8,000-character CPU executor response rejection was removed; a valid longer response can be parsed, while persisted artifact fields still follow their schema. No historical snapshots were rewritten. Regression tests were updated for no quota-driven premature stop, with offline fake sessions only.

The public M01 smoke's final audit removed the five-minute project-set Actions job deadline and the last one-call strict-request rule. The live provider-bound DeepSeek campaign ledger now attaches to its Pi runner. It reserves each serialized HTTP payload against the unchanged 2.1 CNY total smoke ceiling before transport, enforces the existing 12,000-byte payload boundary, and records every complete priced provider event. The sidecar validator accepts multiple fully accounted assistant events with a final stop. The former single-call estimate alone could not protect a multi-transport SDK turn; the per-transport ledger does. Under current full provider output bounds this still rejects before paid model work, and no new smoke run is claimed.
