# Bounded DeepSeek campaign runner (2026-10-04)

This change adds an optional, in-process campaign budget to the Pi SessionRunner. When installed, all created and resumed sessions must use one fixed DeepSeek model, official endpoint, request payload byte cap, output-token cap, and a shared sequential prompt lane. Each provider payload reserves a worst-case CNY planning amount before SDK transport. Agent and provider retries and compaction are disabled. The shared call and CNY ceilings cover every request that passes through this runner, including a tool-using M07 builder, fresh reviewer, and session reuse. Reservations are never refunded, and failed, aborted, unpriced, incomplete, over-budget, or nonpersisted outcomes stop further campaign dispatch. A campaign has no process-restart budget recovery; creating a fresh instance does not continue its ledger.

Campaign mode rejects Pi's native execution grant, since its bash tool can make unmetered network calls and its file tools are not rooted to the task directory. It also rejects arbitrary custom tools and read-dir extras. A real M07 driver must substitute the audited `createConfinedCampaignFileTools` grant for the builder while preserving the controller's task and review loop. This factory supplies no subprocess or network tool and requires an exact relative-file write/edit allowlist. Defense-in-depth minimal environment handling for native bash remains in the runner, but campaign mode does not admit a native bash child. This is not an OS sandbox or a secret-isolation boundary: same-UID access and other network-capable code in the driver must still be considered. The planning estimate also cannot guarantee the provider invoice, price or exchange-rate stability, or behavior beyond the pinned SDK request path. A real paid lab run therefore still requires a reviewed tool/data boundary, a private material handoff, and verification of current official pricing and the user's remaining cap.

Offline injected-transport tests cover multi-request tool loops, reservation-before-transport denial, endpoint change, payload rejection, incomplete/excess usage, ledger-persistence failure, preserved legacy one-call behavior, unsafe-tool rejection, and confined-file behavior. Typecheck and the full offline suite (350 tests) passed. No paid request or lab execution was made in this batch.
