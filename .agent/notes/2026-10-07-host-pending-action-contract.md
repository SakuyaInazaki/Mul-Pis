# Host pending action contract

The original-objective checkpoint can now include a versioned, host-authored pending action for the next safe work boundary. The record distinguishes an incomplete mission from the action after a suspended run. Its kind names the next host step, and its safety class identifies read-only same-session repair, independent fresh work, or reconciliation before replay. A prior authenticated-carry source can be attached when available. Older checkpoints without this field retain their serialized shape.

The pure classifier uses host stop reasons and explicit host observations. An invalid assessment, model blocked verdict, rejected M04 draft, or transient transport failure does not alone assert that a person is required. That assertion requires a separate host-verified, exclusive unavailable credential, input, permission, or capability. Unknown M07 operations and unresolved M04 transactions take precedence and retain the no-replay boundary. Structural validation checks carried actions before reusing them.

A model claim of fulfillment cannot overwrite a concrete failed dispatch, accounting-integrity failure, unresolved M04 transaction, incomplete bounded run, inaccessible assessment evidence, cancellation, or rejected or unread M04 evidence. Accounting-integrity failure retains a no-replay safety boundary until the accounting chain is reconciled.

Offline verification: the focused original-objective and ledger-continuation suites passed 79 tests, and TypeScript typecheck passed. These tests exercise controller classification and serialization; they do not run a provider or prove scientific completion.
