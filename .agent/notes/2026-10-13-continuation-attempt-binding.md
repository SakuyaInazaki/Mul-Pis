# Keep ordinary continuation bound to its recorded attempt

Review of the runtime version handoff found that ordinary continuation only checked a versioned goal owner when a run descriptor file was configured. Without that file, the extension could claim the goal and later suspend its recorded owner. With a descriptor present, attempt ID and recorded code revision were not compared with the active attempt. The new regression exercises both bypasses and the valid matching owner using an observed local process identity.

The repair requires a descriptor for ordinary continuation of a versioned goal and matches its attempt ID and recorded revision as well as the existing workspace, instance and process identity checks. Legacy unversioned goals keep their existing path. Rejected startup never binds the goal or suspends its owner during shutdown. This checks consistency with the persisted attempt; a revision label alone does not prove which source bytes a process loaded or that a source candidate was admitted. Existing running sessions and historical records are not modified.

Validation: the regression first reproduced all three incorrect acceptances while the matching-owner case passed. After repair, the continuation suite passed 24/24 and the installed TypeScript typecheck passed. The first full offline run had one timeout in the separate synthetic Actions observer smoke (1,592 passed, one failed, 16 skipped). That smoke passed 3/3 when rerun alone; a complete rerun with unchanged source passed 1,593 of 1,609 tests, zero failures and 16 existing platform/local-fixture skips. The transient timeout was not reproduced or treated as repaired by this change. The staged diff and simulated public file list were reviewed; no active experiment data is included.
