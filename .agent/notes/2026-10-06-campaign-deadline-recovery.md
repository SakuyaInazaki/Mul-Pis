# Campaign deadline and incomplete-attempt recovery

The private campaign driver previously gave each builder and M04 phase a short fixed pilot deadline even though the GitHub campaign step provided a larger bounded envelope. A builder timeout could leave an issued provider operation unresolved. The driver then attempted to finish the active M07 goal, which correctly failed closed and obscured the intended incomplete checkpoint path.

The driver now derives the campaign window from the Actions campaign-step timeout with a reserve for setup and transport, uses the remaining campaign boundary for builder and M04 work, and checks unresolved task or operation state before finishing a goal. Such a goal remains active, with an auditable incomplete checkpoint and bounded private archive. Unknown provider reservations remain held for independent reconciliation.

The continuation collector keeps the last coherent accepted candidate tuple while retaining new unselected attempt source, plan, verification, and reviewer feedback as untrusted, version-bound development history. The current unresolved objective checkpoint remains current control state; it is not part of the historical accepted snapshot. Registered feedback identifies when no candidate measurement ran instead of attributing baseline observations to the attempted candidate. The bounded private verification archive preserves a structured source-gate rule and location plus the requested-thread policy, while recording that actual OpenMP team sizes were not observed.

Synthetic tests cover remaining-envelope deadlines, failed initial-task checkpointing, and prior-tuple retention with failed-attempt history. No real model, private input, or network invocation was used for these tests.

An independent fresh-goal restart adapter now reserves a quarantine receipt before model use, binds the actual new M07 goal before execution, and carries append-only reservation/binding lineage. Admission requires the authenticated prior carry, terminal Actions job evidence, a fixed encrypted-result artifact digest, current independent validation of the earlier selected candidate, and a reviewed source/effect policy. The old active goal and unknown operation stay unchanged, and unknown provider cost remains held. The reviewed source policy is only a compatibility entry for one immutable historical revision; future source revisions need separate review rather than inheriting this assertion. If proof or the sandbox is unavailable, admission fails before provider calls and the diagnostic checkpoint and ledger are retained.
