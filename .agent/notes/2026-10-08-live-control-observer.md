# Encrypted live control observation

The confidential campaign can run for hours while its ordinary result and carry artifacts appear only at the end. This change adds an optional observer for later Actions runs. A local Node24 JavaScript action receives the artifact runtime channel and supervises the trusted observer process; the observer supervises the same campaign driver and uploads small, uniquely named, one-day ciphertext artifacts after the driver has durably committed an incremental control prefix. Ordinary shell steps do not receive this artifact runtime channel. The observer does not read or publish model replies, task text, file paths, performance results, credentials, fee settlement, or scientific completion.

The trusted action and observer retain Actions artifact runtime credentials and give the campaign child a positive allowlist of its existing one-shot inputs. The action relays only the fixed public heartbeat from the observer's FD3; campaign stdout, stderr and artifact toolkit logs remain private. A separate private FD4 carries bounded status frames; each frame uses a key derived from the signed mission seed under a distinct label, binds the exact run source and committed prefix sequence, and reports partial controller counts and finite goal, task and operation state counts. The observer authenticates the frame before any artifact upload. A local private reader checks source, AEAD, schema and sequence gaps after artifact download, writing only control status to a new restricted file. These observations have no selection, replay, accounting or completion authority.

Observer initialization, pipes and uploads are best effort. They run after the critical prefix commit, use one latest pending status, coalesce unchanged facts, and sample request-only changes. Every attempted live upload, including an uncertain failure, consumes one of at most 498 observer slots, preserving two of the documented 500 artifact slots per job for the existing final encrypted outcome and carry. This is a platform capacity boundary for observation, not a research request, time, fee, or output limit. The trusted parent does not await observation before returning the campaign child's true exit status.

The JavaScript action records the true campaign exit in a private receipt and writes its code to the existing step output. A missing observer receipt is an incomplete trusted-parent failure, not a successful campaign. The action itself leaves the encrypted finalization steps runnable; the existing final generic failure step reports the true unsuccessful result after ciphertext output.

The trusted Node parent and fixed campaign driver remain host code. The child environment allowlist is credential separation, not whole-process operating-system isolation. Untrusted model file tools and native validation still use their existing confined permissions and Linux namespace sandbox, with the existing fail-before-provider isolation probes. Local structural tests check the fresh proc mount and cleared native environment; the sandbox cannot execute in this development container, so a live namespace behavior claim depends on the Actions preflight.

Offline tests cover source and ciphertext authentication, malformed frames, same-count controller state changes, sampled status, upload ambiguity and slot reservation, private output streams, heartbeat isolation, and observer failure without changing the child exit. The regression workflow now includes a separate Node24 smoke action using an ephemeral signed seed, a fake no-model child, the production frame/gate/uploader, one real artifact upload and a same-run download with authenticated read. It receives no mission or provider secret. The smoke must pass on GitHub for the exact published source before describing the live upload path as verified there. No live campaign was changed or launched by this local batch.
