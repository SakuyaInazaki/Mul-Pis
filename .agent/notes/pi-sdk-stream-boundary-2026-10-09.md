# Pi SDK streamed tool boundary regression

Added an offline loopback HTTP fixture that runs the actual Pi 0.85.1 AgentSession, ModelRuntime, pi-ai OpenAI Completions adapter, OpenAI SDK request serialization, and the harness PiSessionRunner. A locally intercepted DeepSeek route reaches only the loopback server; no provider credentials, provider requests, or external network are used. The fixture splits SSE JSON frames during a reasoning/tool-call response and verifies one confined local write, then checks the actual second serialized request contains the assistant's signed reasoning, complete tool-call arguments, and exactly one matching tool result. It also checks two distinct observed usage events.

The second fixture interrupts the next HTTP stream after the real local tool has returned. Pi reports an incomplete prompt; the local write appears once, there is no automatic third SDK request or tool replay, and the second request remains unknown rather than attributed reported usage. This covers one in-process transport break after a side-effectful tool, not caller-triggered recovery or process restart. These fixtures do not establish compatibility with a live DeepSeek response or actual billing. No production defect was reproduced or changed.
