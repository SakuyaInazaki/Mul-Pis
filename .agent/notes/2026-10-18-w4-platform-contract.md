# 2026-10-18 W4：新增平台层，把目标硬件的契约变成执行面上的结构

## 为什么

审查依据 A11 共 28 条（21 条 P0），对照结果是：**仓库里原本没有任何平台层**。
`grep -rniE 'ascend|cann|npu|910b|aclnn|triton' src/` 命中 0 条，硬件信息只以自由文本形式出现在任务契约里
（`src/m07/types.ts` 注释写的是 "Platform references such as baselines or hardware bounds"）。于是依据里
那些「成本极低、收益极大」的拦截点一个都不存在：

- RB-A11-02（P0）：生成后、编译前的 API 白名单与签名校验，零设备成本却命中一半以上的首轮失败；
  `no member named` 一类错误应当直接触发签名检索而不是重试。
- RB-A11-03（P0）：容量常数必须从实机读。三篇论文给同一代芯片的 UB 上限分别是 196352 B / ≤204800 B /
  256 KB，互相矛盾，抄哪个都可能让整类算子编译失败。
- RB-A11-04（P0）：32 字节对齐是正确性约束、512 字节对齐是带宽约束，两者用途不同，不得互相覆盖。
- RB-A11-06（P0）：队列配平与尾块掩码要做成**代码结构约束**，不是 prompt 里的禁令；尾块缺失是「能编译
  通过的错误」，最危险。
- RB-A11-07（P0）：matmul 路径先查 `SetBlockDim(1)` 与高吞吐模式两条「一行换数量级」的设置。
- RB-A11-15/16（P0）：产物是 host+device 四件套，agent 的编辑面只应覆盖 device 代码；host/device 分裂本身
  是本平台特有的作弊面，binding 里必须出现真实的设备启动调用、且不得退回框架算子。
- RB-A11-08（P1）、RB-A11-19（P1）、RB-A11-23（P0）：瓶颈标签由指标比值确定性产生、编译前先跑廉价静态检查、
  把编辑面收缩成「受限配置 + 可静态校验的结构声明」。
- RB-A11-17/18（P0）：精度判据按 dtype 尾数位取 τ，不是全局一个 atol；用例必须按四轴构造，非对齐占比 ≥50%。
- RB-A10-08（P0）：设备访问要加锁串行化，崩溃后回收锁。
- RB-A10-13（P1）：工作区＝只读评测面 + 最小可编辑面 + 单文件不变式。
- G8-20、G5-22：失败反馈要能定位到程序决策、只做机械压缩与路由，不得语义润色。

## 改了哪里

新增 `src/platform/`（五个模块，互相单一职责）：

- `profile.ts`：平台档案的 schema、校验与加载。**代码里没有任何硬件数字**；档案里的每个容量常数必须带
  probe 回执（命令、时间、原始输出文件），没有回执直接拒绝加载。还会在加载期拒绝：正则不可编译、指标
  模式没有捕获组、budget 规则引用不存在的容量、瓶颈标签引用不存在的指标、计时口径与指标口径相同、
  精度放宽超过 10×、用例表不满足四轴（<4 条、非对齐不足一半、元素量级 <3 档、秩 <2 种、数值范围 <3 种）。
  `platformTolerance()` 由尾数位算 τ=2^-mantissaBits，不接受直接写死的容差。
- `contract.ts`：规则引擎，六种规则（forbid / require / forbidWithin / requireWithin / pairing / budget）
  加一条内建的符号检查：命名空间调用若不在档案声明的 API 表里就驳回，并按编辑距离给出最接近的合法名字。
  每条发现带规则 ID、用途、file:line、原文证据与修复方向。`platformEditable()` 判定可编辑面。
- `diagnostics.ts`：按档案的模式对工具链/profiler 输出做分类与路由，**不改写原文**；指标比值命中哪条标签
  就给哪条标签与动作顺序，命中不了就写 `inconclusive` 而不是猜一个瓶颈。
- `device-lease.ts`：跨进程设备租约，独占创建即占有；持有者用完整进程身份记录，确认死亡（同主机同 boot、
  进程不存在）才接管，状态未知一律不抢。
- `gate.ts`：把以上组合成执行面上的闸门，并把每次判决追加到 `<persistDir>/<sessionId>.platform.jsonl`。
  档案通过宿主环境变量 `PRE_RSI_PLATFORM_PROFILE` 绑定；模型侧 bash 的环境是重建的，看不到也改不了它。

`src/runner/pi.ts`：execution 会话创建时按环境绑定闸门，并接到工具层——
- `write` 用参数里的完整内容、`edit` 先按同样的替换算出结果文本，**在写盘之前**判定；驳回时抛
  `runner.platform-contract`，字节从未落地。
- 匹配设备命令模式的 bash 命令先拿租约再执行，异常路径也会释放。
- bash 结果在原文之后追加机械解读（失败分类、最接近的签名、确定性瓶颈标签）。

没有档案时以上全部不生效，行为与改动前一致。

- 新增 `test/platform/profile-contract.test.ts`（9 项）、`test/platform/gate-device.test.ts`（7 项）、

  每类违规各报一次且用途不混、幻觉符号给出最近合法名、binding 作弊面、可编辑面、一轮一文件、租约独占与
  死主接管、驳回的写入不落盘、模型侧 shell 读不到档案路径。
- 新增 `docs/implementation/platform.md` 说明档案格式、加载期拒绝条件与有意的边界。

## 边界

- 规则是文本级的，不是 AST 或类型检查；能挡契约违例，挡不了算法错误。
- 闸门只看得到文件写入与工具输出；命令内部做了什么它看不见，binding 层的完整性规则与评测器自己的检查仍然必要。
- 仓库**不自带任何芯片的档案**：容量要实测、API 表要从安装的头文件里抽，这是操作者的工作，不能抄论文。
