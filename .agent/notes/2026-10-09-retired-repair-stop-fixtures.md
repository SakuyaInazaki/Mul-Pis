# Finite fixtures after removing a repair-attempt stopping rule

The synthetic mission tests previously returned the same invalid assessor reply or blocked verdict forever. They ended only because the old assessor implementation stopped after a fixed number of repair attempts. Once that production limit was removed, these tests could run indefinitely even though the workflow was continuing as requested.

The fixtures now issue an explicit synthetic `AbortError` after several repeated replies. This is a test stop, not a production attempt or time limit. Assertions require `cancelled`, retain the incomplete original objective, and verify that recovery does not replay the old builder, evaluator, or M04 work. Ordinary text containing the word “cancelled” remains an ordinary model/tool error in the existing failed-M04 fixture.

The two-owner returned-evaluator race had the same hidden dependency in its loser retry child: that child's assessor returned invalid text indefinitely after the winner settled recovery. The child now stops by an explicit synthetic `AbortError`; the real recovery race still has exactly one M04 and no replay. The targeted cross-process test passed 1/1. Two detached full-suite attempts stopped after their logs remained at the preceding evaluator-journal file, before this fixture; they were interrupted as incomplete test runs, not reported as passing.

The clean cross-process restart and declared binary-material tests also used permanently malformed assessor replies for a one-step authority check. Each now terminates by typed synthetic cancellation after repeated replies, while still requiring the clean restart or exact material handoff. Their direct test files passed 1/1 and 3/3. The V5/V6 interrupted-reconcile fixtures had the same pattern and are handled in their own change batch.

Three more assessor fixtures intentionally withheld mandatory read returns for a selection proof gap, repair feedback, or committed knowledge. Valid JSON with that missing coverage remains provisional, so an assessor permitted to keep correcting would also loop in those tests. The shared synthetic runner now aborts after repeated incomplete reads only for those three fixture options; assertions still require no second builder dispatch. The targeted selection-gap and repair-feedback test groups passed 5/5.

The managed foreground Bash recovery fixture also returned an actionable blocked verdict forever after its second distinct task. Only its `foreground` branch performs the continued default `mission.run`; that branch now uses an explicit synthetic abort after repeated blocked verdicts and still checks both builder/M04 calls, the old failed-M04 feedback, and no selected artifact. The background, UNKNOWN, and malformed transcript branches keep their original fail-closed tests.

Two accepted-task review fixtures deliberately omitted every M04 read event or all required observation reads. Their M04 fake now aborts explicitly after repeated provisional judgments. The test verifies that the pending review checkpoint remains durable and no artifact becomes selected; the targeted test passed 1/1. This fixture stop does not make the real M04 repair loop stop after a fixed number of attempts.
