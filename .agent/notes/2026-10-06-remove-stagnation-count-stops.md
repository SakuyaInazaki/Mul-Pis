# Remove repetition-based continuation stops

The normal noninteractive Pi continuation used to stop an active goal after two unchanged empty rounds. Repetition now produces an explicit observation and a request for a concrete next action, without ending the goal. Persisted goal completion, real cancellation, provider faults and unavailable execution identity remain distinct outcomes.

Original-objective reassessment also stopped after the same unavailable proposal appeared twice despite other available host capabilities. It now retains the failed proposals and gives explicit repeat feedback until the model chooses an available action or returns a justified terminal outcome. It never dispatches an unavailable adapter. Historical stop-reason values remain readable.

Offline regressions run seven unchanged Pi turns before persisted completion and three identical unsupported proposals before a feasible fourth proposal. The process-control status view also reports all observed process-group members instead of silently dropping members after 32; scan failure remains unknown. No paid request, scientific adapter modification, or publication is part of this batch.

Updated AGENTS.md current control policy and the limit inventory to distinguish retired limits, current observability, retained byte/security boundaries, and unverified third-party behavior. Current policy does not authorize any paid run.

Final integration updated the old fee-stop checkpoint regression: retired fee/price labels do not replace the real incomplete-branch reason, and unresolved external operations still require reconciliation. Historical artifacts themselves are unchanged.
