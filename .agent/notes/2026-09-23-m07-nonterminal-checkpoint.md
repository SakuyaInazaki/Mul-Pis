# M07 nonterminal checkpoint and exact M04 source binding

An active M07 goal can now create a controller-owned `C###` checkpoint only when no task is running. The controller freezes its begin-time problem, bounded current text raw inputs, and files already frozen by task review. It writes a goal snapshot, manifest, and feedback under `checkpoints/C###/` before registering the checkpoint in the live goal. The live goal and M07 run remain active/running, and success criteria are unchanged. A failed or oversized freeze leaves no registered checkpoint; the existing goal remains intact. No live task work directory is granted to M04.

Checkpoint feedback is explicitly a development, nonterminal view. The existing frozen feedback character cap remains in force. When control facts exceed it, a bounded index points to the checkpoint's `goal.json`; this does not claim that M04 read the full evidence. The checkpoint manifest uses path/size records for access control, not file hashes. Frozen copy limits are 256 files, 8 MiB per file, and 64 MiB total. Oversized or unsafe files fail closed rather than being omitted silently.

An incomplete checkpoint attempt is never deleted or overwritten. The next attempt skips occupied `C###` directories and receives a fresh ID. Explicit nonempty, unique `taskIds` allow a later batch to freeze only those tasks' reviewed evidence; omitted tasks retain their control status but no readable review paths in the checkpoint snapshot. The manifest and bounded feedback identify selected and omitted task IDs. With no `taskIds`, existing all-task behavior remains. These snapshot limits affect this local handoff, not the M07 goal's execution contract or total workflow budget.

`ResearchService` accepts `goalAction('checkpoint', ..., {runId})` and `StageRequest.feedbackCheckpointId` only with M07 feedback. After M04 consumes a checkpoint, `plan(refreshBaseline:true)` requires the paired checkpoint ID and M04 run ID; the latest completed formal M04 run's controller source record must match this goal and checkpoint. A workflow method bound at goal begin cannot hot-swap its knowledge epoch. The existing plan path for goals without checkpoints remains.
