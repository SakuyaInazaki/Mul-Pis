# Local interrupted dispatch review boundary

This batch adds a narrow host review path for a later, independently verified local mission interruption. It does not reconcile any existing private mission or resume an old provider session.

A future built-in local dispatch now freezes a three-file lineage record after M07 assigns the task ID: equal mission-side and M07-side binding records, followed by a mission-side commit marker containing their SHA-256 digest. The binding names the MISSION intent, its host attempt and exact committed checkpoint, the M07 goal and task, the assessor task digest, and the M07 process owner. Missing, partial, or changed lineage cannot justify a continuation.

The `mission reconcile` CLI path requires the committed lineage, a dead same-host and same-boot old process, one exactly bound rejected M07 task with a complete feedback checkpoint and response-received operation, a failed M04 with the matching frozen handoff and no-proposal knowledge transaction, and a pinned review of the SDK output-maximum guard before HTTP. Its versioned host receipt and changed objective progress share one append-only checkpoint commit marker. The old checkpoints, provider usage, fees, task outcome, M04 failure, and candidate history are retained. The reviewed checkpoint allows only a new assessment and task; it grants no replay of the old task or session.

Legacy interrupted dispatches without an explicit committed mission-to-M07 lineage remain held, even where a goal and task share the same owner and objective text. Such similarity does not prove a unique causal dispatch edge. Unknown sends, unsettled knowledge transactions, live or reused process identities, stale checkpoints, forged review requests, and duplicate reviews also remain held.

Verification: TypeScript typecheck and focused local mission, adapter, host, restart, CLI, and reconciliation tests. No network or model calls and no active mission state changes.

A separate legacy review uses checkpoint receipt version 3 and retains `historicalExplicitDispatchBinding: false`. It may infer a unique serial dispatch only after an operator-reviewed effect declaration is checked against the exact old source commit/tree and audited loader, controller, stage, and provider blobs; frozen assessor task, task input digest and process owner; every MISSION/M07/M04 run in the workspace; all retained task tool entries, their failed results and unknown numeric exit codes; the M07 response, M04 transcript, failed no-proposal transaction and before-HTTP guard. The effect conclusion is limited to observations within the same-UID trusted host. It does not claim OS isolation or absolute absence of external effects. A legacy CLI review defaults to a read-only dry-run; only an explicit `--apply` can write a reviewed successor checkpoint. No historical lineage record is backfilled.

The legacy review additionally parses retained Pi session JSONL to pair every tool-call ID with one result and to count M04 assistant responses with positive usage separately from the single terminal zero-usage error. It records failed tool ordinals and missing numeric exit-code observations without treating those as success. Later host status reads re-hash the pinned old MISSION/M07/M04 records, frozen checkpoint material and M04 session transcript; changed historical settlement marks the host repair-needed. The receipt explicitly records that actual launch argv and historical dispatch binding were not persisted, labels the association as reviewed inference, and grants only fresh follow-up work.

Review publication now prepares a complete successor attempt off to the side and atomically renames the directory into the attempt sequence only after all source, checkpoint, process and effect checks pass. A crash before rename leaves the old checkpoint current; a crash after rename leaves a complete review. Dead review-writer locks and uncommitted preparations have an exact recovery path; abandoned preparations are archived, and duplicate requests return the existing committed result. The legacy admission census checks every observed MISSION/M07/M04 run for unsupported records, unknown M07 tasks/effects and open or unsupported M04 transactions. The committed receipt freezes that census at admission; later unrelated workspace runs do not invalidate it. Future dispatch lineage is recorded at the controller seam after durable task allocation and before session creation or provider/tool activity.
