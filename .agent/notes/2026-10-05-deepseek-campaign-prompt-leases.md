# DeepSeek campaign prompt leases and conservative settlement

- Replaced the single active-prompt cursor with explicit per-prompt leases owned by a session and prompt. Requests receive unique identities and synchronous, shared call/CNY reservations before transport. Parallel prompts within one process share the same ceiling; there is no cross-process ledger or lock.
- Kept actual serialized request-byte measurement and the strict output/call caps. No fixed input-byte ceiling was added. Unknown or unreported requests retain their full worst-case commitment, including after a failed prompt. Duplicate request identities and ambiguous ownership stop the campaign.
- Added request-level settlement for a complete reported provider response. The provisional worst-case reservation is replaced with a conservative bound computed from reported input/cache/output tokens and configured maximum rates before another tool-loop request may start. A reported length stop may settle its known usage while the prompt still fails. Missing, partial, conflicting, or synthetic zero usage does not release budget.
- The snapshot separates historical gross reservations, conservatively settled charges, in-flight reservations, unknown held reservations, and their committed sum. These are planning bounds, not a provider invoice or an actual amount paid. Previous campaign records are not retrospectively recalculated.
- Expanded offline tests for interleaved branches, shared ceilings, per-prompt caps, failure retention, per-request usage reconciliation, replay and duplicate rejection, terminal-event ordering, length outcomes, and dispose/resume continuation. No paid or network model calls were made.
- An optional cache-read ceiling now distinguishes reported cache hits from uncached input and cache writes during known-response settlement. It defaults to the uncached input ceiling for old campaign limits. Admission still reserves every input byte at the uncached rate; unknown cache usage stays at that full reservation. Model price verification checks the cache-read rate against the configured ceiling before any request. This is a planning bound using reported usage and configured rate ceilings, not an invoice.
