# Capability-driven execution and feedback recovery

This batch keeps the original objective contract immutable and makes objective reassessment independent of task-specific source names or evaluator IDs. The core accepts opaque adapter IDs and caller-owned evidence requirements. Unsupported or blocked proposals are retained and reconsidered against available capabilities in the same session before an incomplete terminal result. A synthetic unrelated evaluator demonstrates reuse without changing the core.

The private CPU task adapter now accepts model-authored registered experiment plans and exposes observed machine and verifier limits. The model continues to own scientific strategies, candidate source, cases and next-task proposals. Source and experiment inputs are frozen through host measurement and finalization. The same actor must read current host results, including missing-source and failed-compilation feedback, before ordinary review. Diagnostic, measured-scope, cold/startup and uncertainty fields are task feedback rather than adopted scientific conclusions.

Historical accepted source, verification, plans, knowledge and unresolved work are restored only with immutable original-source and contract bindings. No historical knowledge is silently imported into a fresh store. New candidates are compared using fresh same-host measurements; incompatible or unavailable comparisons cannot justify replacing a historical selection. Unselected observations and earlier selected tuples remain separate research history. Assessment receipts and prior task history survive normal continuation and interrupted branches.

Shared-ledger finalization uses authenticated encrypted carry with the complete request audit, including zero-call exits after ledger admission. Research archive collection failures preserve the prior coherent tuple without dropping the new accounting. Resource or verifier limits remain explicit incomplete boundaries, never proof of global optimality or objective completion.

Offline coverage includes generic-adapter dispatch, same-session capability replanning, complete evidence consumption after failed execution, frozen experiment-input mutation rejection, continuation identity checks, coherent historical tuple retention and large non-truncated read-only machine evidence. No provider calls, private task implementation or publication were performed for these engineering changes.
