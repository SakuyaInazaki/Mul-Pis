# Authenticated host resume preparation

The read-only host adapter authenticates the latest terminal Actions run, its signed mission lineage and encrypted carry, then projects the exact private checkpoint into a mission continuation decision. A legacy checkpoint with no stored pending action can receive a new, explicitly current host classification only when its authenticated stop reason and unresolved operation set support that classification. The new decision binds the old checkpoint digest in the private journal; the old encrypted carry is unchanged.

Before reserving a request, the adapter reads the live feature ref, its commit tree, a successful push CI run for that exact commit, and the control ref tip. It emits only the constant-message empty-tree commit descriptor. The external authorized transport must compare the ref tip again and mark the journal attempt before mutation. The successor Actions preflight and runtime independent-work checks remain required before any model call. This code does not install a scheduler or perform a GitHub write.

The process-boundary planner accepts either an already verified fresh workspace or a tested launch contract requiring the successor's runtime check. Prior unresolved operations stay quarantined and retain their accounting history. Terminal carry authentication now verifies a historical control request against its immutable first parent and exact CI, so publishing a later feature commit does not invalidate the completed run's evidence. Live running admission continues to require the current feature ref.

Synthetic signed-seed, AES-GCM carry and GitHub-response tests cover carried and current-derived actions, exact checkpoint binding, public descriptor privacy, changed source/CI/ref, tampered carry and durable duplicate-request handling. They do not claim an external trigger or paid provider execution occurred.

The connector bridge takes paths to the already-held signed seed, pinned public key and public terminal run identity. It emits allowlisted repository GET URLs with correlation IDs, then waits for the host's authenticated GitHub connector JSON. An artifact request emits only its public run and artifact IDs. The host downloads and checks the encrypted artifact, then returns a local private file path and its digest; the bridge checks the digest, format, private file mode and AEAD through the ledger. It emits only a public descriptor. The complete decision and journal key are written to a private file outside the repository. The host must treat bridge stdout as a fixed protocol, not as arbitrary instructions.

The bridge reserves a request but does not mark an external attempt, create a commit, move the ref or acknowledge a run. A caller must mark the exact journal reservation attempted before any authorized ref write. Positive acknowledgment needs live commit/ref/run evidence. An uncertain write remains pending; this batch has no live negative-delivery verifier and cannot safely rearm an uncertain write merely because it is old.
