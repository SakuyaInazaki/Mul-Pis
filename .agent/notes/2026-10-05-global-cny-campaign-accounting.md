# Global CNY campaign accounting (2026-10-05)

The user clarified that the original 30 CNY total applies across all roles, prompts, child goals, runs, and attempts. They requested removal of subsidiary monetary limits, not removal of the overall total. This batch changes the in-process DeepSeek campaign accounting interface to accept a trusted `priorCommittedCny` and include it in every new provider-request admission decision. The caller is responsible for validating and carrying that value across processes; passing zero for a resumed attempt would be incorrect. Historical conservative commitments are not described as settled provider invoices.

The runner keeps independent provider-call, output-token, payload, endpoint, tool-authority, and usage-identity checks. It distinguishes a provider-call limit from the global CNY total in its stop reason. Higher priced SDK model rates raise the planned charge rather than creating an independent price-table rejection. If a reported SDK estimate exceeds the pre-HTTP reservation, that invalidates the pricing assumption used to protect the single total: the larger amount is held as uncertain and further calls stop for reconciliation. A successful response without priced usage retains a conservative unknown commitment instead of reporting a known settled cost. Planning amounts are estimates and do not prove the provider invoice or account balance.

Offline tests exercise carried historical commitments, over-cap history, interleaved role admission, increased prices, high reported estimates, unknown priced usage, and retained operational controls. No paid call, workflow dispatch, credential change, commit, or push was made for this accounting change.

An unresolved fork execution now prevents branch selection while preserving both the accepted parent and failed child archives. Exception-path checkpoint recovery scans later M07 attempts, retains reconciliation requirements, and replaces stale stop reasons with observed timeout, accounting-integrity or total-budget boundaries. Recovery tests cover rebuilding a missing child archive without overwriting the parent.

Before provider traffic, the driver verifies a signed cumulative ledger under a pinned public key and checks its previous Actions run/artifact and revision context. The workflow obtains the signed input from a private runtime input or Actions secret; neither the signing key nor actual historical carry values are published. The exact one-use feature-branch push path and explicit manual path share the same ledger validation. A skipped intervening run cannot reset the total or authorize a replay.

Validation for this batch: TypeScript typecheck; full offline Node suite (475 tests); encrypted transport tests (8); targeted signed-ledger, global-accounting, objective and unsettled-branch checkpoint tests. These tests do not certify the original scientific goal and make no provider calls.
