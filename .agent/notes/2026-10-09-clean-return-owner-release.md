# Clean mission return owner handoff

An explicit CLI mission `run` or `resume` now releases its attempt after a normal, quiescent return. The host reserves and commits its existing one-use final intent and transport-only final receipt with the exact latest checkpoint bytes as carry. It requires no unresolved operation, pending M04 review, unrepresented mission-bound M07 work, current running mission stage, or knowledge merge lock. A failure to establish quiescence remains a typed hold, with the existing checkpoint unchanged. The released source cannot mutate or enter another assessor; a new process may claim the next attempt from the committed final even when a prior PID was reused.

The final receipt is transport evidence only. It does not mark the original objective fulfilled, select a candidate, or reconcile an old uncertain effect. Existing missions are not relabeled. An offline three-process CLI regression kept one mission ID across start, run, and resume with real Pi authentication unavailable; both returned runs stayed auth-held, no M07 dispatch occurred, and a fetch guard observed zero requests. Host tests also cover an unresolved operation that refuses release.
