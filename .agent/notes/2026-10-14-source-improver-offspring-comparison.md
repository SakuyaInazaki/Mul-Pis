# Source-backed I offspring comparison

This batch adds a fixed controller entry for an independent old-I versus candidate-I comparison. The candidate I must be a model-generated, engineering-passed private Git commit whose complete prepared source tree differs from the active source I only at `src/improvement/workflow-improver-program.ts`. The active H, I, knowledge pointer, and configured improver/research models are checked against one caller-frozen baseline before starting. A service-owned optional pre-operation gate can recheck active state and live references before each provider call, source proposal, development evaluation, and protected comparison.

The caller declares the number of independent search pairs, a protected case schedule, and a decision rule. Every pair starts from the same H source commit, knowledge snapshot, model configuration, and development evidence. Old and candidate I use separate loaded child processes and separate search state, with execution order alternating by pair index. Each search's full action, failure, session, usage, and selection records are copied into its run directory. A no-winner search deploys the unchanged common H source for that arm while retaining its no-winner result and search cost. An incomplete search blocks protected comparison. No protected case data reaches either I search. The protected evaluator is invoked only after all search selections have been frozen.

The protected callback reports real H offspring pairs using the existing source-arm receipt/outcome and parent-ledger shapes. The fixed controller checks each pair against the declared schedule and the exact H source selected by that I search, requires distinct child processes and workspaces, and retains partial pairs and provider costs on failure. Search provider cost, offspring execution provider cost, and separately reported protected evaluator provider cost are all labelled in the receipt; unobserved external resources and human work are outside that ledger. A caller-declared decider sees complete paired outcomes and costs. This comparison does not activate I or assert general scientific gain.

A receipt audit added byte copies of each selected H model-candidate receipt and same-search development evaluation receipt before protected evaluation; the controller rechecks the H model session, nonempty diff, common parent commit, and one-file source change. No-winner arms have no H candidate receipt and retain the common H. The protected callback now has a per-arm recording method, so an arm's receipt, parent ledger, and cost are saved as soon as that arm finishes. If the sibling arm fails or the callback aborts, the run remains inconclusive with the completed arm and its expense visible. The whole-pair method remains a convenience wrapper. Offline tests cover both a complete paired run and a deliberate failure after just one protected arm.

The frozen protected schedule validator now requires exactly two entries in each execution order, one `baseline` and one `candidate`. A malformed three-entry order is rejected before any run directory or protected data is opened.

An offline regression generates a real model-edited I private commit and H private commit, runs two independent pairs with four actual loaded I child processes, observes different action sequences and a no-winner branch, verifies all selections are present before protected evaluation, and checks cost and offspring source binding. Typecheck and the focused candidate/search/meta tests passed. No real model, network, production workspace, knowledge merge, or engineering commit/push was used.
