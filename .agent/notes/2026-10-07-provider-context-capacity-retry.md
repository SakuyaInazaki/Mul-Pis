# Provider context capacity retry

The DeepSeek transport now recognizes only a complete, arithmetic-consistent provider HTTP 400 context overflow sentence. It retains five numeric capacity facts and a static reason class; the provider request identifier and message text do not enter the accounting carry or public output. The credential-redacted full provider message remains only in the encrypted private result.

For an identical serialized request body, the runner can retry the rejected transport with `max_tokens` equal to the provider-reported context window minus its reported message tokens. No estimate or fixed reserve margin chooses this number. The initial response remains an UNKNOWN invoice observation even though HTTP 400 returned, and each retry is a separately reserved HTTP transport linked to its predecessor. The successful assistant response is paired only with the transport that produced it. If the response cannot be proved to describe that exact body, the model context no longer has positive output space, the model capacity profile changed, or the corrected payload fails validation, the runner keeps the error and its accounting evidence for the workflow's fresh-context continuation.

The encrypted v3 request audit retains the rejected response, its numeric physical-capacity proof, the retry link and both output caps. Optional transport diagnostics retain the static failure class; prior observations and unpriced usage stay intact. Offline tests use a real Pi stream with a fake provider response, plus accounting and carry regressions. No live model request was made by this repair.
