# Trusted workflow source confirmation and launch binding

Added an explicit protected source-confirmation path after a real source-I development search. The caller fixes the two prepared source commits, completed formal M04 baseline, private admission case set, even AB/BA repetitions, candidate selection and decision-rule declaration before private cases open. The controller checks the selected model-generated candidate against the source-I search's frozen selection, completed development evaluation, committed source receipt, parent commit and narrow first H allowlist. Each fresh source arm records its own complete or failed receipt and the parent's before/after provider ledger. Failures and unknown usage remain in the denominator. The parent evaluates actual M07 report delivery, M04 source reading, knowledge transaction and private semantic truth after the M04 turn; only a complete, supported run can be read for source adoption.

GenerationStore now has distinct human-source seed, isolated-arm copy and confirmed-source adoption paths. The normal activation API still rejects source bundles. The service adopts under its existing mutation lock, rechecks live K and necessary references, verifies the frozen run and active-pointer compare-and-swap, then changes H while retaining I, K, model and protocol. Rollback changes only the active pointer. A separate source-preserving transition lets the pre-existing M04-backed knowledge epoch/dependency paths continue without changing source H/I bytes. The `@active` launcher rechecks current K, necessary references and prepared H/I bindings before returning the source for a new process. V2 method export/import explicitly rejects source methods and source bundles; they remain prompt-data transfer APIs.

V2 case input copying now uses only that case's explicitly required evidence rather than the whole raw tree. Parent evaluation binds every required file through the live task input copy and reviewed artifact, compares live and checkpoint report bytes, and requires the same report to have reached M04. The provider ledger covers M07/M04 execution only; any external trusted semantic checker has its own caller-owned costs. No production workspaces or model sessions were run.

Offline fake-session tests cover real source-I search selection, two H source confirmations and adoptions on the same K/I, development-only and partial-run rejection, source mismatch, stale-pointer rejection, active-source launch and rollback, alongside the earlier v1/v2 source-arm checks. Directed source candidate/search/arm tests and typecheck passed. These fixtures demonstrate control wiring, not a scientific gain or real-model admission.

Added a separate I offspring adoption gate. The service registers each comparison under its private improvement store and rechecks the frozen active pointer, K and necessary references before I operations. Its reader validates the stored old/new searches and copied selections, candidate-I source lineage and module-only change, all declared protected pairs, real arm source identities, complete provider and reported protected-evaluator usage, and the predeclared trusted decision. An accepted run creates an I-only successor bundle; H/K/model/protocol stay frozen. The offline integration fixture executes the old and new I programs and fresh M07→M04 offspring arms, then checks I-only activation, partial/forged/unmetered/stale-run rejection, later I process binding, and rollback. Fixture decisions remain engineering examples rather than measured scientific gains.

Corrected failed workflow provider-turn accounting. The metered runner now takes only the current turn's new usage events, preserves numerically observed provider responses even when the prompt rejects, and marks the unconfirmed tail unknown. The source-arm child sends this partial summary with `prompt-failed`; the parent settles the same values in its own budget and reconciles them against the arm receipt. A crash with no returned usage remains unknown. Offline tests cover a prior successful turn followed by a partially observed failed tool turn, and a failed child arm whose observed tokens and estimated cost remain in the parent ledger. Typecheck and directed workflow budget/source-arm tests passed; no live model or workspace was used.

The I meta adoption reader also now requires the runner's frozen selected-H candidate and development-evaluation receipt copies, with their source lineage, engineering status and selected evaluation matching the search result. It rechecks each protected arm's outcome cost against its receipt and the corresponding parent-ledger delta. Tampering with either copied receipt or a protected parent ledger is rejected by the offline adoption fixture.

Read-only review of the real calibration and development drivers found that the development search had been handed an AbortSignal whose controller was not retained. The private development driver now owns that controller, maps SIGINT/SIGTERM to cancellation, records the active operation and interruption request, stops at the next parent-owned prompt/arm boundary, and writes an interrupted terminal result after control returns. The source arm has no cancellation input, so an already issued provider request is not represented as aborted; observed usage and any unknown tail are retained. Static syntax and seven offline development usage/preference tests passed. The running calibration, prepared source baseline, and live workspace were not changed.
