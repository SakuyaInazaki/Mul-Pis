# Returned task host recovery and empty auxiliary evidence

This change admits an empty regular auxiliary output as a byte-exact M07 candidate while retaining a nonempty task report and ordinary source, link, path, size, and digest checks. Diagnostic errors identify the file role and structural reason without printing file contents. The receipt, selected review, checkpoint, and reviewed host recovery verify a zero-byte candidate by its empty digest. An assessor can count a successful, exact-path, untruncated empty read as complete only while the frozen file still has the verified zero-byte digest; it cannot cite a nonexistent text line.

A dead-owner recovery may finish the host evaluator stage for one already returned, lineage-bound M07 task when no evaluator journal exists. The recovery claim, saved mission assessment, original assessor session and read boundary, source-to-frozen-copy equality, returned task inputs and copies, current evaluator identity, and capability snapshot are checked before the host stage. Existing pre-entry snapshots must be an exact prefix of current candidate sources. An uncopied source must predate the returned-task boundary. Extra or unsafe observation files, unknown effects, source drift, and malformed snapshots remain held. The recovery path does not delegate another M07 task, ask the assessor again, or select scientific artifacts on its own.

Synthetic regressions cover a returned task with one 0600 empty compile log, absent journal and partial snapshot; restart without builder or assessor replay; empty report rejection; zero-byte selection/read integrity; changed or symlinked orphan snapshots; changed uncopied source; changed assessor evidence; and unknown host effects. No private data, evaluator plugin code, provider calls, or remote publication are in this change.
