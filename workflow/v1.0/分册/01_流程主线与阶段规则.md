# 一、范围、版本与最终采用原则

## 1. 这份汇编是什么

本文件汇总本次逐环节讨论中已经接受的科研执行流程，以及图式认识管理两轮复核和最终定稿时补充的规则。它面向一个已经决定要研究的问题，覆盖独立认识、候选判据、外部质询、知识处理、资料获取与阅读、目标式研究、成果审查和交付收口。

这不是竞赛日志的原样复述，也不是从 RSI 论文移植的框架。原始操作、讨论中提出的优化和最终约定保持区分：正文采用最终约定；被撤回或替代的旧建议列在附录，不再作为当前要求。

当前科研执行层的主线已经有结束位置。成果解释、复现交付与阶段收口之后，没有另外新增的必经执行环节。方向层的选题、长期研究组合，以及 RSI 的工作流自我改进，不属于本版；不能在收口后自动接上它们。

**本版定下的是流程和管理设计，不是已经实现并通过测试的图管理软件，也不是跨所有科学问题的有效性保证。** 本次汇编复核检查了已确认决定的覆盖、接口、冲突和旧建议是否混入；软件运行、并发、故障恢复、权限隔离与真实科研效果仍须在实际实现和使用时验证。

## 2. 为什么不是一条只执行一次的流水线

九个模块构成主线，但 M02 候选判据、M03 质询、M04 后处理、M05/M06 资料处理都可以按需要重新调用。重新调用首先检查已有内容是否仍适用，优先增量修改，不另外生成一套平行认识或判据。

候选判据可承担一次研究活动的前处理功能，但不等于全部前处理。纠错与知识记录承担后处理功能，但不是单纯写总结。中间必须有实际工作、核验与反馈，不能从“提出检查办法”直接跳到“结果已验证”。

前后关系相对于当前活动：外部材料阅读之后更新判据，既是对阅读结果的处理，也是在为后续推导、计算或实验准备检查办法。第二次判据调用的触发点是实际读到了足以影响判断的内容，不是仅仅下载了论文。

## 3. 不变的工作原则

- 先让 Agent 面对原始问题独立形成认识，再引入外部分析；零上下文指没有对本问题的先前解读，不是清空模型已有知识。
- 一项目标一次委托；主 Agent 负责思考、方案形成、编排、普通故障处理和验收，不将全部技术管理转回给用户。
- 研究方法、模型和假设允许在证据作用下修订；原始目标、明确约束和授权不得悄悄改变。
- 认识、候选判据、外部评价和文献内容都不是自动正确。依据、条件、实际核查范围和未决问题必须保留。
- 实际执行事实、对事实的解释、采用解释的决定分开记录；多 Agent 一致不是独立科学证据。
- 猜想、失败和未决可以保存并用于有标记的探索，不强迫每轮产生肯定结果或通用经验。
- 主 Agent 验收实际产物，不以 completed 通知、文件数量或“已验证”措辞代替检查。
- 文档和规则按职责分层、按任务读取；不把整套手册塞进每条提示词，不用流程维护替代研究。

## 4. 名称和编号

M01—M09 是本次汇编的导航编号，不新增阶段。P 开头是对应可复制提示词。C/K/E/J/Q/D/X 是已定图式记录类型；G 表示知识库发布版本，N 指行为记录，S 指外部来源。

本版沿用 `.agent/notes/` 这一目录名。已有项目使用 `/note` 或其他同职责目录时，可以建立明确映射，不要求为了名字大规模迁移。路径示例表示职责，不表示这些文件已经在用户项目里存在。

# 二、流程总览、重复调用与职责分工

## 1. 九个功能模块

| 模块 | 核心问题 | 主要交付 | 下一步 |
|---|---|---|---|
| M01 独立初始认识 | 只面对问题本身，我如何理解它？ | 连贯解释、关键关系、假设与不确定性 | M02 |
| M02 候选判据准备与修订 | 怎样发现错误，检查依据和条件是什么？ | 五类候选检查及限制；后续为增量修订 | M03 或本轮实际工作 |
| M03 外部 AI 质询与回答评价 | 初始认识与判据有没有具体混淆、遗漏或无依据推断？ | 问题、完整回答、外部评价和待补证项 | M04 |
| M04 纠错、知识记录与状态更新 | 应改什么、保留什么、暂停什么，后续用什么？ | 有依据的处理决定、相关知识与判据变更 | 当前下一项任务 |
| M05 外部知识获取 | 还需要哪些材料，在哪里，实际取得了什么？ | 检索记录、来源登记、材料与获取缺口 | M06 |
| M06 阅读、提炼、核对与适用性判断 | 材料实际说了什么，对本问题怎样适用？ | 忠实阅读记录、关键核对、项目对照与修改建议 | 按需 M02/M03，再 M04 |
| M07 研究方案与目标式执行 | 当前目标怎样推进，实际获得了什么？ | 推导、构造、代码、数据或实验成果及必要核验 | M04；阶段成熟后 M08 |
| M08 成果级综合核验与外部审查 | 仍在回答原问题吗？完整论证和证据是否支持主要结论？ | 目标—成果对应、结论—依据对应、审查意见与覆盖范围 | M04；必要时返工，随后 M09 |
| M09 成果解释、复现交付与阶段收口 | 怎样理解、核查、继续使用，并结束本轮？ | 对应版本的说明、必要材料、实际复核和恢复入口 | 结束本轮，或由用户指定下一目标 |

常用主线：

M01 → M02（首次）→ M03 → M04 → M05 → M06
→ M02（受影响部分）→ 必要核查/针对性质询 → M04
→ M07〔方案、执行、检查、反馈、按需 M04〕
→ M08 → M04 与影响范围内复审 → M09。

这不是要求每一步每次都全量执行。已有材料或检查能够覆盖当前需要时直接复用；与本问题无关的类别说明后跳过。资料处理不应阻塞所有不受缺口影响的探索，也不要求每读一篇材料就启动全套外审。

## 2. 前处理、核验、后处理的接口

| 部分 | 输入 | 工作 | 输出 |
|---|---|---|---|
| 前处理中的判据准备 | 当前目标、认识、证据和条件 | 建立/复查检查对象与办法；未成熟判据不当硬标准 | 本轮适用的候选检查及待补证项 |
| 实际工作与核验 | 当前目标和允许使用的知识 | 读、推、算、试；实际检查并分析反馈 | 可定位的真实产物、检查结果与问题 |
| 后处理 | 实际产物、依据、意见及原状态 | 处理差异、提出修订、核对影响、更新可用状态 | 后续能够正确调用的认识、限制、未决和产物关系 |

后处理不要求每次都改内容。发现没有必要变化，可以保留原状态并记录实际检查。明确错误应及时限制使用，不能因为“后处理在最后”而继续传播。

## 3. 角色分工

用户决定研究目标、实质性范围变化、重大授权与是否进入下一目标；组织跨网页版 AI 的材料转交和关键取舍。用户不需要预先知道正确模型、全部专业检索词或检查题。

主 Agent 负责恢复相关状态、形成方案、拆分任务、安排子 Agent、核对实际结果、处理一般错误、维护资料与知识记录、给出少量有依据的待决事项。

子 Agent 执行边界明确的阅读、推导、实现、运行或核对任务，只写授权位置。首轮材料阅读保持约定的信息隔离；图管理的公共变更通过统一合入入口。

外部 AI 负责针对指定材料出题或评价，检查自己的预设和质疑，给出位置、理由、影响及最小补证办法。外部 AI 不是天然正确的裁判，也不默认没有工具能力。

运行工具和检查程序提供实际证据；提示词、文件夹、图或一个角色名称本身，不构成技术权限、隔离或科学正确性保证。

# 三、M01：独立初始认识

## 目的与来源

这个环节保留用户的真实意图：在没有对该问题的既有解读和外部分析输入时，让执行 Agent 依据问题本身、必要原始信息、已有知识和自身推理形成自己的认识。

原始操作是“描述背后的物理过程，从头讲理解，不复述题面，单列不确定和题目没说明的部分”。泛化后将“物理过程”扩展为问题对象、概念和关键关系，不引入一长串无关学科或任务名称。

原样导出 Markdown 只是方便复制与转交，不给该动作追加审计冻结、历史认证等原本没有的目的。后续正式知识修订另按图式管理处理。

## 输入边界

只给原始研究问题和理解它必需的原始信息。不给其他 AI 的解释、相关论文的解题分析、旧项目的具体认识、历史纠错结论或预设路线。不在本轮联网补证或开展文献检索。

“新会话”不能仅凭名称被认定为独立。实际输入入口、检索范围、附加说明和自动加载内容都应遵守边界；若无法保证，要如实说明，而不是先输入外部分析再要求“忽略前文”。规范性工作规则可以存在，但不得夹带本问题的预设解释。

## 应做的工作

形成连贯解释，说明研究的真正问题、核心对象及定义、关键关系如何连接到目标，以及为什么这样理解。关键处可以用公式和局部推理说明，不只报方法名。

区分题目明确给出、已有知识、本轮推理、自行添加假设与猜想。单列无法解释、不确定或原始信息缺失的地方；不为追求自洽填补未知。

允许为表达理解作必要推理；不默认写程序、跑实验、决定正式解法或展开完整求解。自然出现的思路可以标为候选，不自动实施。

## 输出与结束

一份可直接阅读的初始认识，加上关键假设和未决项。需要复制时原样导出，不重新润色成另一个答案。不要求证据编号、复杂评分表、完整材料审计或整套验证方案。

完成标准是“初始认识已经具体到可以追问”，不是“已经完全理解正确”。结束后进入独立的 M02，不再把两轮合成巨型提示词。

对应提示词：P01；可选传递操作：P01E。

# 四、M02：候选判据准备与修订

## 目的与两次基本调用

候选判据回答“在没有完整答案时，可以怎样发现错误”。它不是目标定义、文献搜集、实际验证或最终正确性证明。

首次输入为原始问题、必要原始信息和初始认识，不为补齐判据自动启动外部检索。第二次及以后使用当前相关认识、已有判据、实际读到的外部材料与新反馈，优先增量修改。

知识获取产生线索，不自动触发整套重做；真正读到影响定义、条件、依据或比较方式的内容时，才重开受影响条目。没有变化时保留原判据；后续执行范围或关键机制改变时也可局部调用。

## 五类检查

| 类别 | 内容 | 边界 |
|---|---|---|
| 定义、类型、量纲与单位 | 输入输出定义、数学对象类型、表达式合法性、单位转换、归一化和统计口径 | 非物理对象不强行编单位；不把同名符号当同一量 |
| 有依据的必要约束 | 正负、范围、整数性、恒等式、不等关系、对称性、不变性、守恒、单调性 | 守恒写对象及系统边界；单调性写固定与变化条件；不作无依据的无条件断言 |
| 特例、退化与极限 | 可手算或用简单办法核对的情形及必要推导 | 取零、取无穷、对称等操作须合法；不强制凑两个；特例不能证明全称结论 |
| 适用边界与区分检查 | 当前解释/方法的条件、失效范围、竞争解释怎样区分 | 不强迫编造方向反转；误用也可能算得正常却含义错误 |
| 数量级、标度、上下界与参考范围 | 有依据的估计、标度或界限及推导 | 区分严格界、条件界、近似估计和文献报道；不把报道最小最大值当参数合法区间 |

每条至少有：对象、具体检查、依据、成立条件、检查办法、满足或违反分别说明什么，以及不能说明什么。必要约束、条件性约束、诊断性预期分开；不适用或不确定明确写出，不以条数、置信百分比或精确小数填补依据。

## 准备、采用与实际检查分开

初始认识也可能有错，判据不能只为维护它而设计。局部推导或最小算例可用于澄清依据，不能冒充完整验证。未执行的检查不标通过；只有求解后才知道的量不伪装成先验标准。

判据是否用于正式验收，按当前授权、依据和图式状态处理；工作假设可以支持探索，但不得静默提升成正式结论的硬依据。检查失败既可能涉及研究产物，也可能涉及判据、测试实现或配置，必须定位。

## 修订纪律

修改原 K 条目并保留版本、修改理由和影响，不另建独立“文献版判据”。看到结果后新增或改判据，应记录实际时机与原因；有依据可修，不能为了让现有结果过关而放宽。原始结果和旧评价保留，受影响结果按新版本重评，不将两种标准下的成绩混为一谈。

完成标准是相关候选检查足以供后续审查或执行，并明确剩余缺口。不是所有判据已经正确，也不是整个问题已解决。

对应提示词：P02；后续增量调用：P02U。

# 五、M03：外部 AI 质询与回答评价

## 用户原有的协作链，保持不变

主 Agent 形成认识 → 用户把材料交给网页版 AI → 网页版 AI 按四类框架生成具体题目 → 用户转发题目给执行 Agent → 将完整回答送回网页版 AI 评价 → 用户把意见交回执行 Agent → M04 处理。

专业题目由网页版 AI 生成，不将其写成用户亲自独立设计的专业质询。用户转交材料、问题或答案的身份，与原始提出者的身份分开。导出文件服务于复制传递，不额外建立仪式性审计程序。

## 输入与信息分离

外部 AI 接收原问题、必要原始信息、初始认识和候选判据。后续局部质询可以提供相关新材料及明确范围。认识和判据是待审对象，不是参考答案。

可转发问题与出题说明/判断依据分开。只转发问题，不泄露“此处故意设错”及预期答案。多家 AI 首轮根据同一材料独立出题或评价，不先互相借结论；不固定必须三家，也不凭换模型就断言完全独立。

## 四类测试的最终要求

| 测试 | 保留的作用 | 修订后的出题与判分 |
|---|---|---|
| 错误前提 | 检查是否不加判断地接受听起来合理的断言 | 出题者要能说明确实错在哪里；混合正确、错误、条件不足前提；不强迫每题反驳 |
| 变化预测 | 检查能否由结构预判输入改变的后果 | 明确固定条件；允许方向确定、条件内不反转、现有信息不足三类有理由回答；不能将谨慎本身判错 |
| 相似问题区分 | 检查能否辨认模型/问题的实质差别 | 要指出判别依据和误用后果；不预设一定程序报错或数值崩溃 |
| 失效边界 | 检查具体认识依赖哪些条件 | 对应具体主张，不凑固定数量；区分原条件内错误与换条件后的不适用；未知替代方法就保留未知 |

出题针对影响当前理解的关键说法，不生成通用大题库。需要查原文才能裁定的陷阱不能装成确定答案。任何题目自身都允许被回答者纠正。

## 评价与追加问题

逐题引用实际回答，给出问题位置、判断依据及对认识/判据的影响。区分成立、缺条件或论证、明确错误、题目错误和无法裁定；遗漏不等于说错，要看是否影响当前目标。

不按态度、自信、反驳次数、对评审的服从程度或多模型多数票评价。评审须复查自己的预设。需要追问时给可转发的具体问题，已充分回答的不反复换措辞重问。

外部 AI 如使用工具，应说明实际读取、推导或计算；没有执行不能说完成。网页工具能力、文件数量限制按当时实际情况，不固定成竞赛时条件。

结束标准是主要质疑得到有理由的回应，明确错误已被识别，未决争议具体化。不是逼到所有 AI 意见一致，也不是提前宣布主 Agent 完全懂了。

对应提示词：P03Q（出题）、P03A（评价）。作答时转发生成的问题即可，不新增必需答题管理提示词。

# 六、M04：纠错、知识记录与状态更新

## 处理对象

本模块是可复用后处理：接收外部意见、实际研究结果、阅读发现、检查异常或重要阶段变化，决定保留、限定、修订、暂停或继续探索什么。它既处理错误，也记录新支持、候选假说与无变化的结果；不强制每轮提炼一种通用经验。

先对照原问题、实际回答、原判据和意见原文。相同意见可以合并，但保留来源。检查题植入的前提只有在执行 Agent 实际接受或使用过时，才能记为它的错误。没有实际原文不制造“当时原话”；无法判断内部错误原因时不猜模型内部机制。

## 四种主要处理

| 处理 | 要求 | 结果 |
|---|---|---|
| 接受纠正 | 原主张有明确问题，更正有对应依据 | 更新相关认识、判据与依赖；保留原说法与理由 |
| 部分接受/补条件 | 原结论未必全错，但范围过宽、定义含混或论证不足 | 限定成立范围，补充必要条件与解释 |
| 不采纳 | 对方误读、改变了条件或理由不成立 | 记录具体理由；不因拒绝意见就将原结论视为已证明 |
| 待补证 | 现有材料不能裁定，或需要额外推导、材料、数据/实验 | 保留分歧和影响范围，提出最小补证动作 |

原论证被驳倒不等于替代结论已成立；原依据失效不等于结论必然相反。可以撤回原来的确定性，同时对替代解释保留未知。

## 核查范围

先使用已有原始材料、完整问答、外部评价及必要局部推导。仅在评审中出现但没有取得的文献引用，标明尚未核对，不能升级成原文事实。需要大实验或新资料则转回 M05/M06 或 M07 的针对性任务，不强迫当轮全部消解。

对影响关键关系的纠正，重新解释出错那段推理为什么改变。不是仅写“接受第几条”，也不要求每条小修正都新建测试代码。

## 后续记录与同步

按照图式管理基线，认识/判据/依据/论证/质疑/决定/情境分别记录。当前认识和重要纠错的连贯说明从这些记录生成，未决项独立可见。

`.agent/notes/` 保持全项目行为记录：记本轮读取了什么、实际做了什么、产生或修改了什么以及理由所在。详细科学论证、意见处理和采用决定指向图式记录，不在 notes 再维护一套平行事实。

修订应检查受影响的判据与下游成果：不能只在纠错视图中承认条件遗漏，却让 K 继续无条件使用。未经本轮检查的内容不自动升级为已确认。旧纠正也可以被新证据修订，不成为永久禁令。

明确失效的核心依据及时限制使用；后续昂贵复核可稍后完成，但不得让限制在发布失败或回滚后消失。详细协议见第七章。

## 完成与边界

本轮结束时应能回答：改了什么、为什么；哪些未采纳；哪些仍待补证；哪些旧认识不能再直接用；哪些依赖须重审。没有知识变化也可完成，不能用“所有意见已采纳”或“现在完全正确”作为完成标准。

本模块不允许普通任务自行修改研究总目标、权限或整套流程；不把单次项目纠正自动提升成跨项目的工作规则。核心变更按既定授权处理，未受影响的工作可以继续。

对应提示词：P04。图式管理是它的底层规范，不是用户每次另行执行的一个阶段。

<a id="m05"></a>
# 九、M05：外部知识获取

## 目标与输入

弥补原实践由队友搜集论文的工作。围绕原始问题和当前缺口发现、筛选、取得值得进一步阅读的外部材料，而不是给已有解释找背书。它不只服务于候选判据，也提供定义、理论、竞争解释、方法、数据及已知障碍。

输入包括原问题、当前认识、候选判据、未决质疑和已有资料索引。主 Agent 自行形成知识需求和检索词，不要求用户先知道全部专业答案。不能只读图里的已知缺口，还要回看原问题以发现尚未意识到的遗漏。

## 第一步：先判断缺口的类型

定义/出处缺口可检索；未知命题可查已有证明、反例与引理，但没找到现成答案不表示问题无解；当前对象的实际测量不能以其他对象数据替代；原问题中的实质选择不能由文献搜索偷偷决定。

因此检索可为推导、实验、测量和选择提供方法与信息，但不承诺代替它们。找到相关材料后仍缺新证明或数据，应明确交接剩余任务，而非无限换词寻找一个看似答案的段落。

## 第二步：有限概览＋定点查证

有限概览从原对象、问题和不同表述出发，了解必要概念、主要处理路线和限制；不将主 Agent 首选模型名称设为唯一入口，不扩成全学科综述。

定点检索围绕某个待判断关系的定义、出处、条件、不同结果和限制，而不是“找论文证明我们正确”。不强行配一篇支持一篇反对，但不得因结论不合意排除。

检索根据实际读到的术语、同义词、缩写和引用链迭代。可追查基础工作及后续修订或质疑；不把初始未经确认假设变成硬筛选条件。已有已知相关材料可检查当前策略能否找回，但找回不等于搜全。

## 第三步：必要初筛阅读、获取与登记

允许读摘要、目录、相关段落、图表和方法说明，判断相关性、术语和完整性；不按固定页数划界。明显不相关可排除；信息不足但可能关键的保留待读，不因摘要未写某项内容就认定全文没有。

搜集对象不限论文。按知识需求选择教材、专著、综述、原始研究、数据说明、代码文档等；综述帮助定位，具体主张尽量回到相应原始出处。相关性与材料状况分开，不以最新、高引用、免费、同行评审任何一项独立决定采用。

核对标题与实际文件是否对应、版本与附件是否取得、全文是否缺页、是否有可取得的更正或撤回线索。未发现更正不证明无问题，下载成功不表示内容齐全。关键全文取不到，寻找合法可用版本，仍不足就保留限制，不以无关易下载材料替代。

本轮已确实读到的具体定义或线索可以准确记录，不为阶段分离故意丢弃；但不自动完成整批精读、复现和项目适用性裁定。

## 第四步：检查覆盖并交接

按知识需求对应实际材料，说明阅读优先级及理由。找到来源只关联候选参考，不自动关闭 Q，不把 C/K 升级为确认。需要阅读和论证后才能按 M04 更新。

本轮有三种合法结束状态：材料足够进入阅读；关键缺口在本次范围内未解决并有续查/推导/测量建议；达到资源边界并明确尚未覆盖部分。没有固定篇数，不以重复命中几次就宣称搜全。

记录实际来源、关键检索式、日期、限制、代表性筛选理由、结果查看范围和中断。当前没找到不等于学界没有，权限内没取得不等于文献不存在。复用已有有效材料，后续出现新条件再定点重开。

主 Agent 维护 references 和 notes；只将正式纳入且影响研究的条目按需与图关联，不把每个搜索命中构图。发现有明确依据的重大更正线索，立即触发相应处理，不因未到精读阶段忽略。

对应提示词：P05；资料区初始化为可选准备操作 P00R，不是新科学环节。

<a id="m06"></a>
# 十、M06：阅读、提炼、核对与适用性判断

## 目的与顺序

把“已取得材料”转化为“准确理解材料本身，并有依据地知道与本项目如何相连”。保留先忠实读材料、再判断项目适用性的分工。获取阶段已有准确内容复用，不重复为生成文件而加工。

内部三项工作：材料本身的阅读提炼；准备依赖内容的关键核对；主 Agent 的项目对照与综合。它们由一次委托内部组织，不需要用户逐个管理阅读者。

## 1. 首轮独立阅读

主 Agent 知道项目目标并选择本轮材料；首轮阅读者取得指定版本原始材料、来源身份和统一阅读要求，不取得项目期待结论、主方案辩护、其他 AI 的评价或其他文献的判断。检索记录/来源说明若含预期结论，不直接全量传入首轮阅读。

按材料隔离清晰的首轮任务，不固定整个项目的 Agent 数量。已有筛选记录若仅含客观原文内容可复用；含项目判读的内容不能作为独立阅读者的预设答案。独立性依据实际输入，而非仅依据新建了一个 Agent。

读懂作者研究什么、核心思路、关键论证如何连接。提取具体定义、命题、公式、方法、数据或结果，保留原文位置、成立条件、论据和局限。必要时沿材料内部引用补读上下文；缺外部内容登记，不补造。

不再强制跳过摘要和引言，不限定只读公式前后段落；也不要求每份资料无差别通读到底。不强制对没有公式或单位的资料凑字段。

阅读记录包含问题与主要思路、可引用内容、依据条件、限制疑点和实际读取范围。原文短引句、自己的转述、推导和猜测分开；未经证据不替作者修公式后仍称原文。没有缺项可诚实写无，不强迫每卡列问题。

## 2. 核对真正准备依赖的内容

按重要性和已发现疑点，优先回原材料核对关键命题、公式、参数、参照及适用条件；不把全部材料重新完整读一遍，也不要求用户预先列完拟用公式。

核对符号、下标、单位、版本、位置与原文支持范围；避免将条件性结果扩大为无条件，将有限算例写成一般性命题。卡片内部自洽不等于提取准确。

可以安排另一任务核查，主 Agent 验收；两个 Agent 都认可不代替实际原文核对。AI 核对只记具体核对事实，不伪称用户亲自验证；不沿用整篇统一 AGENT/LIT 升级为正确的简化标签。

## 3. 主 Agent 对照本问题

将阅读结果与原始问题、当前认识、判据和未决放在一起，比较对象、定义、条件、时间/空间/统计口径。明确哪些条件已满足、未知或不满足。

可得到：支持/补充当前认识；原认识需修订；新的候选解释/方法；只有类比启发；冲突或条件不足。每项定位到具体依据，不能因为来自论文就优先于实际证据，也不能只寻找支持旧认识的材料。

冲突先对齐定义和适用范围，再区分不重叠的伪冲突、同条件实质分歧和无法判断。不能悄悄平均或把不同报道的最小最大值直接变成合法参数区间。缺口按当前实际依赖分级，不把所有公式先当拟用从严审计。

假设补充需标明身份，不能用“已声明为假设”让原本不成立的正式断言自动过关。能支持条件性探索不等于支持原问题的无条件解答。

## 4. 接续已定模块

受新内容影响时调用 M02 增量修订原 K；关键提取疑点回原文核对，逻辑疑点用局部推导；重要认识变化或竞争解释才组织针对性 M03。不是每篇论文都重新跑全量四类题。

经必要核查进入 M04，处理采用、限定、暂停和未决，保存 J/E 与版本。references/reading 保存材料自身，knowledge 保存项目解释，notes 保存实际动作，不加平行总结库。

完成标准：准备支撑下一任务的关键材料，实际内容、条件、依据和适用关系明确；不能用的有限制，未决有具体补证需要。无需全部文献读完、全部未知解决，也不为了准备进入研究强行找到一个现成解法。

对应提示词：P06。

# 十二、M07：研究方案与目标式执行

## 交互方式

保留原来“一问完成再让它做下一问”的目标式委托。泛化为一个当前目标一次委托，主 Agent 内部形成方案、安排推导和实现、组织必要检查、处理一般故障并验收。用户不必逐条发送“现在验证、现在诊断、现在修复”。

执行不等于写代码。允许思考、局部构思、定理推导、构造反例、比较解释、设计区分实验和调整路线；工具和语言按实际约定，不把一次竞赛使用 MATLAB 固定成所有研究的要求。

## 内部四项工作

第一，接续相关当前状态。读取本目标需要的定义、认识、假设、判据、未决和已有结果，按局部知识包提供给子任务，不重新加载整个历史。明确本轮研究目标和与原问题的关系，而不是只有“写脚本”“跑实验”等动作。

第二，形成可开始的工作方案。说明路线的理由、关键条件、障碍和近期可检验动作。近期具体、远期可调整；不强制列三种方案或庞大任务树。实质分歧可先做最小区分推导/实验，不必完整实现每条路线。尚无清晰路线时可有边界地探索，不能把未证引理当已成立。

第三，复用 M02 检查本轮判据适用性并落实到对象、范围、配置与检查办法。分清已能做、结果产生后做、尚需设计/补证的检查；不凭空定阈值，不为了开工要求一切验证完备。实现类大量工作按约定派子 Agent，职责和写入范围明确。

第四，按真实结果调整并交付。普通实现问题自行闭环；发现结构不适配要检查模型与表示，不只是不断调系数或优化速度。需要资料、质询或知识纠正时局部返回，不从头重做全部前期流程。

## 工作纪律

原问题与明确约束要遵守；当前认识是可修订起点，不能以“已充分理解、严格遵循旧认识”阻止反证。允许方法改变，不允许无声更改目标、关键定义、正式重要假设、受保护验收或授权范围。

正式运行使用可定位的输入、代码和实际配置；输出在独立运行位置。共享模块按阶段由一个写入者负责，其他工作针对固定版本，避免验证追着不断覆盖的 latest 文件运行。重要参数是否实际生效要核对；接口不能表达的实验、被忽略配置和未执行检查要明确暴露。

检查失败不立即等同研究结论被否定；可能是配置、测试、数值近似、实现、模型或前提的问题。按证据定位，必要时给最小区分动作。判据需要改时保留理由与旧结果，不用放宽标准制造完成。结果、报告、图表和知识身份保持对应。

notes 随实际工作记录，关键知识在准备被后续依赖或阶段交接时按 M04 处理。避免每次操作先填表，也不把失败尝试都丢弃。

## 完成标准

交代实际成果、与本目标的对应、真实检查范围、未通过和未执行项、认识变化与限制、后续有依据的选择。完成可为完整结果、明确部分成果、反例、排除路线或需要授权的具体阻塞；状态必须准确。

不要未经授权开始下一研究目标，也不因没有立即解开困难问题而宣布不能研究。必要检查由主 Agent 内部承担；重要阶段完成后的 M08 是整体核验，不是用户在每个技术子任务后必须亲自组织的一套新仪式。

对应提示词：P07。

<a id="m08"></a>
# 十三、M08：成果级综合核验与外部审查

## 两条主线

第一，目标同一性：从原问题、实际明确澄清与变更记录，核查整个研究实际处理的对象、定义、范围、量词、输出和成功要求。保持问题而非初始解法，具体规则见第十一章。

第二，主要结论的完整论证与证据：逐项检查前提—J 论证—E 实际依据—结果解释—最终表述，不能用代码能跑、图连通、检查通过或形式化通过替代对原问题忠实性和适用性的核对。

## 还需覆盖的内容

各子任务定义与假设能否组合；目标与成果双向对应；关键论证是否省略；来源版本和适用前提；实测/仿真/证明不同性质的依据；备选解释、不确定性与未检查范围；代码、实际配置、数据处理、结果、图表及正文是否属于同一成果版本。

审查按是否影响结论选择内容，不按模块名称一律删除 IO、清洗或绘图代码。单位换算、筛选、插值、聚合、事件时间提取、误差条与图中数值可能是推理链的一部分；纯样式可以按需不纳入核心材料。

候选判据与验证脚本本身也受审。检查是否真正执行、条件是否合适、参照是否同源、跳过是否被误记通过。重要检查可在隔离副本用已知错误及正常对照测试，但只支持实际检查过的错误类型，不证明无漏检。

## 五步组织

1. 指定本轮目标、主要结论及实际版本。冻结审查对象的定义、数据、代码、配置、结果和评价条件；其他分支可继续，但新改动不得混入旧审查对象。
2. 主 Agent 整体自查。生成目标—成果对应和结论—论证—依据—未决视图，直接核对原始产物查图的遗漏；处理有依据的明确问题，不隐藏失败和限制以美化材料。
3. 准备可访问的审查材料与清单。包含原始目标与澄清、关键定义假设、主要推理、实际数据/配置/必要代码、结果、已执行检查和缺口。不能只有自我总结；本机路径不等于已交材料。敏感或不能分享的内容明确限制。
4. 外部 AI 从原问题自行理解目标，再对照实际研究与结论。多家首轮分别审同一版本，不固定数量，不把共享来源下的相互认可叫完全独立。按实际工具能力进行核查并如实报告。
5. 收回意见进入 M04，补资料/重算则局部返回。小修改局部复审，共享定义、核心假设、主要证据改变扩大复核。旧评审不能自动覆盖新版成果。

## 评审意见格式

准确位置及原说法/实际操作 → 问题与依据 → 影响目标与结论 → 最小补证或修正办法。问题成立程度和影响严重程度分开。区分明确错误、缺依据、条件不足、无法裁定和可选建议，不为显得严苛而凑问题。

评审要复查自己的前提，不能把与其预设不同判为错误。没有运行只作代码阅读就如实说明；提问“需更严谨”应定位缺失步骤，无法裁定给区分办法，不迫使执行 Agent 服从。

用户授权一个范围不等于为科学内容提供证明。正式目标改变需明确确认，原目标和未完成部分保留。

## 完成与收口

分别给目标回应程度、各主要结论支持范围、阻塞问题、可交付范围和审查覆盖。目标忠实且证据充分可按该范围交付；局部可靠结果可阶段交付；关键论证缺失仍待验证；实际答了别题则原目标未完成；反例按原问题的要求说明意义。

完成一次审查不等于完成科学问题。结束不以所有 AI 认可、所有 Q 关闭、总分或通过率为标准；核心主张有相应检查，问题有理由处理，未决限制进入表述与使用条件，才构成相应范围的审查完成。

对应提示词：P08M（主 Agent 核验与准备）、P08E（外部成果审查）；意见处理复用 P04。

# 十四、M09：成果解释、复现交付与阶段收口

## 目的

使成果可理解、可核查、可继续使用，并明确本轮结束位置。这是本版执行主线最后一个模块，不等于默认写论文或生成压缩包，也不自动公开、投稿、启动新目标或 RSI。

重要阶段也可调用解释与交接，不必等整项目结束。先查已有接收者和用途约定，只有实质不明确才询问；不因“流程完整”制造没人需要的交付包。

## 1. 明确交付对象、用途、范围和版本

接收者可以是用户、合作者、评审或后续 Agent。用于理解则突出主线及限制；用于继续工作则保留当前接口与未决；用于复算则提供确切配置、运行入口和比较方式；用于对外表达则根据实际要求提供支撑与来源，不擅自发送。

阶段交付可以是条件性证明、反例、可靠部分成果或带边界的观察。不能将允许交接等同于原问题全部解决。

## 2. 成果说明

讲清原问题、核心思路、关键步骤为何成立、实际结果、结果含义和仍未解决的部分。先连贯解释，再提供可追溯细节，不把日志或节点列表直接当成果说明，不只列方法名称。

重组叙述、统一已确认符号可以；新增关键推论、改变结论范围需要回 M04/M08。不得补造实验、伪造早期先见、隐藏影响结论的困难，或把有限检验写成普遍成立。清楚区分复现、已知结果应用、推广、改进、反例与新发现；声称新颖时按需定点查询相关工作，检索没发现不自动证明新颖。

帮助用户理解主张、依据、限制和反证条件，不把用户当考试对象。说明已提供、用户已读/理解、用户实际核验过哪些内容分别记录，不能擅自证明用户已经理解。AI 使用、署名和核验经历以真实过程为准。

## 3. 从指定版本组织材料

研究工作区可保留完整开发历史，本次交付按用途选必要内容，不维护第二套科学代码或平行知识库。清单说明版本、包含内容、用途、主结论和依据位置、未提供内容及原因。

必要依赖链为原始输入/取得方式—处理与配置—结果—表图与结论。不能只指向本机路径、变化中的 latest、未声明缓存或个人环境。完整历史可单独留存，不要求接收者接收无关材料，但关键限制、不利证据和依赖不能为精简删除。

排版、标题、导航变化通常核对表达和链接；路径、入口、依赖变化重跑相关交付检查；公式、数据处理、默认参数、模型或核心结论变化返回研究核验。不得把实质研究修改藏在“清理文件”里。

## 4. 复核实际交付内容

涉及计算，在独立临时副本或适当隔离环境按交付说明运行，不覆盖待交付材料。记录环境、输入、步骤、结果和比较办法；检查路径、依赖、运行顺序、配置是否真实生效以及是否需隐含缓存。

只从保存结果重画图，不能称完整复算；重跑数据分析不等于重做现实实验；另一个 Agent 同环境复算不能称独立团队重复实验。已有完全相同版本、环境和步骤的核验可复用，删减或迁移改变依赖则重查。

精确字节一致、数值误差内一致、随机结果统计相符是不同要求。比较方式要有依据，不在失败后临时放宽，不不断换种子挑最接近的一次。大规模计算资源不足时说明关键路径已跑和完整复算未跑，不假装独立复现完成。

理论成果提供定义、命题、完整论证及引用基础；形式工具实际构建与陈述忠实性分开。实验成果提供协议、条件、观测和分析记录，原始测量不可由重分析代替。

## 5. 明确状态、恢复入口和停止

分别报告研究状态与交付状态：原目标完成到哪里，哪些主张支持到什么范围；材料准备、验证、发送或发布实际到了哪一步。

留下当前目标、有效认识/版本、关键产物、未决与下一次恢复要核查什么。按约定安全处理实际运行任务；仍运行或不能中断的明确状态，不把它们写成已停止。

新方向可记录候选，不自动开始。准备好材料不等于获准公开、投稿或发送第三方。发现新撤回/版本问题按影响范围返回处理，不因旧清单已写好继续错误交付。

完成标准：成果可理解、内容可追溯、材料与用途相符、复核范围真实、版本/未决/恢复入口清楚。本輪完成后停止；新的研究目标由用户指定，未决事项不靠再接一个无限“优化阶段”消失。

对应提示词：P09。

# 十五、触发、返回、停止与完成判定

## 1. 不重跑全流程的返回规则

| 发生的情况 | 调用或处理 |
|---|---|
| 当前认识存在歧义、无依据断言或机制混淆 | M03 针对性质询，M04 处理；需要原文则 M05/M06 |
| 发现只有外部定义/出处/条件能处理的缺口 | M05 定点获取，M06 阅读适配 |
| 新材料改变了判据依据或成立条件 | M02 增量修订，必要核查后 M04；不建第二套 K |
| 资料卡内部自洽但关键提取未核对 | M06 回原文；不能直接当文献事实 |
| 普通代码/数值实现错误 | M07 内部定位、修复与相关回归 |
| 多次尝试只改症状，未取得相关新信息 | 在原目标内检查路线、表示与结构，必要外部质询；不自动改研究方向 |
| 关键认识已明确失效 | 立即登记并使影响范围限制生效，再完整修订/复核 |
| 核心定义、原目标或重大授权需要改变 | 给用户具体差异、影响与建议；不让其代替专业证据判断 |
| 外部评审有分歧 | 对齐对象、版本、条件和依据；M04 接受/限定/拒绝/待补证，不多数表决 |
| 包装时改路径或入口 | 在实际交付副本重查相关执行 |
| 包装时新增公式、处理规则或结论 | 返回 M04/M07/M08 受影响部分，不当作排版 |
| 资源耗尽、来源取不到或工具受限 | 保留已完成、未覆盖及实际限制；不把中断写成搜全/验证通过 |
| 阶段已完成或已有明确可交接结果 | M09 对应范围收口，不自动开始下个目标 |

## 2. 每种“完成”的区别

初始认识完成：把当前理解说具体，不是正确性已确认。

判据准备完成：候选检查与前提明确，不是检查已执行。

质询完成：问题得到理由回应且未决具体，不是所有评审一致。

知识更新完成：状态与影响已按规则发布，不是所有内容科学上已证实。

资料获取完成：实际材料/范围/缺口能交接，不是所有知识已掌握。

阅读处理完成：关键内容、核对与适配范围明确，不是整篇全对或一定能用。

目标执行完成：实际成果和目标关系清楚，不是代码数量达到计划。

成果审查完成：检查覆盖与结论支持范围明确，不是原科学问题必然完成。

交付收口完成：接收内容、复核与未决状态清楚，不是发表、公开或新目标已获授权。

## 3. 无统一量化分数的底线

不以文件数、节点数、问题数、论文数、迭代次数或 AI 意见数评价科学进展。记录真正改变的认识和证据、不受支持的部分、实际管理/运行成本。此处只说明执行质量如何观察，不启动 RSI 对工作流自身的自动优化。

# 十九、最终收口与阅读方式

本版科研执行主线的起点是“已经有一个准备研究的问题”，终点是“形成与目标对应、论证和证据边界明确、能被理解与复核的阶段成果，并留下实际交付状态和恢复入口”。

九个模块、可复用前后处理、目标基准、资料规范、行为日志及图式管理共同构成当前基线。阶段切换由实际输入、知识状态、证据与授权决定，不是机械按固定清单把所有项全量跑完。

日常阅读先看流程总览，再看当前模块和对应提示词。涉及来源管理查资料规范，涉及知识修改/调用查图规范，涉及审查与交付查目标与论证要求。后续只有出现具体新需求、实现失败或真实使用问题，才有理由局部修订；不因为本版收口就自动再加一个“继续全面优化”的环节。

本次完整收录的是已讨论并接受的执行层设计。它不把开发出来的文档冒充已经部署的基础设施，不把设计复核冒充故障测试，也不把一次实践顺畅外推为所有科研问题的成功保证。
