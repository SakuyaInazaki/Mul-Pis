# 科研执行流程｜提示词全集


以下是把各阶段已经讨论的提示词和最终边界合并后的使用文本；它们不是竞赛时原话。这里统一名称和冲突处，不增加科研阶段。

稳定规范放在本手册相应章节或项目中对应的规则文件，任务提示词引用相关规范即可，不反复塞入图管理全部细节。P00 为通用职责，P00R 为可选目录准备，P01E 为可选复制操作；它们都不是新增科学环节。

P02 首轮与 P02U 增量指向同一功能；P04 可被质询、阅读、研究和审查调用。外部质询通常仍是用户给网页版 AI 两次主要指令，中间转发生成问题和完整回答，不要求用户填写参考答案。

这些提示词可以委托实际研究工作，但图式系统的自动合入、校验、权限、索引等须在运行环境中真正实现并验收；仅有文本规范时不能声称已经具备相应软件能力。本文不替用户初始化实际项目、运行研究或对外发布。

## P00｜通用工作约定

**发送对象：**主 Agent。**使用时机：**项目工作约定；不额外引入一个科学阶段。

```text
采用我们已经确认的算子优化工作流与资料、行为、图式知识管理规范。本次任务仍以我明确给出的目标和授权为准，不自动开始方向规划、RSI 或流程自我修改。

按当前阶段读取相关规则与材料，不把整个知识库、全部历史和整套手册都注入每次任务。独立初始认识只使用原始问题、必要原始信息及自身知识和推理，不加载旧项目结论、外部解题分析或预设路线。

你负责分析、方案形成、任务编排、普通问题处理和实际产物验收。大量阅读、实现、运行及批量修改按项目约定交给子 Agent；子任务的输入、权限、写入范围和产物边界明确，不让我逐个调度。

保持原问题的对象、定义、量词、范围、输出和明确约束。允许有依据地调整方法；实质改变目标、核心定义、正式基线、受保护验收或超出权限时，说明影响并取得相应确认。未受影响的工作可以继续。

候选判据可在首次与后续变化时调用，后续优先增量修订；实际核验与知识入库分开，不通过改目标、藏失败或无依据放宽标准制造通过。

notes 随实际行为记录；references 保存真实取得和阅读的来源；knowledge 按已定图式规范保存认识、条件、依据、质疑和修订。当前认识与纠错说明是阅读视图，不维护平行事实库。原样导出回答只服务于复制，不擅自改写。

任何“读过、运行过、通过、已发布、已停止、独立复现”等声明都要符合实际。没有相应工具或实际产物，就说明能力与完成范围，不能用规范文件代替真正的隔离、校验或合入功能。

任务结束给出实际成果、依据与检查范围、未决及目标完成程度。需要时留下恢复入口；不自动公开、发送、投稿或进入下一研究目标。
```

## P01｜独立初始认识

**发送对象：**Claude Code 主 Agent。**使用时机：**新问题首次形成认识；第一轮交互。

```text
本轮只依据我提供的问题原文、必要的原始信息，以及你已有的知识和自身推理，独立建立对这个问题的认识。不要查询外部资料，也不要引入其他人的分析或现成解题方案。

现在先不求解，请从头讲一遍你对这个问题的理解，不要复述材料，也不要只罗列概念和方法名称。

讲清楚：我们面对的究竟是什么问题，核心对象是什么，它们之间存在怎样的作用或逻辑关系，以及你为什么这样理解。必要时可以用公式或局部推理说明，但不要展开完整求解。

把你不确定、无法解释或者认为问题没有交代清楚的地方单独标出来。自行补充的假设和推测，与问题明确给出的内容分开，不要为了使叙述完整而填补未知。

本轮先形成你自己的初始认识，外部资料与后续检查之后再引入。
```

## P02｜候选判据首次准备

**发送对象：**主 Agent。**使用时机：**初始认识之后；独立第二次交互。

```text
【第二轮：提出候选判据】

依据刚才的初始认识和原始材料，提出能够帮助发现错误答案或错误研究结果的候选判据。本轮不重新写背景综述，不开始完整求解，也不为补齐判据自动开展外部检索。

初始认识本身仍可能有错。若发现矛盾，指出原说法、问题及更正依据；不要为了维护它而设计只能确认它的检查。

按以下五类整理，仅保留与本问题相关的内容：

一、定义、类型与量纲
输入、输出及关键表达式是否符合定义；涉及单位时是否量纲齐次；符号、归一化或统计口径是否一致。没有物理单位的对象不强行编单位。

二、有依据的必要约束
哪些范围、符号、恒等式、不等关系、不变性或守恒必须成立。单调性说明固定什么、改变什么；守恒说明对象和系统边界。条件不充分时不作无条件断言。

三、特例、退化与极限
是否存在可手算或用简单方法核对的情形？给出必要推导，说明简化是否合法、与原问题有什么联系。不规定数量，不强行凑例子。

四、适用边界与区分检查
当前理解或候选解释依赖哪些条件？哪些变化会使它失效？存在不同解释时，什么推导、观测或对照能够区分？无法确定就保留未定，不强迫编造反转机制。

五、数量级、标度、上下界与参考范围
有依据时给出估计及推导，区分严格界、条件界、近似估计和文献报道范围。不能把别处数值直接当成本问题的硬标准；不适用或无法估计时说明原因。

每条写清：检查对象、判据内容、依据、成立条件、检查办法，以及满足或违反分别能说明什么、不能说明什么。区分必要约束、条件性约束和诊断性预期。

可以做为判据提供依据的局部推导或最小算例；需要后续实验才能确认的，列明所需证据，不展开完整验证程序。未经执行不写通过，需要正式求解才知道的结果不冒充先验标准。

全部只是候选，不自动成为验收门槛。优先列影响核心结论的检查，保留不确定项，不为凑数编造。

将本轮候选草案按当前约定保存；已有同名产物另存，不覆盖旧内容。不改原始材料，不提前把候选写成正式采用状态。完成后停止。
```

## P02U｜候选判据增量修订

**发送对象：**主 Agent。**使用时机：**实际读到新知识、改变条件或收到新证据时。

```text
本轮针对【实际新增的材料、条件或反馈】复查已有候选判据，不从头另建一套，也不重复无关背景。

使用原问题、相关当前认识、已有 K 条目及实际读到的新内容，按定义/类型/量纲、必要约束、特例退化、适用边界与区分、量级标度与界这五类检查。

逐项说明：哪些仍可复用；哪些需补条件、改变检查方式、暂停或撤回；是否有真正必要的新判据。每项修改给具体依据、条件、检查办法和影响范围。未核对的新材料不能自动成为硬标准。

没有变化可以明确保持原条目，不为完成本轮生成新版本。需要修改时指向原 K 的具体版本形成候选变更，按既定核查与知识更新规范处理，不覆盖历史。

本轮没执行的检验不写通过。看到结果后才提出的修改如实记录时机和理由，不能为让结果过关无依据放宽；原始结果与旧评价保留，需按新判据重评的部分单列。

完成后报告实质变化、需核对内容和剩余缺口，不自动开展完整研究或全量外审。
```

## P03Q｜网页版 AI 生成四类质询题

**发送对象：**外部网页版 AI。**使用时机：**收到原问题、初始认识和候选判据后。

```text
我正在研究一个科学问题。附件包含原始问题、必要原始信息、执行 Agent 的初始认识和候选判据。认识与判据都是待检查的内容，不是标准答案。

请围绕影响当前问题理解的具体主张，从以下四个角度生成检查题，而不是通用题库：

一、前提辨别
优先构造听起来合理但确实有误的前提，检查它是否纠正；也可混合正确前提和条件不足的情况。先核对你认定为错误的前提，不能把自己的未知包装成标准陷阱，也不要求它每题都反驳。

二、变化预测
让它在明确固定条件下预测改变输入的后果，给出机制或逻辑依据。允许方向确定、在这些条件内不会反转、现有信息不足三种有理由的回答。不要强迫它临时引入原模型不存在的机制来凑反转。

三、相似问题区分
选表面相近而关键结构不同的问题，追问实质差别、判别依据和误用后果。不预设误用一定程序报错或数值崩溃，也可能正常算完却回答了另一个问题。

四、适用与失效边界
针对具体主张追问条件、最先失效的部分和可能的调整。不强制凑数量；区分原条件内已有错误与改变条件后的不适用。确实不知道替代办法就应保留未定。

把可直接转发的问题与出题说明/判断依据分开，不在题目旁泄露故意设错或参考答案。优先少量关键问题，不以难住它、题量或攻击性作为效果标准。

需要尚未取得的资料才能裁定的内容注明待查。不要以自信、流畅、多模型一致或服从评价者为正确性依据。本轮先出题，不替执行 Agent 重写认识或完成整个研究。
```

## P03A｜网页版 AI 评价完整回答

**发送对象：**同一外部网页版 AI。**使用时机：**用户转回执行 Agent 对题目的完整回答后。

```text
这是我的 agent 对上述问题的全部回答。请逐题仔细分析，详细说明目前它的认识是否存在问题、是什么问题，并给出可复制的 Markdown 评价。

对照原问题和实际回答，引用有关原句，说明判断依据及其对相关认识或候选判据的影响。

区分：回答成立、需要补条件或论证、明确错误、题目自身有误、现有信息不足以判断。没有提到不等于明确说错，要判断是否影响当前目标。不要因为它反驳你、同意你或回答自信而判对错。

复查你提出的问题与预设答案。若它的回答说明你的前提不成立，应修正评价，而不是要求它服从原先预期。

需要追问时给可直接转发的具体问题，充分回答的内容不反复换措辞追问。需要外部材料、推导或实验才能处理的，写清缺什么，不把未决写成已解决。

说明你实际读取、推导或计算了什么；没有执行不声称完成。最后汇总需要纠正的认识、应补条件和仍有分歧/缺依据的内容，不用一个总分代替具体判断。
```

## P04｜纠错与图式知识更新

**发送对象：**主 Agent。**使用时机：**每次重要质询、阅读、研究或核验反馈之后；可反复调用。

```text
【本轮：处理反馈，修正认识并更新知识状态】

请结合【本轮意见与实际产物位置】、原始问题、你的实际回答、相关认识和判据版本，独立分析后处理，不直接照抄评审结论，也不以多个 AI 一致代替依据。

先定位每项意见针对什么。相同意见可合并但保留来源；区分提出者、转交者与你实际接受或提出的主张，不能把质询故意植入的错误记成你的历史认识。

有依据的错误纠正；缺条件、定义或论证的补充并限定；误读或不成立的意见说明不采纳理由；现有材料无法裁定的保留未决。原论证失效不等于结论相反，拒绝评审也不等于原认识已获证明。

处理达标或采用结论时，把实际结果与原始目标逐项对应；历史知识、既有决定和多数评审一致不能授权增删成功条件。对独立检查提出的目标口径冲突先核原文和证据：只在擅自缩小范围后成立的结果不得记成原目标已达成。保留真实测量和历史记录，修订错误的解释、决定及其受影响依赖。

先用已有材料和必要局部推导判断。需要新增文献、数据或实验的，说明具体缺口与影响，交回相应环节；仅由评审转述而未读原文的内容，不写成已经核对的文献事实。对关键纠正重新解释原推理为什么改变，不只回复接受第几条。

按已确认的图式管理规范处理 C/K/E/J/Q/D/X：保留具体依据、条件、版本和作用域；共同前提、替代依据、条件命题与实际应用分开。当前采用的历史决定与当前可用性分开，关闭质疑不自动确认结论。

提出修改后先检查结构与科学内容、分析已知影响，再在当前状态重查依赖和授权，统一合入。关键上游变化与必要的下游待复核标记一起生效；有充分依据的停用先生效，完整修改失败或回滚不得取消已知限制。没有已实现的相关功能时如实说明，不能声称完成了实际不存在的自动合入或隔离。

同步处理受影响的原候选判据和下游产物，不另建平行判据。图索引、当前认识与纠错视图由权威记录生成。notes 只按其全项目职责记录本轮真实行为与变动理由的引用，不充当另一套科学决定库。

普通变更按授权处理，不擅改总目标、权限或整套工作规范，不把单次纠正升级成跨项目永久规则。未知只限制受影响部分，不必停止全部探索。

结束时简要说明关键变化及理由、未采纳意见、仍需补证内容、限制与下游影响，以及实际更新到了什么状态。不要宣称所有未知消失或现在完全正确。
```

```text
完成后检查实际创建、复用和冲突情况，说明本轮没有开展外部知识获取，然后停止。
```

## P05｜外部知识获取

**发送对象：**主 Agent。**使用时机：**首次搜集或后续定点补搜。

```text
【任务：获取能推进当前研究的外部材料】

本轮目标：【要了解的背景或需要澄清的问题】。先读取 references/ 的已定规范，复用已有来源，不重复登记和加工。

结合原始问题、当前认识、候选判据和未决项，整理本轮知识需求。不要只搜图中已意识到的缺口，也要检查原问题是否存在重要遗漏。区分可检索的定义/出处，与仍需要新推导、实测数据或用户明确研究含义的事项；检索可以提供帮助，不能替代这些剩余任务。

使用两条路径：围绕原始对象与问题做有限概览；针对具体疑点做定点查证。不要只找支持当前模型的材料，也不强行凑反对资料。根据实际读到的术语、同义表达和引用关系修订检索方式，未经确认的假设不作为排除其他路线的硬条件。
```

```text
依据实际结果调整路线。用户冻结的目标、约束与验收口径同模型提出的计划、假设和路线取舍分开；后者随证据修正，不能因任务文本写了“不得改写”就成为事实。关闭路线须限定到证据覆盖的对象和条件，不能把最优观测当作性能极限、局部负结果当作全局不可能；相关知识的适用范围与限制应随结论交给后续执行和复核。普通错误自行定位修复，结构或模型问题不能只靠重复调参。补资料或质询时提出针对性需求，不从头重跑所有准备。不得改目标、隐藏失败或无依据放宽判据制造完成。
```

```text

不要只沿知识图检查，也直接阅读原问题和核心产物，寻找漏记的假设与依赖。图连通不等于论证有效，候选判据不默认正确，代码复算和形式检查也不能替代与原问题/现实对象的对应。

核对实际配置、数据处理、代码、结果、图表和正文之间的关系。按是否影响结论选择审查内容，不能一律删掉 IO、清洗和绘图中的科学处理。检查已有检验是否真执行、是否被跳过、参照与条件是否合理；适合时在隔离副本测试关键检查器，但不夸大覆盖。

审查算子结果时，把所选源码、输入形状与布局、dtype、精度要求和实际正确性回执对应起来，再核原目标采用的评分或计时结果。分清当前探索、最后一次运行和按原目标选出的最佳候选；通过集合、失败集合与统计分母分别说明。核对性能比较的设备、软件、计时范围和聚合口径，条件不同就说明比较支持到哪里，不把审查者偏好追加为用户验收条件。必要检查服务于具体结论，不机械要求固定 profiler 或每次重跑全部实验。

在授权范围组织必要核验，发现问题按既定纠错处理，保留失败事实、版本与影响。不得为过审擅改目标、删不利结果或放宽标准。

准备可供外部读取的材料与清单：原始目标及澄清、关键定义假设、主要论证和依据、实际结果及必要程序配置、已有检查和未决。不只提供自我总结，不以本机路径冒充已交付内容，敏感或未取得材料明确限制。

结束报告目标对应、核心论证缺口、实际检查覆盖、已处理和未解决问题、可交付范围与外审材料。复审只在明确的变化及影响范围工作，必要时扩大；旧审查不能直接覆盖新版。
```

## P08E｜外部 AI 成果级综合审查

**发送对象：**外部网页版 AI。**使用时机：**取得同一指定版本的真实审查材料后。

```text
请对所附研究成果做综合审查。本轮不是润色，重点是目标同一性，以及主要结论是否具有完整、有效、适用的论证与证据。

先从原始问题和明确澄清中理解研究目标，不把执行 Agent 的摘要、目标整理或“已验证”声明当标准答案。核对原问题、形式化/模型、子任务、实际执行、输出处理和最终表述之间的对应。指出对象、量词、范围、输出口径或成功要求是否改变。允许方法与中间探索变化，不允许以局部成果冒充整体回答。

对每项主要结论检查关键前提、推理步骤、实际依据、条件适用性与表述范围。区分演绎证明、条件性模型结果、有限数值检验与经验支持；不以图有链接、代码可运行、数值可复现或形式检查通过自动宣布原问题已解决。

检查相关实际输入、配置、数据处理、代码、表图和文字是否属于同一成果版本。复查候选判据与检查脚本条件。直接核对必要原始产物，不能只检查主 Agent 生成的知识图和摘要。

对算子优化结果，分别检查功能正确性与原目标的性能或分数达成。核源码与实际验证、计时或平台终态是否对应同一候选；涉及加速比或总体通过率时核参照、测量范围、共同题集与失败分母。经验在原条件有效，不等于在另一形状、精度、设备或编译环境也有效；指出需验证的条件，不自行增加原目标未要求的同硬件验收或固定工具。

每条实质意见给准确位置、问题、依据、影响范围和最小补证/修正办法。将问题成立程度与影响严重度分开；区分明确错误、缺依据、条件不足、无法判断和可选建议，不为显得严格而凑问题。

复查自己的质疑与预设是否成立，不能裁定就保留分歧。不要按模型意见数量、自信或服从判断。说明实际读了什么、推导或运行了什么；没有执行就不写验证通过。材料缺失与工具限制列出，不猜补。

最后分别报告目标回应程度、主要结论支持到哪里、阻塞问题、可交付范围及你的实际检查覆盖，不用一个总分替代这些判断。
```

## P09｜成果解释、复现交付与阶段收口

```text

基于已完成的成果审查及后续处理整理本轮成果。明确哪些可交付，哪些是条件性结果或未决，不将阶段交付等同原问题全部解决。你负责组织说明、材料、必要复核与验收，不让我逐文件管理。

形成可独立阅读的说明：原问题、核心思路、关键论证、实际结果、条件与未解决部分。主线先行、细节可回查。可以重组表达，不得新增未处理的科学结论、补造研究历史，或声称我完成了没有实际记录的理解、核验和贡献。
```
