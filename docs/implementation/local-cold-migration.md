# Trusted host review for a cold-migrated legacy dispatch

`reconcileColdMigratedLocalMission` is a host-side API for the narrow pre-lineage serial dispatch covered by the existing legacy effect review. It is not exposed as a JSON-only CLI action: a request file cannot authenticate an original-host platform observation. A trusted host caller supplies `verifyTrustedObservation`, which must verify the retained platform message IDs and times, the exact old process birth identity and terminal exit, the reviewed one-shot launch and no observed automatic restarter, the source archive identities, and the finite source-effect census. The callback must reject a live or uncertain source writer. It is called before a dry run can report eligibility and again under the writer lock before publication. The callback should use its own authenticated platform source, not merely compare the attestation to text supplied with the request.

The request names the exact mission, intent, old attempt, checkpoint, M07 task/operation, M04 failed run, provider proof, legacy effect review, canonical observation file, and pre-migration archive file. The observation JSON is serialized as `JSON.stringify(observation) + "\n"`; its SHA-256 and the archive SHA-256 are supplied in the request. The original checkpoint hash in the observation must equal the committed old checkpoint. The workspace census hash refers to the retained MISSION/M07/M04 files; the original-host process observation is cited by platform message ID and time, not by an invented OS receipt. Preserve the historical absolute workspace paths when materializing this older archive, since old run/goal records contain and bind them.

After a dry run, the caller may invoke the same API without `dryRun` using the same authenticated observation. The host requires the original-host reviewed tool-and-process census, the exact settled M07/M04 stage evidence, and an exclusive writer lock on the destination mission root. It prepares a successor attempt and V5 review checkpoint privately, then publishes them with one directory rename. A concurrent writer, changed evidence, unresolved operation, ambiguous dispatch, or uncertain source observation leaves the old checkpoint held. After publication, check `LocalMissionHost.status` for exactly one V5 review, compare retained old checkpoint bytes, and use the normal mission step for a fresh assessment. The old builder and M04 session must not be replayed.

This review records observations within a trusted same-UID scope. It does not establish OS noninterference, authenticate arbitrary message text, protect against a separately writable copy forever, or make the whole workflow portable. Other cross-host recovery and lock paths need their own reviewed transfer design.
