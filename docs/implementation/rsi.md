# 首轮工作流改进外环

## 已实现范围

首轮外环只改进预算与证据交接策略。它读取历史运行的匿名规模和粗粒度失败类别，由显式配置的 `improver` 角色提出一个结构固定的预算策略，再用 harness 内固定的确定性评价器与当前策略做成对回放。候选通过全部硬门槛和最低缩减要求后，控制器自动原子切换活动策略；未通过则保留拒绝记录且不改变活动策略。

这是一条独立于 M01–M09 科研执行层的入口：

- Pi extension：`research_improve`，动作 `status`、`run`、`rollback`。
- CLI：`node src/cli.ts improve status|run|rollback --workspace <dir>`。
- `run` 需要 `research.config.json` 中显式配置 `roles.improver`；harness 不替用户选择模型。
- 本地产物位于工作区 `.agent/improvement/`，包括候选、协议、评测、晋级或拒绝记录和活动版本指针。这些材料属于本地私有运行记录，禁止提交或公开推送。

## 固定边界

候选只能包含既定 `BudgetPolicy` 字段，不能改 evaluator、验收阈值、工具权限、M01–M09 规则、知识记录或源代码。候选不能扩大当前预算。评价器要求 schema 合法、单文件与聚合内联预算不扩大、溢出时保留 manifest 可追踪性，并同时满足最小内联字符缩减、单代新增延后负担上限和跨代仍适用的绝对最低内联覆盖率。当前协议没有真实重放 prompt 总长和反馈包生成，因此 `maxPromptChars`、`maxFeedbackChars` 与 `overflowMode` 必须和本代基线完全相同，不能靠压低未评测参数获得晋级。

活动指针是唯一激活点。晋级先持久化版本和 prepared 回执，提交前再次比较活动指针与本轮冻结基线；基线已变化则以 `improvement.stale-baseline` 拒绝晋级，要求基于新版本重跑。通过后才原子替换活动指针。`run` 与 `rollback` 共用工作区 `mutation.lock`，因此同一工作区的不同进程不能同时改变策略。正常结束会清理锁；进程崩溃留下锁时系统保守拒绝后续变更，操作者须先检查锁内 `owner.json`，确认没有活动进程，再只删除该精确锁目录。

每个新 M07 目标在 `begin` 时一致读取并冻结活动策略正文、版本号和冻结时间。该目标之后的委派和常规 M04 反馈生成始终使用这份快照；后续晋级或回退只由之后新建的目标继承，不改写进行中或已保存目标。冻结机制加入前的 legacy 目标仍可查看，但不能继续委派或走常规 finish/反馈；需要按当前策略继续时必须新建目标。它仍可用受控 `interrupt` 归档为 blocked：专用 legacy 反馈只登记控制事实和证据位置，不读取、内联或截断证据正文，也不套用当前活动策略。

回退只把活动指针切到上一预算版本。它不恢复研究工作区快照，不删除运行历史，不改写已有 M07 目标的策略快照，也不能解除 C/K/E/J/Q/D/X 知识库中已经生效的停用、撤回或需复核限制。

## 证据口径

当前历史试跑已经用于发现并修复问题，因此它们是 development replay，不是盲测或真正 held-out。提议器只接收阶段、状态、输入输出规模和粗粒度失败类别，不接收题面、文件名、路径或内容；这降低了私人材料泄漏风险，但不能把已见历史重新变成保留集。

当前自动晋级只证明候选满足这个固定离线评价器对预算策略的要求。它没有证明：

- 泛科研任务的成果质量或成功率提高；
- 系统能够修改、验证和部署自身源代码；
- 多代改进产生递归复利；
- 评价器能抵抗恶意候选，或该结果可推广到未见任务分布。

因此该实现可描述为“受控的预算策略持久改进原型”或“L1 起点”，不能直接称为已经实现通用 RSI。真正保留集、跨任务 A/B、长期能力保持和多代收益仍需后续独立验证。

## 使用顺序

1. 先运行 `status` 查看当前版本及历史状态。
2. 运行 `run`。评价失败会得到 `rejected` 记录，不会晋级；通过时自动晋级，无需逐轮人工批准。
3. 新策略造成运行问题时使用 `rollback`。没有上一版本时回退会明确失败，不会猜测一个版本。回退只影响之后新建的 M07 目标。

验收策略和允许修改范围由项目代码固定。扩大候选范围、修改评价标准、解除知识限制或发布到外部，仍不属于自动晋级权限。
