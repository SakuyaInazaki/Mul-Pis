# Manual public M01 environment check

This is a deliberately small, billable prerequisite check, not a private lab run or a scientific validation. The GitHub Actions workflow supports manual `workflow_dispatch` and a temporary, single-publish push check. The latter is job-guarded to the exact repository, owner actor, branch, first run attempt and unique head-commit message `Run one bounded public M01 connectivity check (mul-pis-20261004-once)`. Remove the push trigger immediately after that one run; a later push without the marker skips the job. It uses one fixed, public arithmetic prompt through `ResearchService.runStage(M01)` and a real `PiSessionRunner`, with the `execution` role explicitly set to `deepseek/deepseek-flash:low`. The API key comes only from the `DEEPSEEK_API_KEY` environment variable; the runner does not read a credential file or a global Pi profile.

The pinned Pi SDK's built-in catalog can lag the current DeepSeek name. The entry creates a temporary, secret-free model profile for the [current official `deepseek-flash` model and endpoint](https://api-docs.deepseek.com/quick_start/pricing/). It verifies resolution before the model call and aborts if the key is absent. Pi strict-request enforcement disables retries and compaction, permits no tools, verifies one provider payload, caps that payload at 12,000 UTF-8 bytes, and caps output at 2,048 tokens. The script also sets a 90-second abort. The separate Actions job has a five-minute timeout, read-only repository permission and no artifact upload.

For planning, even charging both input and output at USD 10 per million tokens and converting at 10 CNY/USD yields at most 1.4048 CNY for one capped request, below this check's 1.5 CNY planning ceiling and far below the user's 30 CNY test ceiling. That is a conservative estimate, not a provider invoice or a guarantee against future pricing changes. Check the provider's live price page before manually dispatching. Repeated manual dispatches can accumulate charges.

Run offline preflight with `node scripts/manual-env-m01-smoke.ts --check`. Run the actual public check only by the one guarded publish push, by manually dispatching the Actions workflow, or locally with a safely configured `DEEPSEEK_API_KEY` environment variable and `node scripts/manual-env-m01-smoke.ts --run`. Do not pass a key on the command line. Neither mode accepts a user-supplied problem path. The run writes its workspace/session artifacts under a temporary directory and deletes it when the process exits normally. Success requires one complete, priced assistant usage event in the genuine Pi SDK sidecar. Console output whitelists only check status, stage/model identifiers, the planning ceiling, observed SDK-reported token counts and SDK-estimated cost/completeness. SDK usage is not an independent invoice or proof of model weights. The script never prints the prompt, model response, provider errors, credentials or temporary paths. GitHub Actions must remain configured without transcript or artifact uploads.

This route cannot validate the private lab: Actions receives only repository content and the API secret, with no supported private input transfer. Do not add lab text, materials, solutions, paths or transcripts to this repository, Actions inputs, logs, caches or artifacts. A later private lab driver needs a separate, reviewed host-local input/output design and a bounded end-to-end research budget; this one-call M01 check must not be presented as that driver.
