# Manual public M01 environment check

This is a deliberately small, billable prerequisite check, not a private lab run or a scientific validation. The GitHub Actions workflow is manual-only (`workflow_dispatch`). The temporary guarded push trigger used for the initial connectivity checks has been removed. It uses one fixed, public arithmetic prompt through `ResearchService.runStage(M01)` and a real `PiSessionRunner`, with the `execution` role explicitly set to `deepseek/deepseek-flash:low`. The API key comes only from the `DEEPSEEK_API_KEY` environment variable; the runner does not read a credential file or a global Pi profile.

The pinned Pi SDK's built-in catalog can lag the current DeepSeek name. The entry creates a temporary, secret-free model profile for the [current official `deepseek-flash` model and endpoint](https://api-docs.deepseek.com/quick_start/pricing/). It verifies resolution before the model call and aborts if the key is absent. Pi strict-request enforcement disables retries and compaction, permits no tools, verifies one provider payload, caps that payload at 12,000 UTF-8 bytes, and sends an 8,192-token output cap. The script also sets a 90-second abort. The separate Actions job has a five-minute timeout, read-only repository permission and no artifact upload.

For planning, the request cap plus a 32-token accounting margin gives 12,000 + 8,192 + 32 = 20,224 tokens. Even charging all of them at USD 10 per million and converting at 10 CNY/USD yields 2.0224 CNY, below this check's 2.1 CNY per-call reserve and the user's 30 CNY total test ceiling. Two prior attempts reserved 2.8096 CNY together under the earlier 1.4048 CNY-per-call ceiling; adding one 2.1 CNY reserve totals 4.9096 CNY. These reserves are not actual charges. The 32-token margin acknowledges that the provider reported 2,049 output tokens for an earlier 2,048-token capped request. A cap sent and verified in the request is not an absolute billing guarantee. These are conservative planning figures, not provider invoices or guarantees against future pricing changes. Check the provider's live price page and cumulative test spend before any further manual dispatch.

Run offline preflight with `node scripts/manual-env-m01-smoke.ts --check`. Run the actual public check only by manually dispatching the Actions workflow, or locally with a safely configured `DEEPSEEK_API_KEY` environment variable and `node scripts/manual-env-m01-smoke.ts --run`. Do not pass a key on the command line. Neither mode accepts a user-supplied problem path. The run writes its workspace/session artifacts under a temporary directory and deletes it when the process exits normally. Success requires one complete, priced assistant usage event in the genuine Pi SDK sidecar. Console output whitelists only check status, stage/model identifiers, the planning ceiling, observed SDK-reported token counts and SDK-estimated cost/completeness. On failure it may report a fixed execution phase, allowlisted harness code, numeric HTTP status and allowlisted stop reason/usage counts from the Pi sidecar. SDK usage is not an independent invoice or proof of model weights. The script never prints the prompt, model response, provider error messages, credentials or temporary paths. GitHub Actions must remain configured without transcript or artifact uploads.

This route cannot validate the private lab: Actions receives only repository content and the API secret, with no supported private input transfer. Do not add lab text, materials, solutions, paths or transcripts to this repository, Actions inputs, logs, caches or artifacts. A later private lab driver needs a separate, reviewed host-local input/output design and a bounded end-to-end research budget; this one-call M01 check must not be presented as that driver.
