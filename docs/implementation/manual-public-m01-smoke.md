# Manual public M01 environment check

This is a deliberately small, billable prerequisite check, not a private lab run or a scientific validation. The GitHub Actions workflow is manual-only (`workflow_dispatch`). The temporary guarded push trigger used for the initial connectivity checks has been removed. It uses one fixed, public arithmetic prompt through `ResearchService.runStage(M01)` and a real `PiSessionRunner`, with the `execution` role explicitly set to `deepseek/deepseek-flash:low`. The API key comes only from the `DEEPSEEK_API_KEY` environment variable; the runner does not read a credential file or a global Pi profile.

The pinned Pi SDK's built-in catalog can lag the current DeepSeek name. The entry creates a temporary, secret-free model profile for the [current official `deepseek-flash` model and endpoint](https://api-docs.deepseek.com/quick_start/pricing/). Before any model call, it reads the exact model's output maximum from DeepSeek's authenticated [models endpoint](https://api-docs.deepseek.com/api/list-models/) and checks it against the provider's [chat-completion parameter range](https://api-docs.deepseek.com/api/create-chat-completion/). It then uses that provider maximum in the temporary profile. The tool-free Pi strict request disables retries and compaction, verifies each provider payload uses the resolved provider output maximum, and caps each serialized payload at 12,000 UTF-8 bytes. It does not impose a smaller workflow output limit, a monetary ceiling, a maximum number of provider transports, or an M01 execution deadline. The Actions job has no project-set execution timeout; it retains read-only repository permission and no artifact upload.

There is no automatic CNY pre-reservation or spending stop in this public smoke. A single M01 session may make more than one provider transport. A manual dispatch may therefore incur charges even if the stage later fails. Review the provider's live price page and your account controls before dispatching it. The temporary model profile's prices support Pi's SDK estimate in the usage sidecar; that estimate is not a provider invoice.

Run offline preflight with `node scripts/manual-env-m01-smoke.ts --check`. This offline check does not contact DeepSeek or validate its live maximum; `--run` does that before any model request. Run the actual public check only by manually dispatching the Actions workflow, or locally with a safely configured `DEEPSEEK_API_KEY` environment variable and `node scripts/manual-env-m01-smoke.ts --run`. Do not pass a key on the command line. Neither mode accepts a user-supplied problem path. The run writes its workspace/session artifacts under a temporary directory and deletes it when the process exits normally. Success requires complete, priced assistant usage for every observed assistant event in the genuine Pi SDK sidecar and a final stop response. Console output whitelists only check status, stage/model identifiers, the verified provider output maximum, observed SDK-reported token counts, and SDK-estimated cost/completeness. On failure it may report a fixed execution phase, allowlisted harness code, numeric HTTP status and allowlisted stop reason/usage counts from the Pi sidecar. SDK usage is not an independent invoice or proof of model weights. The script never prints the prompt, model response, provider error messages, credentials or temporary paths. GitHub Actions must remain configured without transcript or artifact uploads.

This route cannot validate the private lab: Actions receives only repository content and the API secret, with no supported private input transfer. Do not add lab text, materials, solutions, paths or transcripts to this repository, Actions inputs, logs, caches or artifacts. A later private lab driver needs a separate, reviewed host-local input/output design and a bounded end-to-end research budget; this one-stage M01 check must not be presented as that driver.
