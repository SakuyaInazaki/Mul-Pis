# 科研执行流程 v1.0 基础理解与当前对齐

> 本文先解释 `workflow/v1.0` 的原始规范，再记录本轮围绕 M01–M09 对齐的当前执行方式。原目录保留 v1 文本，当前调整以本文“当前对齐”部分为入口；这不表示运行时已经实现，也不构成编码授权。

## 当前状态怎样理解

九个模块的主流程已经讨论并暂时对齐，可以继续按阶段检查和细化。这句话只表示职责、主要输入输出、会话关系和返回方向已有当前版本，不表示每项工程细节完备，也不表示获准实现软件。

本文使用三种状态，避免把不同证据混在一起：

- **原 v1 基线**：用户原 workflow 已写入的规则；仍是研究基础，但不代表本轮逐条重新确认了每句细节。
- **本轮已对齐**：本轮明确讨论过的阶段安排和关键执行关系，优先于原文中与之冲突的旧承载方式。
- **当前暂定**：M08、M09 由用户委托按原 workflow 补齐的现行安排，尚未像 M01–M07 一样逐项讨论确认。

具体模型、工具、API、并发、预算、长会话恢复和持久化实现仍未决定。Claude 不采用；这不等于已经选择了替代模型。全网资料获取已获授权，不购买付费资料，遇到付费墙应自主寻找作者稿、预印本或机构库等合法可用版本。

## 术语边界

- **角色**是在某一步承担责任的主体，如主 Agent、阅读 Agent、核对 Agent或外部评审者；角色不自动等于固定模型、进程或长期 Agent 实例。
- **模型**是一次会话实际调用的模型。相同角色可配置不同模型，不同角色也可能暂用同一模型；当前选型与路由未定。
- **会话**是一段具有自身消息历史和输入边界的模型交互。新会话用于隔离所见材料与历史，但不证明统计独立；相同模型、来源和提示结构仍可能产生相关误差。
- **任务**是为具体目标分配的有界工作，可在一个会话完成，也可包含工具调用和多轮交互；它不等于 workflow 阶段。
- **阶段/模块**是 M01–M09 的职责和返回关系。一个阶段可以包含多个任务和会话；会话结束不等于阶段完成。
- **一轮**必须带对象说明。一次模型轮次通常是一条输入至对应输出；一次评审轮次是同一固定版本的一组既定评审全部返回并统一处理；一次研究阶段不等于一次模型调用。

## M01–M09 当前对齐

### M01｜独立初始认识

**原 v1 基线。** 只给原问题与理解所必需的原始信息，允许模型使用自身已有知识和推理，不先给外部检索、他人分析、现成路线或旧项目结论。输出应形成可以被追问的对象、关系、假设、不确定性和未知，而不是提前完成求解。

**本轮已对齐。** 主 Agent 组织一次独立 M01 会话；本阶段不执行外部检索，而不只是“不提前把检索内容给模型”。执行模型需要较强知识与推理能力，但不因此约束主 Agent 必须使用相同模型。用户不必观看 M01 输出，M01 结束到 M02 之间也没有固定的人工审批停顿。

**输出与流转。** 保留 M01 完整产出；它进入 M02，并在 M03 回答环节由原 M01 会话继续使用。P01E 仅是需要复制时的原样导出操作。

**完成与返回。** 输出具体到能够追问即完成，不代表正确性已经确认。若原问题或必要原始信息不清，应暴露缺口，不自行补造成事实。

**待查证。** 具体执行模型、真实输入隔离、长会话恢复与上下文保留方式。

### M02｜候选判据准备与修订

**原 v1 基线。** 建立定义/类型/量纲、必要约束、特例/退化/极限、适用边界/区分检查、数量级/标度/界/参考范围五类候选检查。每条保留对象、依据、条件、检查办法、结果含义和不能证明什么。候选判据不是已执行验证或硬验收；后续只对受影响的原 K 增量修订。

**本轮已对齐。** M02 使用与 M01 相同的执行模型，但开启独立新会话。“新会话”指不继承此前对话历史和自动发现的资源，不是不给任务材料。输入限于原问题必要信息、M01 完整可见产出和 M02 指令。M02 审视 M01 并形成候选判据；M01 和 M02 的完整产出共同进入 M03。

**完成与返回。** 五类中与本问题有关的候选、限制和缺项已说明即可完成；不为凑类别制造无依据阈值。新材料或反馈改变依据时调用 P02U 修改原条目，不建第二套判据。

**待查证。** 输入隔离怎样真实落实，以及实际运行时怎样保证没有遗漏原判据职责；无需重新决定 M02 的基本职责或是否另开会话。

### M03｜外部质询、回答与评价

**原 v1 基线。** 四类质询、题目与判断依据分开、完整回答、逐题评价、评价者检查自身预设，以及不按多数票裁决，继续作为语义底座。v1 写下的用户在主 Agent、网页版 AI 和执行 Agent 间人工转交，是历史承载方式，不是当前最新规则。

**本轮已对齐。** 主 Agent 自动组织一个全新的评审会话，输入原问题及 M01/M02 产出，由其生成问题并保留出题依据。随后把 M02 完整产出和可转发问题一次送回 M01 原会话作答，不另加“先读 M02 后回复”的独立轮次。完整回答再回到原出题评审会话评价。

**输入禁区。** 首轮评审不能收到其他评审者意见后再冒充独立判断；题目不能把评审者预设藏成事实。M01 回答必须保留完整推理和限制，不能只交摘要。出题说明与预期答案留在评审会话，只把可转发问题送入作答会话。

**输出与流转。** 保存具体问题、出题依据、完整回答、逐题评价和待补证项，统一进入 M04。

**完成与返回。** 有理由的意见和未决已经定位即完成，不要求所有评审一致。重要认识变化或竞争解释可在后续组织针对性 M03，不必重跑全部四类问题。

**待查证。** 外审模型与数量、多评审结果如何汇集、真实会话隔离和 M01 原会话恢复。原 v1“不固定必须三家”的边界继续成立。

### M04｜纠错、知识记录与状态更新

**原 v1 基线。** 对意见、实际结果、阅读发现和异常作接受、部分接受/补条件、不采纳或待补证；同步认识、判据、依据、论证、质疑、处理决定与情境，保留影响范围和未决。

**本轮已对齐。** 主 Agent 负责组织，研究模型承担实质科学处理。首次 M04 可以接续 M01 原会话；此后每次处理使用新的研究会话。一次有明确对象的处理轮次是最小单元，只读取相关当前知识、证据、未决和实际产物，不依赖无限历史。

**触发。** M03 的评价、M06 同批材料汇总后的建议、M07/M08 产生的真正新研究或核验证据，以及用户对事实或要求的修正，都可以触发相应范围的 M04。一次处理结束只表示该批输入已按当前依据处理，不表示整个科研问题已经解决；存在未决也不触发无新信息的盲目自循环。

**输入禁区。** 不能把评审意见当裁决，不能用模型一致代替证据，不能把未取得的引用写成原文事实，也不能自行改变目标、正式基线或授权。

**输出与流转。** 输出有依据的处理决定、相关 C/K/E/J/Q/D/X 修改建议、影响范围和下一步。需要资料时去 M05/M06，需要实际执行时去 M07；重要认识变化可回针对性 M03。

**完成与返回。** 没有必要修改也可记录检查后保持原状态。明确错误应及时限制使用；无法判断则保留待补证，不强行二选一。

**待查证。** 研究模型、相关知识查询、七类对象真实读写、串行合入与持久恢复。图式规则是 v1 底座，不代表已经批准某种数据库或技术实现。

### M05｜外部知识获取

**原 v1 基线。** 围绕当前缺口区分资料可解决、需推导、需实测和需用户选择的事项；先有限概览，再定点获取，记录来源、版本、取得范围与剩余缺口。搜索命中或下载文件不自动关闭 Q，也不自动采用结论。

**本轮已对齐。** 检索范围是全网络，包括论文、正式文档、论坛和社区。普通资料获取由 Agent 自主完成，不再为大文件下载等普通获取动作泛泛增加人工审批。不购买付费资料；付费或受限时主动寻找合法开放版本。允许读取搜索摘要、摘要页和相关段落作初筛，但必须与整份材料的正式阅读区分。

**输入与输出。** 输入为当前问题、认识、K、Q、已有来源和具体缺口；输出为检索记录、实际取得材料、版本与访问事实、建议阅读优先级和未覆盖部分。URL、摘要、已下载文件、提取文本、局部阅读和完整阅读是不同事实。

**完成与返回。** 材料足以进入 M06、关键缺口有明确续查办法、或已达到实际资源边界并披露未覆盖部分，三者都可合法结束。没有固定篇数，也不能声称“搜全”。

**待查证。** 搜索、抓取、PDF 工具和模型均未选。现有工具文档只是候选清单，具体接口和 extension 方案都不是当前架构决定。

### M06｜阅读、核对与项目适用性

**原 v1 基线。** 先忠实理解材料，再核对真正准备依赖的关键内容，最后判断对当前项目的适用性；阅读、项目判断和正式知识更新分工明确。

**本轮已对齐。** 每份进入深入处理的材料建立三个各自独立的会话，分别执行三个任务；三个会话不共享消息历史：

1. 阅读任务只取得该材料和阅读要求，不给项目期待；按任务需要覆盖相关范围，只有任务明确要求全文时才保证全文，始终记录实际阅读与跳过范围。
2. 核对任务取得原材料和阅读产出，检查提取是否忠实、遗漏、越界或混淆；范围覆盖准备使用的关键依据。
3. 项目适用性任务取得经核对的材料认识以及当前项目状态、问题和用途，判断能支持或反对什么、成立条件、限制与未决。

同一份材料按“阅读 → 核对 → 项目适用性”依次执行；不同材料组可以并行。同一批各材料的适用性分析使用同一个当前项目状态。N 份材料形成 N 组三步任务，各阅读 Agent 不直接修改权威知识。这里的隔离是输入和历史隔离，不是统计独立保证。

**本轮暂定的批次调整与防漂移。** 某组失败、材料不可得或未读完时，主 Agent 可以调整本批纳入范围，但不能改变原问题、范围、条件或成功要求。主 Agent 通过研究任务按实际依据区分：真正覆盖原用途的可靠替代资料、可以暂缓但需披露覆盖损失的补充资料，以及涉及关键前提、必要证据、潜在反例或重要性未知的缺口；最后一类不能默认“不重要”，并须阻止相应主张在无依据时被正式采用。被排除的材料、排除原因以及原问题留下的研究义务不会消失。调整后，本批所有实际纳入组完成再统一送入 M04，同时附上失败或排除原因、剩余缺口及其对原目标的影响，不能把缩减后的批次完成冒充全目标完成。最终仍按原目标报告完成程度；实质目标变更交由用户决定。

**完成与返回。** 关键内容、位置、条件、核对事实和项目关系已明确；不可用处和未决补证需求已写清。整批结果先进入 M04，由研究会话依据实际材料承担科学判断，主 Agent 负责组织、检查依据与任务是否完整并避免重复，而不接管科学判断。能直接处理的就在该轮 M04 处理；需要重新准备或审查检查办法时调用 M02U，它是 M02 的增量修订，不是新阶段；重要认识变化或竞争解释，并且独立质询能够检验推理、预测或边界时，才调用针对性 M03；缺实际材料、证明、数据或实验则按性质返回 M05/M06 或 M07。补充结果回到新一轮 M04，缺证时不提前采用。

每次调用都应指出具体 C/K/J 等对象、新证据改变了什么以及要解决的问题。检查未通过不等于应放宽判据，模型认可不能替代证据；一时分不清路径时保留未决，优先做最小范围的原文核对或局部推导，不默认把 M02U、M03、M05/M06 和 M07 全部重跑。

**待查证。** 并发、具体失败重试策略、长材料分块、PDF/图表覆盖、模型路由和技术承载仍未选择；SDK 独立 session 只是候选。上述阶段流转已对齐，不表示这些实现细节已经完备或获准开发。M08/M09 仍是用户委托补齐的当前暂定流程。

**本轮暂定的停用边界。** 整批尚未汇齐时，已有充分依据或授权的停用先可靠记录并生效，只限制相关依赖，不提前采纳尚未核对的替代结论，也不冻结无关研究；一般质疑不自动升级为紧急停用，解除限制需要新的依据。这一处理不把当前安排改成每份材料分别进入 M04。

### M07｜主 Agent 动态执行

**原 v1 基线。** 一个当前目标一次委托；执行可包含推导、构造、反例、实验、代码或路线调整。主 Agent 形成方案、落实判据、处理普通故障并根据真实结果调整。

**本轮已对齐。** 主 Agent 持续负责目标理解、规划、动态拆分、委派、读取真实产物、验收和选择返回路径。M07 正式依赖的项目状态须经 M04 处理，有标记的候选可用于探索性工作但不得静默补齐条件；边界明确的子任务按需要动态产生，不固定会话数量。重要且将被后续依赖的结果安排独立检查，不要求每个细碎动作都另做一次完整审查。主 Agent 可继续委派、要求返工，或返回 M04/M05/M06。

**输入禁区。** 子任务不能无声改变目标、关键定义、正式假设、受保护验收或权限。任务结束消息、会话结束和程序退出码都不等于科研结果通过，必须检查实际产物和真实检查范围。

**输出与流转。** 交付推导、构造、代码、数据、实验、反例或排除路线，以及与目标的对应、实际配置、检查范围、失败、未执行项和限制。普通实现问题在 M07 内闭环；认识变化进 M04，缺资料进 M05/M06；阶段成果成熟后进 M08。

**待查证。** 有界委派的具体接口、参数、并发和长任务 runner 未定，也不意味着再造第二个主 Agent。

### M08｜成果级综合核验与外部审查

**状态。** 以下是用户委托按原 workflow 补齐形成的当前暂定流程，并非用户逐句确认，也不是运行实现授权。

1. 固定同一审查版本的原问题与澄清、定义、数据、代码、配置、结果、判据和主要主张。
2. 主 Agent 将 P08M 自查拆成具体独立任务，核对目标同一性、结论—论证—证据、材料版本一致性、检查真实性和未决。
3. 自查任务全部返回后，主 Agent 准备同一版本的真实材料，不能只给摘要。
4. 自动组织一个或多个外审任务。每个评审先从原始问题理解目标，再读同一版本成果；首轮不读取其他评审意见。
5. 选定评审全部返回后，结果统一进入 M04，不以多数一致为正确性证据。
6. 修改后按影响范围复审；核心定义、主要证据或结论改变时扩大复核，旧审查不覆盖新版。

**完成与返回。** 分别报告目标回应程度、各主要结论支持范围、阻塞、审查覆盖和可交付范围。局部可靠结果允许阶段交付；无需所有 Q 关闭或所有 AI 同意。补资料、重算或返工按实际影响返回 M05/M06/M07/M04。

**待查证。** 评审数量、模型、跨 provider、预算、并发和结构化输出未定。被撤回的实现不构成接口、测试或方案正确性的证据，当前没有获准运行代码。

### M09｜成果解释、复现交付与阶段收口

**状态。** 以下同样是用户委托补齐的当前暂定流程，不是逐句确认或编码授权。

1. 在 M08 及后续 M04 已处理的同一版本上，自动建立独立整理任务，按接收者和用途形成可独立阅读的说明，不新增科学结论。
2. 建立独立交付复核任务，检查实际材料、入口、路径、依赖、配置和版本；涉及计算时在独立副本按说明复核并记录真实覆盖。
3. 两类任务全部返回后，主 Agent 汇总研究完成程度、交付状态、实际核验、未决与限制、版本、关键产物、恢复入口和真实运行任务状态。
4. 停止当前目标，不自动公开、投稿、外发、启动下一目标或 RSI；停止目标不等于关闭 Pi 进程，仍运行或未知任务必须如实保留。

**输入禁区。** 不能在整理中新增推论、扩大结论、隐藏未提供内容或把有限复核写成完整复现。重画图、重跑分析、完整复算和重做现实实验必须区分；命令成功不等于科学通过。

**完成与返回。** 成果可理解、可追溯，材料与用途相符，实际复核范围、版本、未决和恢复入口清楚，即可在相应范围收口。发现实质科学变更回 M04/M07/M08；发现路径或依赖问题重查交付副本。

**待查证。** 交付形态、复算命令策略、模型配置与持久状态实现均未定。

## 一、原 v1 文本的基础理解

这套流程不是把一份数学建模竞赛工具包直接推广出去。README 开头就声明它“不是竞赛旧版工具包”，完整手册进一步说明它“不是竞赛日志的原样复述，也不是从 RSI 论文移植的框架”；原始实践、讨论中的优化和最终接受的约定被有意分开，现行要求以最终约定为准（`README.md:3`；完整手册 `36-42`）。

它已经是一个泛科研的执行层设计，起点是“已经有一个准备研究的问题”，终点是形成与目标对应、论证和证据边界明确、可理解和复核的阶段成果，并留下真实交付状态与恢复入口（完整手册 `1445-1454`）。选题、长期研究组合和 workflow 自我改进属于后议范围，不能在 M09 后自动接入（完整手册 `36-42, 743-789`）。

先前把“固定网页版 AI 转发链”“题目给定”“有限竞赛周期”笼统称作赛制特例，是没有忠实依据的判断：

- M03 的人工转交链确实是原 v1 的明确规则，而不是当时未定的临时 adapter（完整手册 `195-231`；分册 01 `169-205`）。本轮已将当前执行方式对齐为主 Agent 自动编排，详见上文；这里仅说明原文，不能再当作最新规则。
- 文档只把网页工具能力、文件数量限制、固定 AI 数量、统一工具和语言视为随项目实例化的承载条件，明确不把竞赛配置固定下来（完整手册 `227, 888`）。
- 流程面向“已经决定要研究的问题”，但允许方法、模型、路线和预期答案被证据推翻；它保护的是问题对象、含义、量词、范围、输出口径和成功要求，不是某个题面答案（完整手册 `615-644`）。
- 原实践确有竞赛起点，但现行 v1.0 已明确记录哪些内容被泛化、哪些旧建议被撤回，不能重新用“竞赛遗留”覆盖最终决定（完整手册 `861-906`）。

## 二、原 v1 的整体工作方式

### 1. 它是有主线的按需返回系统

M01-M09 提供导航主线，但不是每次全量执行的固定流水线。M02、M03、M04、M05/M06 都能按证据需要重新调用；重开时先检查已有内容是否仍适用，优先做增量修订，不另建平行认识或判据（完整手册 `44-50, 88-105`）。

常用主线是：

`M01 → M02 → M03 → M04 → M05 → M06 → 受影响的 M02/必要质询 → M04 → M07（内部反复检查与 M04）→ M08 → M04/局部复审 → M09`

这条线表达的是常见依赖，不是强制把所有类别跑一遍。已有材料足以覆盖时可以复用，无关类别说明后跳过，资料缺口不阻断不受影响的探索（完整手册 `74-95`）。

### 2. 它把准备、实际核验和后处理拆开

- 前处理中的 M02 只准备候选检查：说明对象、依据、条件、办法、结果含义和不能说明什么。
- 中间必须实际阅读、推导、计算或实验，并产生可定位的产物和检查结果。
- M04 接收真实产物和反馈，决定接受纠正、补条件、不采纳或待补证，再同步认识、判据、依赖和可用状态。

因此，“提出了检查办法”不等于“已经验证”，“后处理”也不是在末尾写总结。明确错误应及时限制使用，不能等流程走到最后（完整手册 `44-50, 97-105, 235-277`）。

### 3. M04 是贯穿执行层的状态回收口

M04 不只处理外部 AI 意见。阅读发现、研究结果、检查异常、重要阶段变化都进入它。它允许四种结果：接受纠正、部分接受/补条件、不采纳、待补证；原论证失效不自动证明相反结论成立（完整手册 `235-259`）。

M04 的核心动作是：定位意见针对的实际对象和版本；检查依据；解释关键推理为什么改变；更新 C/K/E/J/Q/D/X；分析下游影响；在当前状态与授权下合入。没有知识变化也可以合法结束。它不能自行修改总目标、权限或整套流程，也不能把一次项目纠正自动升级为跨项目规则（完整手册 `261-277`）。

### 4. 阶段切换由证据状态和授权触发

文档给出的返回规则不是“失败就重跑”：缺原文去 M05/M06；普通代码或数值错误在 M07 内闭环；关键认识失效先让限制生效再修订；核心定义或目标需变更时把差异、影响和建议交给用户；外审分歧进入 M04 而不是多数表决；包装改变运行路径则在交付副本重查（完整手册 `795-814`）。

每个模块都有自己的完成语义。例如判据准备完成不表示检查已执行，资料获取完成不表示知识已掌握，成果审查完成不表示科学问题完成，交付收口完成不表示已发表或获准启动新目标（完整手册 `816-838`）。

## 四、工作流已定的认识管理结构

### 1. 七类对象不是同一种“知识节点”

| 类型 | 它回答什么 | 不能与什么混淆 |
|---|---|---|
| C 认识条目 | 当前具体定义、假设、机制解释、命题或经验结论是什么 | 不能因被采用就视为已证明 |
| K 候选判据 | 怎样检查某个认识或结果，检查能说明到哪里 | 不是目标，不是已经执行的验证，也不是自动硬门槛 |
| E 依据项 | 原文、原始数据、实际输出或证明检查记录具体是什么 | 资料取得、内容可靠、项目适用和使用决定不是同一状态 |
| J 论证记录 | 怎样由哪些前提/依据支持、反驳或限定目标 | 图连通、输入成立都不自动保证 J 有效 |
| Q 质疑与未决 | 哪一对象的哪一版本存在什么问题、影响与处理状态 | Q 关闭不等于目标认识被证明 |
| D 处理与修订决定 | 在特定情境、用途和版本下如何使用相关内容 | 是使用决定，不是科学真假标签 |
| X 研究情境 | 某分支共享的定义、条件、对象范围和比较口径是什么 | 不同 X 未建立映射时不能直接合并或比较 |

N 是行为记录，S 是外部来源身份；两者不复制进知识库充当科学结论。J 与 D 的分离尤其关键：J 解释“为什么受到支持或反对”，D 解释“当前用途下如何使用”（完整手册 `294-324`）。

### 2. 关系必须保留论证作用

共同前提 `A∧B → J1 → C` 与替代路线 `D → J2 → C` 不同；用于证明条件命题的局部假设、反证中的临时假设、实际应用条件也不能作为同一种事实依赖传播。`H⇒C` 成立与当前对象满足 H 是两个判断（完整手册 `326-334`）。

图允许有环，但循环引用不增加独立证明。影响传播的是“需要检查”，不是机械地把所有下游判假；图追踪还必须由直接阅读原始产物补充，因为图可能漏记假设和依赖（完整手册 `368-372`）。

### 3. 三种状态必须分开

流程拒绝一个统一置信等级，而区分：

1. **依据状况**：题设、工作假设、原文陈述、本轮推导、数值检查、独立复算、形式检查以及未覆盖部分。
2. **历史使用决定**：候选、工作假设、当前采用、暂停、撤回或替换，绑定情境、用途和版本。
3. **当前可用性**：结合 D、X 匹配、依据变化、阻断问题和权限派生出的按条件可用、仅探索、需复核或禁用。

因此历史 D 不被新证据重写，但当前可用性会反映新限制；回滚旧文件也不能让已知停用自动失效（完整手册 `336-380`）。

### 4. 更新是“候选—检查—影响—发布”，不是直接改 latest

最终更新协议是：接收与定位 → 候选修改 → 结构/语义检查 → 已知影响分析 → 在最新状态复查依赖与授权 → 整体发布 → 后续复核和交接。上游变化与下游必要的待复核/暂停标记一起发布；有充分依据的停用优先生效，即使完整修订失败也不能取消（完整手册 `374-382`）。

并发任务在授权空间产生材料和修改建议，公共认识经单一串行入口合入。合入不只检查写冲突，还要检查读依赖、新 Q、新决定和查询条件。发布状态需固定资料、产物、代码、配置、情境、K 和规范版本；指向会被覆盖的 `latest` 不构成固定证据（完整手册 `384-404`）。

## 五、目标同一性与事实/主张/决定分离

### 1. 保持问题，不保持预期答案

目标同一性保护原对象、问题含义、量词、范围、输出口径和成功要求。模型、方法、假设和预期答案允许被证据推翻。得到不可能性或反例可以是重要成果，但必须按它与原目标的关系表述，不能冒充完成了原构造（完整手册 `615-629`）。

原问题到形式化、子任务、实际执行、输出处理、最终结论的每个关键转换，都要说明保持了什么、新增了什么、怎样回应目标。等价改写需要映射理由，特例不能冒充全局，代理问题需说明连接和误差，实质变更要有授权并保留未完成的原目标（完整手册 `631-644`）。

### 2. 事实、解释、采用决定不是一条状态

原始运行事实、从事实得到的解释、以及采用解释的决定分别保存。外部论文“声称 P”和“P 对本项目成立”之间需要适用性 J。检查失败可能来自配置、测试、数值近似、实现、模型或前提，不能直接写成科学结论被否定（完整手册 `308, 358-366, 677-685`）。

论证完整性要求核对起点、推理、条件相容、实际证据和终点表述。数值复算只支持相应实现事实，形式检查只在所写规格内成立；它们不能替代规格是否忠实、模型是否适合现实对象的判断（完整手册 `646-654`）。

## 六、资料、阅读和行为记录的分工

`references/` 保存找到、取得和读到的材料事实；`knowledge/` 保存项目如何理解、采用、论证和保留未决；`.agent/notes/` 保存 Agent 实际做了什么。原题、代码和数据保持其原位置，不为规范强搬（分册 03 `8-27`；完整手册 `453-475`）。

资料记录逐级形成：搜索命中先记线索，正式纳入才分配 S，实际提炼后才建 reading，准备参与判断才连接 E/J/C/K。获取状态以 `source.md` 为准，阅读范围以 reading 为准，项目是否采用由 knowledge 管；找到、取得、读过、摘录准确、项目适用之间不能自动升级（分册 03 `29-46`）。

notes 不是外部评审分类库，也不是最后回忆式总结。它记录主体、任务、实际输入/版本、动作与计划差异、产物、完成状态、修改理由和未决；科学论证和采用决定留在 J/D/Q，notes 指向它们（分册 03 `54-62`）。

## 七、原 v1 的角色分工与权限边界

- **用户**决定研究目标、实质范围变化、重大授权与是否进入下一目标，不需要预先知道正确模型、专业检索词或检查题。原 v1 还让用户组织网页版 AI 的材料转交；当前对齐已改为主 Agent 自动编排。
- **主 Agent**恢复状态、形成方案、拆任务、安排子 Agent、验收实际结果、处理一般错误并维护资料与知识记录。
- **子 Agent**执行边界清楚的阅读、推导、实现、运行或核对，只写授权位置；首轮阅读遵守信息隔离，公共知识修改走统一入口。
- **外部 AI**对指定材料出题或评价，同时检查自己的前提，提供位置、依据、影响和最小补证；它不是天然正确裁判。
- **工具和检查程序**产生实际证据；提示词、目录、图或角色名本身不提供技术权限、隔离或科学正确性。

依据：完整手册 `107-117`。外部材料属于数据，不能授权自己或修改工作规范；真正写入控制与最小权限必须由运行系统实现（完整手册 `416-422`）。
